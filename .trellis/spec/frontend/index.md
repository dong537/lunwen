# 前端 index

本项目规范以 [平台契约](../platform-contract.md) 为权威，开发前阅读全部接口、数据流、权限与验收约束。

- 后端：审核引擎保持在 backend；账号、提交、COS与队列属于 platform-backend。JPA负责查询，Flyway负责schema，不混写到controller。
- 前端：React TypeScript Vite，路由负责组合，API与Query集中处理服务状态。沿用CSS体系，不引入第二套UI框架。
- 数据：PostgreSQL保存账号、提交和专业目录；UTC时间、字符串ID，未知统计为null。不得把失败或未审核显示为零问题通过。
- 权限：每个请求以数据库用户/导师关系为准，学生本人及指导教师可看论文。ADMIN 且 collegeCode 非空的学院管理员兼具本人指导学生能力，保留管理菜单并复用名单、导入、学生详情与提交详情；校级管理员无该能力。指导能力统一供菜单、路由和提交返回路径使用，不开放教师统计；后端仍校验本人指导且同院。首次改密由后端限制。
- 错误：中文稳定错误码和requestId，技术细节只入日志；不记录密码、cookie、COS密钥或论文正文。
- 验证：真实PostgreSQL集成测试、引擎Maven全量、前端test/build与浏览器流程；外部COS不能用stub结果冒充真实验收。
- 变更：限定模块边界，沿用统一envelope、分页和配置；测试结果与未验证事项写入任务check记录。
- 会话隔离：发布不同账号/角色的新会话前，取消并移除业务Query；按身份重建业务子树，避免跨页签切换留下旧论文、File和表单。不能只清退出按钮路径的缓存。
- 登录学院：匿名时从GET /auth/colleges加载既有学院，不硬编码或复用受限管理员目录；选择随凭据提交，由服务端核对账号归属。校级管理员及未分配学院账号可留空，加载/失败重试/空选项可见，登录错误保留表单；细节见[登录学院选择契约](../backend/login-college-contract.md)。
- 学院隔离：同一账号的 collegeCode 变化也须清除业务Query；目录、导师选项和账号列表重新查询。前端筛选不能代替服务端授权，详见 [学院账号与专业目录契约](../backend/college-account-contract.md)。
- 专业目录：逐行修改名称沿用受控表单弹窗，预填/校验/失败重试/取消不提交；明确说明同学院使用旧名称的师生资料同步更新。保存成功失效majors、teacher-majors、users、teacher-options、students、student和teacher-insights，不能仅显示成功提示而保留旧资料。管理员导入页仅在学生模板说明专业和指导教师工号必填。
- 异步回调：上传完成后的跳转和缓存写入仅由仍挂载的上传页面执行；离页后后台任务继续，但迟到响应不能返回旧页面或带回旧账号缓存。
- 首次改密：等待新会话生效后声明式进入业务路由，避免旧守卫抢先跳回改密页；mustChangePassword 变化时清理业务Query并重建业务子树，使已挂载的查询观察器重新请求，不能只移除缓存而留下改密前的403错误。改密失败不改变会话，保留强制弹窗与真实错误。
