# 前端 quality-guidelines

本项目规范以 [平台契约](../platform-contract.md) 为权威，开发前阅读全部接口、数据流、权限与验收约束。

- 后端：审核引擎保持在 backend；账号、提交、COS与队列属于 platform-backend。JPA负责查询，Flyway负责schema，不混写到controller。
- 前端：React TypeScript Vite，路由负责组合，API与Query集中处理服务状态。沿用CSS体系，不引入第二套UI框架。
- 数据：PostgreSQL保存账号、提交和专业目录；UTC时间、字符串ID，未知统计为null。不得把失败或未审核显示为零问题通过。
- 权限：每个请求以数据库用户/导师关系为准，学生本人/名下教师可看论文，管理员不可看。首次改密由后端限制。
- 错误：中文稳定错误码和requestId，技术细节只入日志；不记录密码、cookie、COS密钥或论文正文。
- 验证：真实PostgreSQL集成测试、引擎Maven全量、前端test/build与浏览器流程；外部COS不能用stub结果冒充真实验收。
- 变更：限定模块边界，沿用统一envelope、分页和配置；测试结果与未验证事项写入任务check记录。

## 管理与名单页面的验证边界

- Ant Design 的反馈和确认框从现有 `App.useApp()` 取得，保留主题、焦点和上下文；组件属性以仓库安装版本的类型定义为准，不继续新增已弃用属性。
- 新增或修改账号表单、名单导入和错误列表时，覆盖375px窄屏和桌面；整页不应被固定宽度筛选器或错误表撑宽，表格可在明确容器内横向滚动，不能隐藏错误内容来通过检查。
- 确认框验证键盘进入、取消不发送请求、关闭后焦点恢复；导航使用单一链接元素，不嵌套按钮。保存失败不出现成功消息，输入保留并支持显式重试。
- Chromium加受控API的用例用于验证前端状态、请求和交互，不能替代PostgreSQL迁移、权限、事务及真实文件导入联调。200% CSS zoom与浏览器原生缩放分别记录。
- 导入错误列表的记录标识采用 `row/username/message` 稳定组合，不使用数组下标或仅行号；同一行存在两种错误时，两条都须保留，预检与执行返回顺序变化后仍正确展示。
- 修改导入页时，浏览器回归同时收集 `pageerror` 和 `console.error`，断言预检、执行和结果展示后均为空；不能只看页面未崩溃，也不能过滤组件弃用警告来宣称通过。
- 导入结果正文使用现有正文语义色；成功状态由完成文案和现有反馈表达。普通字号文字须按浏览器实际计算颜色验证至少4.5:1对比度，不能假设组件内置成功色在白底上已达标。

## 统计图表与年级筛选

- 统计图、数字卡、热力表和导出必须来自同一受权 API 口径；筛选条件进入 React Query 的 queryKey，切换年级或日期范围时不保留旧数据冒充新结果。班级不进入账号或统计模型。
- 旧学生年级为 null，不得从学号推断；“全部”包含旧记录，“未填写年级”使用服务端显式筛选。年份展示、Excel 与接口数值保持一致。
- 规则榜单显示问题数与触达人数两个独立数值；触达人数使用接口affectedStudents，按每类问题涉及的学生去重，不能从热力图前10名或学生当前分页推算。
- 榜单和热力图不重复展示常规“规则明细覆盖 X / Y 份最近成功审核”文案；仅索引不完整时保留页面级警告，未建立历史索引的审核不能被当作零问题。没有任何成功审核时，问题数显示“—”，真实零问题显示“0”。
- 图表必须有可读数值与文本标签，键盘和屏幕阅读器可获得同等信息；窄屏允许图表区域横向滚动，但页面本身不能溢出。导出失败给出可重试反馈，不生成空文件假成功。
