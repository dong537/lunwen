# 封面页眉范围与批注文案证据

## 适用范围与数据流

`Docx4jDocumentParser → ParsedDocument → CoverHeaderScope.identify → HeaderRuleModule.check → CheckResult → CommentWriter.writeCopy`。
DOCX 的段落、首节边界和有效页眉映射是结构事实来源；文件名、学生身份或某篇论文不能作为规则白名单。不凭静态 XML 声称已确认 Word/WPS 最终页数。

## 封面组合识别契约

保留既有明确论文类型、学校名组合及严格图片封面的识别路径。仅在既有文字路径失败后使用组合证据，并同时满足：

- 有至少两节，首节是可定位到 `word/document.xml` 的非末尾独立节。
- 首个字段前有独立论文类型段落，含“毕业”与“设计/论文”，且只由本科、毕业生、设计、论文、学士、学位及括号等论文类型词构成；该文字不能独自触发封面豁免。
- 题目、学生姓名、学号均有标签和实际非空值，独立日期符合既有日期语法；全部证据位于同一首节。
- 证据取直接正文段落，不从表格、文本框、后续分节或正文示例拼凑。
- 首节后的首个非空内容是已识别的前置部分或正文结构边界，中间出现普通叙述不能跳过。
- 组合路径按整个首节确定封面范围，不把独立日期后的导师等封面内容错误当作需要页眉的正文。

证据不足保持原检查。识别首节为封面不豁免后续摘要、目录、正文等部分；共享页眉、首页不同和奇偶页设置继续遵循有效分节映射。

## 页眉结果与批注文案

`HEADER-01-MISSING` 表示相应有效页眉设置不存在，其 `source` 是正文分节定位点，不能称“空白页眉”或暗示已有共用页眉对象。

| 结果与证据 | 批注位置 | 前缀语义 |
| --- | --- | --- |
| `HEADER-01-MISSING` | 页首 | 本节缺少相应的页眉设置，批注放在本节适用页面的页首 |
| `HEADER-01-MISSING` | 原位置 | 本节缺少相应的页眉设置，批注标在本节对应位置 |
| `HEADER-01-TEXT` 且 `actual != null && actual.isBlank()` | 任一受支持回退位置 | 明确“本节页眉内容为空” |
| 其他页眉结果，或 `actual` 非空/未知 | 任一受支持回退位置 | 中性“页眉问题”，不推断整个页眉为空 |
| `placement == null` | 原正常文字范围 | 不附加回退说明 |

首个页眉段落为空不等于整个页眉为空。只根据 `HEADER-01-TEXT.actual` 判断内容空白。本次文案路径不更改锚点、状态、分组、高亮或页首定位算法。

## 必需回归

- `HeaderMetadataCoverScopeTest`：变体论文类型、完整字段、日期非最后内容的封面通过；缺字段/空值/跨节/无独立节/无结构边界/正文或前言示例不豁免；摘要缺页眉继续失败。
- 保留 `HeaderRuleModuleTest`、`HeaderImageCoverScopeTest`、`HeaderContextSourceTest`，证明共享页眉及首页/偶数页要求未被覆盖。
- `CommentWriterPageStartTest` 从 `writeCopy` 公共入口读取批注 XML，验证 MISSING 两分支、真实空页眉、首段空但后段非空、`actual=null`，同时检查原文、段落属性及批注配对。
- 真实原稿及旧批注版另存复检；核对错误批注消失、原文和分节属性不变。以移除后续页眉引用的临时副本验证后续部分仍报缺失，不能把负例副本交付为修复稿。

错误做法：根据批注锚点为空，把全部 `HEADER-*` 解释成“空白页眉”。正确做法：先区分结果语义，再根据已读取的页眉内容和实际定位原因描述。
