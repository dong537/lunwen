# 单机检测 API 设计

## 目标与边界

为第一期检测内核提供一个无需登录注册的 HTTP 接口，完成：上传 DOCX、同步执行格式检查、返回 JSON 报告，并可选生成带 Word 批注的 DOCX 副本。

本阶段不实现用户、权限、数据库、异步队列、前端页面、真实分页计算和学校原始样本验收。服务面向本机或内网单实例运行，不宣称公网上的多用户隔离能力。

## API 契约

### `POST /api/inspections`

请求使用 `multipart/form-data`：

- `file`：必填，扩展名为 `.docx`；
- `annotate`：可选，默认 `false`，为 `true` 时生成批注副本。

成功响应 `200 application/json`：

```json
{
  "requestId": "uuid",
  "sourceSha256": "...",
  "ruleSetId": "school-default-v1",
  "report": { "results": [], "diagnostics": [] },
  "annotation": { "available": true, "downloadPath": "/api/inspections/{requestId}/annotated" }
}
```

未请求批注时 `annotation.available=false`。报告中的 `REVIEW`、`UNKNOWN` 和 `UNSUPPORTED` 原样保留。

### `GET /api/inspections/{requestId}/annotated`

下载该请求生成的带批注 DOCX。不存在、未生成或已清理时返回统一错误。

### 错误响应

```json
{
  "requestId": "uuid",
  "code": "INVALID_DOCX",
  "message": "input must be a readable .docx file"
}
```

HTTP 状态映射：400 表示请求或文件格式错误，413 表示超过大小限制，404 表示批注副本不存在，422 表示 DOCX 可读取但规则执行失败，500 表示未预期错误。

## 模块与数据流

```text
HTTP multipart
  -> InspectionController
  -> InspectionService
  -> 临时文件（受限大小、随机目录）
  -> InspectionKernel.inspect(path, RuleSet)
  -> InspectionReport
  -> JsonReportWriter / CommentWriter
  -> JSON 响应与临时批注文件
```

`InspectionService` 是 API 与检测内核之间的唯一编排模块，负责 requestId、临时文件生命周期、规则版本和批注文件索引。控制器不解析 DOCX、不计算合规状态。

批注副本只保存到配置的临时根目录，并绑定源文件 SHA-256；下载前检查文件存在和绑定关系。默认保留时间为进程生命周期，清理在请求完成后删除原始上传文件，批注副本按配置保留。

## 技术选择

本阶段引入 Spring Boot Web，使用 Java 21。保留现有 Maven 单模块和 docx4j 依赖，不引入数据库、ORM 或消息队列。规则集先由固定的 `RuleSet.schoolDefault()` 提供，版本写入响应，后续再迁移为可审计的数据库或资源文件配置。

## 验证

- 单元测试：文件类型、大小限制、错误映射、批注开关和下载不存在文件；
- MVC 集成测试：真实生成 DOCX 上传，断言报告中的页边距结果和批注下载内容；
- 完整检查：`mvn -B -ntp verify -f backend/pom.xml` 与 `git diff --check`；
- 当前环境没有 Word/WPS/LibreOffice，因此只验证 OOXML 与 docx4j 回读，不宣称编辑器视觉兼容。
