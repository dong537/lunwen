# 表格、公式与参考文献检查设计

## 目标

在现有论文格式检查内核中增加三类能力：三线表题头定位与基础边框检查、公式对象识别与编号回显、参考文献类别识别。系统继续只处理 DOCX，不实现登录注册，不修改论文正文和公式对象本身。

## 已确认范围

- 表格：识别表格、表题和表格 XML 结构；检查题头位置、编号和明显边框异常。
- 公式：识别 OMML、MathType/OLE 和图片公式对象；回显公式编号、对象类型和所在位置；检查独立公式是否有编号。
- 文献：识别参考文献区域和条目编号；识别 `M`、`J`、`D`、`C`、`N`、`EB/OL` 等明确类别标识。
- 公式回显采用可读摘要和原始位置证据；不把 MathType/OLE 转换成新的公式图片或 MathML。
- 布局无法由 XML 确定时返回“需复核”，不把 XML 邻接直接当作最终屏幕位置。

## 不在本阶段

- 不自动判断真实分页、浮动对象最终视觉位置、图题是否跨页或是否同页。
- 不解析公式内部变量语义、变量说明、公式字体的完整视觉替代结果。
- 不根据作者、出版社、期刊名称或 DOI 猜测文献类别。
- 不修改公式、表格内容或参考文献文字，只写批注和报告。

## 数据流与模块边界

DOCX ZIP/XML → `DocxReader` 安全读取 → `Docx4jDocumentParser` 解析正文结构 → 结构模型（段落、表格、公式、文献条目） → 规则引擎 → JSON 报告与 `CommentWriter` 批注副本。

`Docx4jDocumentParser` 负责结构事实和 XML 来源地址；表格、公式、文献解析器负责各自对象识别；规则引擎只消费模型，不直接读取 XML；`CommentWriter` 只负责把结果映射回支持的 XML 锚点。

## 表格模型与规则

表格对象至少包含表格路径、表题段落路径、表题文本、行列数、边框证据和定位状态。表题通过相邻段落文本识别，支持“表 1-1”“表1-1”等形式。

规则编号：

- `TAB-01`：表题未识别；
- `TAB-02`：表题与表格位置无法确认，需复核；
- `TAB-03`：表格边框疑似不符合三线表；
- `TAB-04`：表编号格式异常。

表题问题批注表题段落；边框问题批注表格第一行或表格锚点。同一表格同一规则只写一条批注。

## 公式模型与规则

公式对象至少包含所在段落路径、对象类型、对象 XML 来源、公式编号、是否独立公式和回显摘要。OMML 从 `m:oMath`/`m:oMathPara` 读取；MathType/OLE 从 `w:object`、`o:OLEObject`、VML 或相关关系识别；图片公式仅标记为待复核对象。

规则编号：

- `EQ-01`：独立公式缺少编号；
- `EQ-02`：公式编号格式异常；
- `EQ-03`：公式编号重复；
- `EQ-04`：公式对象已识别但内容需要在 Word 中复核。

带批注 DOCX 保留公式 XML、OLE part、图片 part 和关系，只新增评论及必要高亮。

## 参考文献模型与规则

参考文献区域从“参考文献”或等价标题开始识别，直到附录、致谢或文档结束。每条记录包含条目段落路径、编号、原文、类别标识和解析状态。

支持类别：`M`、`J`、`D`、`C`、`N`、`EB/OL`。类别必须来自条目中的明确方括号标识，不通过语义猜测补全。

规则编号：

- `REF-01`：文献条目缺少编号；
- `REF-02`：文献类别标识缺失；
- `REF-03`：文献类别标识不支持；
- `REF-04`：文献编号重复。

边界不清的条目标记为需复核，不直接写成格式错误。批注定位到对应文献段落。

## 报告契约

报告新增结构化摘要：`tables`、`equations`、`references`、`unsupportedObjects`、`needsReview`。既有 `results` 保留，新增规则结果继续使用 `CheckResult`，并携带 `SourceAddress`。

前端按对象类型分组显示结果；批注下载路径和现有请求 ID 契约保持不变。

## 验证策略

- 为每个 XML 对象类型建立最小 DOCX fixture，并先写失败测试。
- 验证表题在多个 run、表格嵌套段落、合并单元格和边框缺失时的结果。
- 验证 OMML、MathType/OLE、图片公式不会被删除，批注副本可被 docx4j 回读。
- 验证文献条目跨 run、编号重复、类别缺失和不支持类别。
- 用真实论文完成一次 API 上传、报告生成和 Word 批注下载检查。
- 无法证明真实视觉位置时，测试结果必须是需复核而不是错误。

## 风险

- 浮动表格和文本框的最终视觉关系不能只靠 `document.xml` 确定。
- MathType/OLE 依赖嵌入对象格式和关系文件，首版只能稳定识别存在性和位置。
- 参考文献的自然语言边界可能有歧义，必须保留复核状态。
