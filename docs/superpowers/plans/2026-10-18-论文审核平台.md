# 论文审核平台实施计划

> 执行方式：使用 subagent-driven-development，并行按文件边界实施，主Agent整合与真实集成验证。

**目标：** 将现有DOCX审核工具完善为学生、教师、管理员共享的审核平台。

**架构：** 独立业务API与PostgreSQL持久状态，私有腾讯COS文件，现有审核引擎HTTP调用。前端同源会话，按角色编排。

**技术栈：** Java21、Spring Boot3.4.3、Spring Security、JPA、Flyway、PostgreSQL16、腾讯COS SDK、Apache POI、React/TS/Vite、Router、TanStack Query。

## 全局约束

以 `.trellis/tasks/10-18-thesis-platform/prd.md` 与 `.trellis/spec/platform-contract.md` 为实现依据。保留既有规则与未提交工作；不commit既有未知变更，不部署推送；不得假装COS联调成功。新代码与老代码分目录避免相互污染。

## 任务与文件边界

- [x] 账号与管理（Agent A）：platform-backend/pom.xml、Application、account/auth/common/importing包、resources配置与Flyway迁移、相应JUnit真实PG测试。先测试首次改密和跨角色拒绝，再实现；再测重置/禁用、长密码、Excel重复/错误/2000行边界。接口按platform-contract。
- [x] 提交与异步审核（Agent B）：platform-backend/submission/storage/engine包及测试。依赖UserRepository/CurrentUser/ApiResponse。先测试授权/状态转换；实现COS适配、上传与下载、worker重试和宕机恢复、教师成功统计、管理员纯计数。外部SDK可在单测边界stub，核心状态使用真实PostgreSQL；不提供生产本地存储fallback。
- [x] 前端（Agent C）：frontend目录。先添加API与关键状态行为测试，再实现登录/强制改密、学生、教师、管理员、Excel预检确认。前端不得调用旧引擎；所有请求/类型集中。编译与测试后交由主Agent真实浏览器检查。
- [x] 引擎与部署（主Agent）：backend上传/解析50MiB一致限制、资源膨胀限制、内部错误契约回归；compose四服务、平台与引擎Docker多阶段非root镜像、Nginx同源业务API、环境样例、部署文档。
