# 检测内核第一期实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or superpowers:subagent-driven-development) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立一个不含登录注册的 Java 检测内核，能够读取 DOCX 原始 OOXML 与 docx4j 有效属性，检查学校已确认的页边距、字体、字号、缩进和行距规则，并输出可追溯的结构化结果。

**Architecture:** 采用 Maven 模块化单体中的纯检测模块。`DocxReader` 只负责受限解包、原始部件哈希和 docx4j 加载；`DocumentModel` 保存有效属性与原始 XML 证据；`RuleEngine` 只比较模型和不可变规则，不重新打开 DOCX；`JsonReportWriter` 输出版本化报告。批注写入保留为独立 adapter，本计划只实现正文直接段落和表格段落所需的锚点契约。

**Tech Stack:** Java 21、Spring Boot 暂不引入、docx4j 17.2.1、Jackson、JUnit 5、Maven。

## Global Constraints

- 原件不可修改；所有结果必须绑定原始 DOCX SHA-256 与 XML 部件 SHA-256。
- 四边页边距严格按 2.6 cm，内部比较值为 1474 twips；模板实际 1418 twips 视为不合格。
- 未知属性、未支持对象和解析错误不能默认通过；分别输出 `REVIEW`、`UNSUPPORTED` 或 `ERROR`。
- 首期不自动裁决真实分页、文本框 Choice/Fallback、页眉页脚批注、旧 Equation.3 内部字号和实际字体替代。
- 不执行 OLE、不抓取外部关系、不把 docx4j JAXB 树直接持久化。
- 测试必须穿过生产模块公开接口；固定模板缺失时不能伪造通过证据。

## 计划自检

- 设计中的原件不可变、原始地址、有效属性、三维结果状态、首期规则范围和批注边界均有对应任务。
- 没有引入登录、注册、账户、角色、数据库或前端，避免把多个独立子系统混进首期内核。
- 学校原件缺失时只允许使用授权脱敏 fixture；计划不把研究日志当成生产测试通过。
- 所有失败路径都有明确错误或覆盖状态；不存在 broad catch 返回空结果的步骤。
