# 论文格式规则覆盖修复计划

> **执行说明：** 按任务分块实现，每块先补充能复现问题的测试，再修改生产代码，最后由主线程检查跨模块结果。

**目标：** 让论文筛查规则严格遵从学校规范 XML 与用户最新边界，消除已确认的漏检和误判。

**架构：** DOCX 解析器负责提供可验证的 OOXML 证据；规则引擎只基于证据生成结论；报告与 Word 批注呈现同一规则结果。无法从 XML 证明的实际打印和分页行为不伪装成通过或确定错误。

**模块边界：** 按封面、摘要、目录、正文标题与正文、公式、插图、表格、参考文献、文末部分、页码划分语义规则模块。共享段落格式检查器负责可复用的字体、字号、粗体、缩进、行距和对齐比较；引用顺序、续表对应关系、编号连续性等语义关系保留在领域检查器中。本轮优先在现有边界内补齐规则，不做一次性大规模迁移。

**技术栈：** Java、docx4j、JUnit 5、现有规则模型与报告流程。

## 统一范围与数据来源

- 当前用户要求优先于规范文件中相冲突的示例：四边距每节精确为 1474 twips（2.6 cm）；不检查全文单位写法一致；不输出正文篇幅提示；中英文摘要不设字数上限。
- 正文有效段落及标题行距统一按 OOXML `w:line=360`、`w:lineRule=auto` 检查；表格单元格、图表题、摘要、目录和参考文献分别依据各自适用规则处理。
- 表格仍检查本表参数量和单位；不得把未知量名或未知单位直接当作格式错误。
- DOCX 的 `document.xml`、`styles.xml`、分节设置是格式证据来源；不得以测试论文的个例替代规范。
- 解析、规则、批注和报告保持现有公开接口；不添加新依赖，不检查/修改全文单位一致性，不启用 PDF 渲染。

- 语义模块：封面、中文摘要、英文摘要、目录、正文标题与正文、公式、插图、表格、参考文献、致谢/附录、页码。
