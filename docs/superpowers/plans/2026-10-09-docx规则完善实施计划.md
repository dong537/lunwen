# DOCX 论文格式规则完善实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 完善 DOCX/XML 可直接证明的参考文献、表格、图片、公式和章节标题格式检查，并保证错误批注能准确定位到原始 XML。

**Architecture:** `RuleEngine` 继续负责整体编排；新增领域检查器负责单一对象类型的规则判断。解析器扩展 `TableModel`、`ImageModel`、`EquationModel` 和 `ReferenceEntryModel`，只保存可追溯的 XML 证据；`CommentWriter` 继续作为唯一批注写入模块。

**Tech Stack:** Java 21、Spring Boot 3.4、docx4j 17.2、DOM OOXML 解析、JUnit 5、React/Vite 前端。

## Global Constraints

- 只对 DOCX/XML 能证明的内容直接输出 `PASS` 或 `FAIL`。
- 对外 API 不输出 `REVIEW`，失败项必须能生成具体中文修改建议。
- 不修改原始 DOCX，只生成带批注副本。
- 同一段落同一规则只保留一条批注。
- 不引入登录注册、数据库或第二套文档解析库。
- 所有新增规则必须有通过、失败和边界测试。
