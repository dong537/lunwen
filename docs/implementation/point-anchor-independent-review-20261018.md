## 已确认的问题

| 等级 | 触发条件 | 实际结果与原因 |
| --- | --- | --- |
| P1 | 同段落的普通文字结果先处理，指向该段页首的空白结果后处理 | 原文 `PrevAbstract` 变成 `PrevAbstractAbstract`，两条结果却均为 WRITTEN。普通高亮拆分并移除了原运行；预先缓存的 `Placement.afterBreak` 仍指向脱离文档的旧运行。随后拆分旧节点并把旧标题追加回活动段落，造成正文重复。 |
| P2 | 空白结果先处理，后续字体/字号结果使用运行级 `sourceElements` | 页首拆分把标题移入新运行，缓存源仍是只含分页符的前半运行。输出仅给空分页运行着色，标题未着色，但结果仍标记 WRITTEN。 |
| P2 | 空白零宽批注先写，同段落的精确文字批注后写 | `hasCommentRange` 看到已有零宽标记后，把后续文字批注改放段尾。两个批注都变成空范围，文字错误失去原精确范围。输出顺序改变用户看到的锚点。 |
| P2 | 页首分页符前存在制表符或手动换行 | 实际插入点位于可见文本坐标 1，`anchorSource` 却记录 0..0。`address` 固定写 0..0，未计入分页符前的制表符、`br` 或 `cr`。 |

直接证据：

- `probe.log`：四种排列（段落/运行源 × 空白/文字优先）的 WRITTEN 状态、输出正文及高亮内容。
- `paragraph-text-first-output.docx`：能够直接看到标题重复。
- `run-point-first-output.docx`：标题未被着色，只有空分页运行带高亮属性。
- `offset-red.log`：第五个回归测试在旧生产快照上失败，实际 0..0、预期 1..1。

## 修复完成后的独立复核

已只读检查主 Agent 的最终生产改动：

- `Placement` 使用 `afterLeadingBreak` 布尔值，不再保存可能脱离文档的分页元素引用。
- `CommentWriter` 先完成普通文字批注组，再处理页首零宽组，保证运行级文字定位和高亮不受后续分页拆分影响。
- 插入零宽批注时重新读取活动段落中的分页边界；写入前验证分页符仍由该活动段落的直属运行持有，拒绝脱离文档或包装节点中的边界。
- `anchorSource` 记录分页符前制表符、手动换行和回车的实际字符偏移。
- 不支持的包装节点会拒绝页首候选，随后保留实际原问题位置，不会把已迁移的位置标称为原位置。

## 空节与剩余边界

- 分节没有正文段落时，页眉来源仍可保留在自身空页眉段落；不能挪到上一节的正文。当前解析器有显式跳过空节、回到原页眉的路径。
- 主文档来源若是没有可用段落的末尾 `sectPr`，`resolveAnchor` 可能在页首解析前就返回 `EMPTY_ANCHOR`。这类输入不能据已有“空段落可写批注”测试宣称均已支持；保留明确未写入结果，不能借用别节文字。
- 本次未确认额外的生产错误。已复核修复实现及 16 个通过的锚点测试；空终端分节边界和真实论文重测仍按上述范围记录，不能借此宣称所有空分节都可写入。
