# 公式批注源坐标修复（2026-10-18）

## 目标与范围

修复最新 16 篇交付中第 09 篇《数学论文初稿(测试版)》的公式批注越界。仅修改公式解析器及其回归测试；不改批注写入器、页码锚点迁移或变量判定规则。

数据链路：原始 DOCX 的 `word/document.xml` → `EquationParser` 的 `SourceAddress` → 已有规则结果 → `CommentWriter`。XML 中实际存在的可见字符是批注坐标的唯一来源；供人阅读的公式摘要不能提供坐标。

## 已复现的原因

本次基线目录由 `logs/latest-16-output-path.txt` 指向：`16篇论文-行距修复全量重检-20261018-174614`。来源取其 `批量检测汇总.json` 的第 09 项原始文件，未使用已批注的输出作为输入。原始 SHA-256 为 `a32f6bd186505b18518fd859ace3a2e5932d3aedfb2fb5fc475e5cce4b5c1f18`。

- 56 条公式结果未写入，涉及 15 个公式段落：EQ-07 15 条、EQ-02 15 条、EQ-04 15 条、EQ-03 11 条。
- 公式摘要为了区分相邻数学变量，在文本之间补了用于阅读的空格。旧代码直接把摘要长度作为段落结束坐标。
- 例：段落路径 `[0,151]` 的原始数学文本长 51，摘要因分子、分母之间增加空格变为 52。旧范围 `0..52` 超过实际文本。其余 14 处多出 1–7 个字符。
- 批注写入按段落分组，一个结果越界会使同段的编号、引用等结果一并未写入，所以不能把 56 条失败都解释为编号本身损坏。
- 另一个坐标问题：OMML 编号使用所在数学运行的局部 `0..5`，而批注写入要求包含段内此前文本的坐标。上例编号实际为 `46..51`。
- 分片编号另有可复现问题：单行公式数组只接受最后两个运行分别为 `#` 和完整编号；合法的 `(3-`、`1)` 两段编号不能识别。多行数组已有拼接逻辑，两个路径不一致。

## 修复内容

1. 公式范围直接映射原始 XML 子树对应的可见文本，不再使用摘要长度。保留摘要中用于阅读的分隔符。
2. 映射同时计算 Word/OMML 文本、制表符和手动换行；不计域指令、分页/分栏标记、删除内容、移出修订或嵌套段落。
3. 内嵌对象没有可见字符时，使用对象在段内的准确零宽位置；不把“嵌入公式对象”等说明文案长度当成正文字符。
4. OMML 编号保留原数学运行路径，起止位置使用段落累计坐标，并准确排除编号两端空白。
5. 单行、多行公式数组统一使用已有的编号尾部拼接规则；居右证据同样认可跨多个数学运行的编号。
6. 未通过放宽范围、截断越界或设置容差来掩盖错误；未改动变量提取或变量说明判定。

## 回归与验证

新增四个测试：

- `usesXmlTextLengthRatherThanDisplaySummaryForFractionAnchor`：真实结构的 52/51 长度差及编号 `46..51`。
- `anchorsInlineEquationUsingVisibleParagraphCoordinates`：前置文字、制表符、手动换行、修订和域指令混合时的精确位置。
- `anchorsSplitMathNumberAtItsExactParagraphOffset`：单行公式数组中的分片编号、前后空白和居右证据。
- `objectDescriptionDoesNotBecomeAVisibleTextRange`：OLE 对象说明文字不得制造虚假的字符范围。

执行证据：

- 主 Agent 的 Maven RED 日志：`logs/equation-anchor-red.log`，4 个新增测试均未通过（其中单行分片编号暴露真实识别缺口）。
- 本子任务未执行 Maven；用独立输出目录编译 Java 并调用 JUnit 断言，全部 50 个 `EquationParserTest` 方法通过：`logs/equation-anchor-check-20261018/green.log`。没有写入共享 `backend/target`。
- 对原始数学论文重新解析，37 个公式范围均未越界，所有具有 OMML 编号证据的范围均能从原始段落精确截取出相同编号；15 个原越界段落的坐标均已修复。证据为同目录的 `source-coordinates.json` 和 `coordinate-validation.json`。
- Maven 定向/全量测试，以及完整服务重新检测后的实际批注写入结果，由主 Agent 汇总；此处的坐标验证不替代这些验证。

## 边界

这次证据证明的是公式批注坐标错误，不证明 EQ-07 的变量错误判定都正确。原有普通 Word 运行编号的坐标、数学变量局部坐标属于另一套已有定位路径；本次不扩大修改到全文段落模型或批注接口。不得据本次修复宣称所有公式检查已百分之百准确。
