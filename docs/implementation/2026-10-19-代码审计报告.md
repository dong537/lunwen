## 已确认问题

### 1. P1：切换账号后，旧页面仍能以新账号发起原账号文件上传

- 触发：页签 A 登录学生甲并选文件，页签 B 退出并登录学生乙，然后回 A 提交。
- 结果：A 仍显示甲且保留所选文件，实际 Cookie 已属于乙，仍发起上传请求。后端按真实 Cookie 身份确定归属，因此文件可能被提交到乙名下。
- 证据：真实登录与浏览器复现账号 `11 → 12`；上传 POST 在测试边界被阻断，没有实际提交论文。归属后果由后端 principal 数据流确认，未冒称真实 COS 上传成功。
- 根因：会话变化通知只作用于当前 window，缺少跨页签同步；会话缓存未刷新前，写操作也未核实选择文件时的身份。
- 位置：[session.tsx:23](../../frontend/src/features/auth/session.tsx)、[http.ts:66](../../frontend/src/shared/api/http.ts)、[SubmissionPages.tsx:20](../../frontend/src/features/submissions/SubmissionPages.tsx)。
- 修复方向：会话模块统一同步登录/退出/改密；身份变化立即清理私有缓存、File 与表单；提交与发起时身份绑定。不能仅缩短缓存时间。

### 2. P1：管理员接口已经返回 403，页面仍展示账号名单

- 触发：管理员页已缓存账号列表，另一页签切换到学生，再回旧页请求名单。
- 结果：后端正确拒绝并返回 403，页面显示无权限错误，却继续显示缓存的学号、姓名、专业、导师及管理按钮。
- 根因：展示错误后仍无条件渲染 list.data。此为浏览器缓存泄露，未发现该场景下后端 API 越权。
- 位置：[UserPages.tsx:194](../../frontend/src/features/users/UserPages.tsx)（194–196、222–272 行）。
- 修复方向：授权拒绝立即隐藏对应缓存与操作，再重新确认会话；网络失败是否显示旧数据应与权限拒绝分开。

### 3. P1：COS SDK 错误日志包含完整请求签名

- 触发：真实 SDK 请求发生 HTTP 503 或超时。
- 结果：SDK 在 adapter 捕获异常之前，将 Authorization、对象路径和请求方法写入 ERROR 日志；外层异常脱敏无法撤回该日志。
- 风险：日志读者获得的是签名有效期内的请求凭据，可尝试重放对应请求；不是永久 SecretKey 泄露。本轮使用本地 HTTP 和无效测试凭据，未对真实 COS 重放。
- 证据：`signedHeaderCount=2 fakeAccessKeyAndSignatureSeen=true`；持久证据已脱敏，未打印真实凭据。
- 位置：[CosObjectStorage.java:23](../../platform-backend/src/main/java/cn/luwneshacha/platform/storage/CosObjectStorage.java)（23–40、82–96 行）。
- 修复方向：从 SDK 原始请求日志入口阻止签名落盘，保留 adapter 的安全诊断；测试必须走真实 SDK 错误路径。

### 4. P1：转换服务故障被告知为“文档损坏”，且不重试

- 触发：转换程序不可用等运行环境故障。
- 结果：引擎产生 FORMULA_CONVERSION_FAILED，但异常处理器返回 HTTP 400；平台把 400 统一视为文档损坏、不可重试，首次就进入 FAILED 及失败文件清理。用户重新保存 Word 不能修好服务环境。
- 证据：实际引擎服务类、异常处理器和平台 adapter 联合探针得到 `http=400 retryable=false`。报告写入 I/O 故障使用同一默认 400 路径，为静态证据。
- 位置：[ApiExceptionHandler.java:22](../../backend/src/main/java/cn/luwneshacha/thesis/api/ApiExceptionHandler.java)、[InspectionService.java:83](../../backend/src/main/java/cn/luwneshacha/thesis/api/InspectionService.java)、[HttpAuditEngine.java:120](../../platform-backend/src/main/java/cn/luwneshacha/platform/engine/HttpAuditEngine.java)。
- 修复方向：以明确的错误代码区分文件非法、转换/报告/存储服务故障，再决定 HTTP 状态、文案和重试策略。

### 5. P1：原文被全部替换，批注产物仍能通过校验

- 触发：引擎错误返回非空但与输入不相符的批注 Word。
- 结果：平台只判断输入有内容时输出是否完全为空；不检查原段落、表格、图片和公式是否保留。
- 证据：故障注入把输入两段原文全部换成无关内容，并放入合法批注与关系，真实 adapter 仍接受：`accepted=true original-paragraphs=2 marked-original-paragraphs=0`。
- 边界：这证明保护逻辑有漏洞，**不代表已发现真实用户论文被替换或丢失**。
- 位置：[MarkedDocumentValidator.java:22](../../platform-backend/src/main/java/cn/luwneshacha/platform/engine/MarkedDocumentValidator.java)。
- 修复方向：按批注允许的变更验证规范化内容及对象序列保留；公式转换使用单独的变换契约。

### 6. P2：COS 的“总超时”没有覆盖部分响应正文

- 触发：服务及时返回响应头，但缓慢传输 listObjects XML 或 PUT 错误正文。
- 结果：每次读取未超过 socket 空闲限制时，SDK 调用仍可超出配置的 requestTimeout；影响上传、任务租约预算和清理。
- 证据：将真实 SDK 预算缩短为 250ms，控制组响应头超时为 289ms；列表正文耗时 1086ms，PUT 错误正文耗时 763ms。是时间尺度缩短的验证，不是声称线上已等待超过五分钟。
- 位置：[CosObjectStorage.java:26](../../platform-backend/src/main/java/cn/luwneshacha/platform/storage/CosObjectStorage.java)（26–40、74–86 行）。
- 修复方向：完整请求连同正文共用截止时间，超时应取消底层 I/O；仅设置读取空闲超时不够。

### 7. P2：历史文件清理会阻塞整个实例的任务领取

- 触发：任一历史失败任务的 COS 删除/列举变慢。
- 结果：清理与领取共用实际大小为 1 的调度池；一次补偿最多串行处理 100 条记录，清理等待时新论文无法领取，租约恢复也停住。
- 证据：真实 Boot 调度拓扑与生产 worker，清理阻塞约 25 个轮询周期，领取计数 `1 → 1`，释放后立即 `→ 2`。外部存储等待使用受控 latch，未替代数据库业务验收。
- 位置：[SubmissionWorker.java:35](../../platform-backend/src/main/java/cn/luwneshacha/platform/submission/SubmissionWorker.java)（35–40、74–85 行）。
- 修复方向：任务执行与清理有界隔离，约束单次补偿耗时，避免无关 I/O 阻塞队列推进。

### 8. P2：上传中离开页面，成功后返回仍显示“没有提交记录”

- 触发：上传未完成即离页，后台返回 202，10 秒内回列表。
- 结果：组件已卸载，组件级成功回调不执行，列表没有失效；旧空列表不触发轮询，继续等待 11.5 秒也没有新的列表请求，手动刷新才出现记录。
- 证据：真实登录与生产 UI，提交 API 边界控制时序；并未验证真实 COS 上传。
- 位置：[SubmissionPages.tsx:27](../../frontend/src/features/submissions/SubmissionPages.tsx)（27–47、119–124 行）。
- 修复方向：缓存失效放在不依赖页面存活的成功处理，并校验会话归属；页面跳转仍只属于原页面。

### 9. P2：改密成功后，被尚未完成的旧请求再次退出登录

- 触发：同一会话中的旧请求持有旧密码指纹，另一个请求先完成改密。
- 结果：改密返回 200 且新密码已入库；旧请求继续运行，发现指纹过期，直接 invalidate 已经更新认证状态的同一 HttpSession。
- 证据：真实生产认证实现与一次性 PostgreSQL，控制并发顺序后得到 `passwordResponse=200 oldRequestResponse=401 newSessionInvalidated=true passwordChanged=true`。
- 位置：[SessionGuardFilter.java:22](../../platform-backend/src/main/java/cn/luwneshacha/platform/auth/SessionGuardFilter.java)、[AuthController.java:56](../../platform-backend/src/main/java/cn/luwneshacha/platform/auth/AuthController.java)。
- 修复方向：区分请求所属的旧认证状态与 session 当前认证代次，阻断旧请求同时保留之后建立的有效会话。

## 单列观察，不混入 9 项确认缺陷

1. **旧公式转换仍有未收敛问题。** 当前镜像只有 Writer；同一样本补装 Math 后由“0 个公式”变为“1 个空公式”，本机完整 LibreOffice 也输出空公式。源 OLE 有效性尚未独立验证，不能简单判断“都是论文的问题”或“装 Math 就修好了”。需使用已知有效的样本核对转换内容。
2. **导师停用后修改学生姓名受阻。** 保留原 teacherId、只更正姓名会返回 INVALID_TEACHER。该行为已复现，但需求未明确是否强制先换导师，列为业务口径待明确，未当作已确认权限缺陷。
3. **控制字符导致导入整批中断的假设被排除。** 本次测试三行均成功，未以未成立假设凑问题数量。
4. **真实 COS 验收仍缺少配置。** 尚未完成真实桶合法上传→审核→批注保存→授权下载→失败清理的完整验证；本地 HTTP 探针不能替代该验收。
