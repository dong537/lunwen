# 论文格式检查规则修改总表

这份文档是当前代码规则的维护入口。规则修改必须同时更新实现、原因说明、批注文案和回归测试。

## 解析层

- 通过 docx4j 读取正文、表格、图片、公式、页眉页脚和页码的 OOXML 属性。
- 字体、字号、页边距、首行缩进、行距、标题层级和编号使用 XML 属性或原始文本精确比较。
- 表格解析保留表头、边框、合并单元格、单位、续表标题和 XML 数值有效性。
- Word 将一个视觉表格拆成多个 XML 表时，规则层使用相邻表结构进行语义归并，不能按单个 `w:tbl` 直接下结论。

## 规则层

- 正文：宋体、Times New Roman、字号、首行缩进、1.5 倍行距。
- 标题：一级、二级、三级及三级以下标题的层级、空格、字体、字号、行距和分页。
- 摘要：中英文标题、空行、摘要正文、关键词数量、分隔符、加粗和对齐。
- 图表：编号、题注位置、引用、连续性、三线表边框、表头、单位、表注和续表。
- 公式：编号、圆括号、章节连续性、引用、变量说明和 OMML/OLE 能力边界。
- 参考文献：类别、数量、编号顺序、正文引用、字体、字号、行距和引用格式。
- 页码和页边距：正文到附录的连续页码、页脚居中、Times New Roman 五号、四边 2.6 cm。

## 已修复的共性误判

### 封面字段空白

`学    号`、`院    系` 等字段内部的排版空白合法。规则允许 Unicode 空白，但仍检查字段名称、冒号和字段值边界。

### Word 分割续表

同编号表格中优先选择完整原表；若存在与原表表头完全相同的单行重复表头，则将其作为 Word 分割产生的重复节点。只有表头证据确实不同才报 `TABLE_CONTINUATION_HEADER_MISMATCH`。

### 英文关键词数量

`Keywords:` 后英文关键词必须为 3 至 5 个。原因码为 `ENGLISH_KEYWORD_COUNT_MISMATCH`，报告和 Word 批注均输出中文修改建议。

### 批注和报告一致性

所有原因码必须在 `RuleDescriptions` 中有中文原因和建议；`CommentWriter` 必须为同一原因码生成自然中文批注。一个段落同类错误合并为一次批注，避免重复高亮。

## 禁止的回归方式

- 不得按论文文件名、学生姓名或单篇论文路径添加特例。
- 不得用数值容差替代规范的精确 XML 比较。
- 不得把 XML 无法证明的版面事实直接判为格式正确。
- 不得只修改报告文案而不修改 Word 批注文案。
- 不得用旧批注文档作为新规则的输入基线；重跑必须使用原始论文。

### 续表分割片段归属

Word 可能把续表前的最后一行单独保存为一个无表题 `w:tbl`，随后才写入“续表编号”段落和真正的续表。解析器只把续表标题绑定到标题后的表；规则引擎会依据前置同编号原表、列数一致和 XML 顺序跳过这个分割片段的独立表题及三线表检查，避免把真实数据行误报为缺表题或缺边框。

## 必跑验证

```powershell
mvn -s settings.xml -q '-Dtest=RuleEngineTest,TableRuleCheckerTest,RuleDescriptionsTest,CommentWriterTest' test
mvn -s settings.xml -q verify
```

Docker 更新顺序：

```powershell
mvn -s settings.xml -q -DskipTests package
docker compose build backend
docker compose up -d --force-recreate backend
```

交付前至少用一篇含封面字段空白、一个 Word 分割续表和一篇英文关键词超过 5 个的原始论文做端到端验证。
