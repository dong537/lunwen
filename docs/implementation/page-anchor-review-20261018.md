# 无文字批注定位复审（2026-10-18）

## 范围与证据

本次只复审 `PageStartAnchorResolver`、`CommentWriter` 的无文字错误定位，以及页眉规则向批注器传递适用分节的路径。规则证据地址 `source` 必须保持原值；实际写入位置单独记录为 `anchorSource`。批注器不能重新定义封面豁免规则。

原稿来源从 `16篇论文-行距修复全量重检-20261018-174614` 各篇 `来源记录.json` 获取。具体 XML 路径与图片封面证据另见 `textless-page-anchor-audit-20261018.md`。本文记录静态审查发现及修复职责，不代表全量 Maven 或 16 篇真实检测已经通过。

## 阻断问题

### P1：复用页眉可能把摘要错误迁回封面

规则模块已跳过封面分节，但旧定位器从页眉关系重新搜索第一个引用该部件的分节。封面独立成节、摘要继承同一页眉时，定位器会选择封面，破坏规则的适用范围。

修复边界：`HeaderRuleModule` 根据 `CoverHeaderScope`、当前分节及页眉类型完成适用判断，并用 `CheckResult.contextSource` 传递该分节的首个适用主文档段落。页眉自身仍是 `source`。`PageStartAnchorResolver` 仅在该上下文内寻找定位证据，不复制封面识别逻辑。空末节必须使用自己的空段落，不能借前一节致谢。

定向测试覆盖独立封面、同节封面与摘要、图片封面、封面 FIRST 与后续 DEFAULT 复用、后续分节 FIRST、独立空末节及旧构造器。主代理已运行 RED：`logs/header-context-red.log`，7 项测试、6 项失败、0 个错误。随后完成 `HeaderRuleModule` 上下文传递实现。子代理读取最新 Surefire XML 确认 GREEN：`HeaderContextSourceTest` 7 项、`HeaderImageCoverScopeTest` 10 项、`HeaderRuleModuleTest` 28 项，均零失败、零错误、零跳过。

### P1：分页符和标题位于同一文字片段时，零宽批注可能插到上一页

`<w:r><w:br w:type="page"/><w:t>标题</w:t></w:r>` 中，文本偏移 0 不足以表达分页符后的插入点。若直接在整个 `w:r` 前放批注，批注位于分页符前。真实 11、16 原稿的致谢存在同一片段内 `lastRenderedPageBreak` 后紧接“致”的结构。

修复边界：保留具体分页元素后的 DOM 边界，写入器在该边界处理批注；复杂包装内无法保持该边界时保留原始定位，不声称已经定位到页首。主代理负责定位器、写入器与对应回归。

### P1：默认段落样式识别把缺失属性当成启用

对 `<w:pageBreakBefore/>`，缺少 `w:val` 表示启用；但对 `<w:style>`，缺少 `w:default` 不代表默认样式。旧实现复用了同一判断，把之后的 Heading1 等样式覆盖为默认段落样式，可能把无 `pStyle` 的正文误判为分页开始。

复审时主代理已加入 `style.hasAttributeNS(w, "default")` 条件。需要测试验证：Normal 是默认样式，后置 Heading1 不带 default 且包含 pageBreakBefore，普通正文不能被当成页首。

## 其它边界

- 页首和错误源点之间若存在未知自动分页范围，不能仅凭节首推断它们同页。复审时已看到定位器在两者之间存在可见内容或对象时停止迁移；仍需动态测试。
- `lastRenderedPageBreak` 是保存时的版面缓存，文案不应暗示系统重新执行了 Word 排版。显式分页、缓存分页和原位置应分别记录证据。
- EVEN 页眉对应的物理页码奇偶无法由此定位器确认；保持页眉源点比迁到任意正文页更准确。
- 页眉适用分节上下文不等于 DEFAULT、FIRST、EVEN 的物理页首。定位器仍需核对启用的首页不同设置与分页证据。
- 在插入批注之前解析全部锚点 Element，能够避免新增节点改变后续路径索引。零宽路径不应插入可见说明文字或不必要的高亮。
- 验证除文字不变外，还应检查段落属性、分页元素、域、图形及批注起止配对；文字相同不代表 DOCX 结构未受影响。
