## 运维与回退

当前平台的只读状态命令：

```bash
sudo docker compose --env-file /opt/thesis-platform/.env -p thesis-platform -f /opt/thesis-platform/compose.json ps
curl --fail --silent --show-error https://124.223.86.157/api/health
```

引擎属于原项目，更新时使用 `/opt/thesis-inspection/compose.yaml` 和 `/opt/thesis-inspection/compose.release.yaml`，仅操作 `backend`。不要无范围执行 `up` 以重新开放旧免登录前端。平台重建后须同步重载/重建前端以重新解析上游容器地址。

发布证据位于 `/opt/thesis-platform/releases/release-20261019-131415/`，当前指针为 `/opt/thesis-platform/current-release.json`。该发布目录保留 `previous-nginx.conf`、旧发布指针、旧Compose和 `rollback-engine.compose.json`。

回退要分别决定是否恢复旧入口、是否恢复旧引擎。恢复旧入口意味着恢复免登录行为，不能视为权限等价回退。先停止接收新业务并保留当前提交，再恢复选定配置、检查Nginx语法及实际健康/业务行为。无论回退哪一层，均保留新平台数据库和COS文件；禁止 `down -v`、删库或清空对象。旧镜像直接使用，不能在回退时重新编译。
