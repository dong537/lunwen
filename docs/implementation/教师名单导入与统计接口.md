# 教师名单导入与统计接口

本文供教师端前端对接使用。本次增加单名学生创建、教师名单批量导入和统计后端接口，不包含前端页面。所有教师接口只操作当前登录教师名下的学生，不接受客户端指定其他指导教师。

## 1. 通用约定

- 接口前缀为 `/api`，使用当前平台的会话 Cookie。浏览器请求携带 `credentials: 'include'`。
- JSON 字段采用 camelCase。账号及提交 ID 为字符串，计数为数字，时间为 UTC 的 ISO 8601 字符串。
- 成功 JSON 为 `{data, error: null, requestId}`；失败为 `{data: null, error: {code, message, fieldErrors}, requestId}`。展示后端中文 `message`，支持字段错误时展示 `fieldErrors`，排查时保留 `requestId`。
- 教师账号须已启用并完成初始密码修改。后端每次核对数据库中的角色、状态及当前师生归属；客户端隐藏按钮不能代替权限检查。
- `POST` 需要 CSRF：先调用 `GET /api/auth/csrf`，读取 `data.headerName` 与 `data.token`，再将该名称和令牌放入请求头。登录和改密后重新获取，不硬编码令牌。
- 新创建学生初始密码沿用 `123456`，首次登录可直接使用论文功能；仍可自愿改密。创建和导入响应不返回密码散列。统一初始密码不强制修改时存在冒用风险，上线前需改为每人独立密码并安全发放。

## 2. 接口一览

| 方法 | 路径 | 用途 | 成功状态 |
| --- | --- | --- | --- |
| POST | `/api/teacher/students` | 新增单名学生 | 201 |
| GET | `/api/teacher/students/imports/template` | 下载教师学生导入模板 | 200，Excel 文件 |
| POST | `/api/teacher/students/imports/preview` | 预检教师学生名单 | 200 |
| POST | `/api/teacher/students/imports/execute` | 执行教师学生名单导入 | 200 |
| GET | `/api/teacher/students` | 查询名下学生 | 200 |
| GET | `/api/teacher/students/{id}` | 查询名下学生资料 | 200 |
| GET | `/api/teacher/students/{id}/submissions` | 查询该学生提交历史 | 200 |
| GET | `/api/teacher/statistics` | 当前教师的学生及审核统计 | 200 |

## 3. 新增单名学生

`POST /api/teacher/students`，`Content-Type: application/json`。

```json
{
  "username": "2022001001",
  "name": "示例学生",
  "major": "计算机科学与技术"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| username | 是 | 学号，同时为登录账号；3–32 位字母、数字或下划线，保留前导零 |
| name | 是 | 姓名，非空且不超过 64 个字符 |
| major | 否 | 专业，不超过 64 个字符；空内容按未填写保存 |

不发送 `role`、`teacherId` 或自定义初始密码。新学生角色固定为 `STUDENT`，指导教师固定为当前登录教师。

成功响应的 `data` 为 `UserView`：

```json
{
  "id": "101",
  "username": "2022001001",
  "name": "示例学生",
  "role": "STUDENT",
  "major": "计算机科学与技术",
  "teacherId": "10",
  "teacherName": "示例教师",
  "active": true,
  "mustChangePassword": true
}
```

用户名在全平台唯一。若已存在，返回 409，不覆盖原资料，也不将其他教师的学生转到当前教师名下。

## 4. 教师名单批量导入

### 4.1 模板与文件要求

从 `GET /api/teacher/students/imports/template` 下载 `.xlsx` 模板。文件包含一张工作表，三列表头顺序固定：

| 学号 | 姓名 | 专业 |
| --- | --- | --- |
| 2022001001 | 示例学生甲 | 计算机科学与技术 |
| 2022001002 | 示例学生乙 | 软件工程 |

名单中的新学生自动归属当前登录教师，文件中不填写指导教师。教师模板与管理员模板不同，不混用。

- 仅支持未加密的 `.xlsx` 文件，文件最大 5 MiB，每次最多 2000 条数据行。
- 只保留一张工作表，保留模板表头，不增加额外列。
- 学号使用文本单元格，避免前导零丢失或变为科学计数法。已经丢失的数字无法靠后台还原。
- 不使用公式；公式、错误单元格、模板以外内容及过长内容会得到文件错误或对应行错误。
- 空白数据行不计入名单；错误行号按 Excel 中的实际行号返回，表头为第 1 行。

### 4.2 预检

`POST /api/teacher/students/imports/preview`，使用 `multipart/form-data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| file | 文件 | 教师学生导入模板填写后的 `.xlsx` |

浏览器使用 `FormData` 时由浏览器生成 `Content-Type` 及 boundary，不手写该请求头；CSRF 请求头仍须携带。

预检不创建账号。示例 `data`：

```json
{
  "totalRows": 4,
  "validRows": 1,
  "successCount": 0,
  "skippedCount": 1,
  "failedCount": 2,
  "errors": [
    {"row": 4, "username": "bad001", "message": "请填写姓名"},
    {"row": 5, "username": "bad-002", "message": "账号须为3至32位字母、数字或下划线"}
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| totalRows | 文件中非空数据行总数 |
| validRows | 本次校验通过、可以新增的行数；执行时为实际新增成功行数 |
| successCount | 实际成功新增行数；预检固定为 0 |
| skippedCount | 平台已存在同名账号而跳过的行数 |
| failedCount | 校验失败行数，与 `errors` 条数一致 |
| errors | 逐行错误，包含 Excel 行号、输入学号及中文原因 |

同一文件里出现重复学号时，所有重复行都失败，不采用“先出现者成功”的处理。平台中已存在的账号会跳过，不更新其姓名、专业或教师归属。

### 4.3 执行与恢复

`POST /api/teacher/students/imports/execute`，请求字段与预检一致，返回相同的 `ImportResult`。

执行必须重新上传文件。后端会重新读取文件和数据库，不接受前端传入的“预检通过行名单”；因此预检后其他操作新增了同学号账号时，执行结果可能多出跳过行。

每行单独提交事务：合法行导入成功，错误行保留具体原因，不会因某一错误行撤销其他已成功行。`HTTP 200` 仅表示导入处理已完成，必须根据 `successCount`、`skippedCount`、`failedCount` 展示结果，不能直接显示“全部导入成功”。

若导入过程发生账号撤权、服务或数据库故障，请求会返回失败；故障前已成功导入的学生仍保留。排除原因后可重新上传原文件，已存在账号会跳过，避免重复创建。不要在收到错误响应后假定整份文件已回滚。

## 5. 学生列表与详情

`GET /api/teacher/students?q=&page=1&size=20`。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| q | 空字符串 | 搜索学号或姓名，最多 100 个字符 |
| page | 1 | 从 1 开始 |
| size | 20 | 1–100 |

列表包含当前名下启用及停用学生，保留既有响应字段。

成功响应 `data`：

```json
{
  "items": [
    {
      "id": "101",
      "username": "2022001001",
      "name": "示例学生",
      "major": "计算机科学与技术",
      "submissionCount": 2,
      "lastSubmittedAt": "2026-11-13T06:30:00Z",
      "latestProblemCount": 7
    }
  ],
  "total": 1,
  "page": 1,
  "size": 20
}
```

`submissionCount` 继续只计成功审核次数。`lastSubmittedAt` 和 `latestProblemCount` 取同一条最近成功审核记录，不被后来的失败、排队或审核中记录覆盖。没有成功审核时次数为 `0`，后两项为 `null`，应显示“—”，不能显示“零问题”或“已通过”。

`GET /api/teacher/students/{id}` 返回既有 `UserView`。提交历史接口 `/api/teacher/students/{id}/submissions` 保留现有分页契约；历史记录包括失败，与列表的成功次数不同。

## 6. 教师统计

`GET /api/teacher/statistics` 查询当前教师名下全部学生的汇总，不接受 `teacherId`。响应 `data` 直接包含以下十个统计字段：

```json
{
  "totalStudents": 3,
  "activeStudents": 3,
  "submittedStudents": 2,
  "notSubmittedStudents": 1,
  "studentsWithSuccessfulReview": 2,
  "successfulSubmissions": 3,
  "pendingSubmissions": 0,
  "processingSubmissions": 0,
  "failedSubmissions": 1,
  "latestSuccessfulProblemCount": 8
}
```

统计字段口径：

| 字段 | 类型 | 口径 |
| --- | --- | --- |
| totalStudents | number | 名下学生总人数，包含停用学生 |
| activeStudents | number | 其中账号启用的学生人数 |
| submittedStudents | number | 至少存在一条持久提交记录的学生人数，每名学生只计一次；失败和上传预留记录也计入 |
| notSubmittedStudents | number | 没有任何持久提交记录的学生人数，即总人数减已提交人数 |
| studentsWithSuccessfulReview | number | 至少成功审核一次的学生人数，每名学生只计一次 |
| successfulSubmissions | number | 当前状态为 `SUCCESS` 的提交记录总数 |
| pendingSubmissions | number | 当前状态为 `PENDING` 的提交记录总数，含尚未释放的上传预留 |
| processingSubmissions | number | 当前状态为 `PROCESSING` 的提交记录总数 |
| failedSubmissions | number | 当前状态为 `FAILED` 的提交记录总数；表示审核流水失败，不表示论文格式不合格 |
| latestSuccessfulProblemCount | number 或 null | 每名学生最近一次成功审核的问题数之和；范围内没有任何成功审核记录时为 `null` |

学生数与提交记录数不能混用。一个学生多次提交可能计入多个状态的记录数，因此不能把 `pendingSubmissions + processingSubmissions + failedSubmissions` 当作学生人数。

最近成功记录以提交时间倒序、同时间时 ID 倒序确定。假设学生甲两次成功的问题数为 12、5，之后又失败一次，学生乙最近成功为 3，则问题汇总是 `5 + 3 = 8`，不是历史累计 20，也不会因甲最新失败而丢掉其成功结果。

无学生时人数与提交次数均为 `0`，`latestSuccessfulProblemCount` 为 `null`。有成功审核且所有最近成功结果均为零问题时，该字段才为 `0`。界面应区分“尚无成功结果”和“最近成功结果零问题”。

## 7. 错误与界面处理

| HTTP 状态 | 典型原因 | 建议处理 |
| --- | --- | --- |
| 400 | 字段格式、模板表头、文件类型或行数不符 | 展示中文原因；存在字段错误时定位输入项 |
| 401 | 未登录、会话失效或账号停用 | 返回登录流程，清除旧账号的业务缓存 |
| 403 | 非教师、首次未改密、学生不归属当前教师或缺少 CSRF | 显示无权限/改密提示；CSRF 失效时按平台流程重新取得令牌 |
| 409 | 单名创建时账号已存在，或并发数据冲突 | 提示重新检查学号或刷新，不自动覆盖已有账号 |
| 413 | 文件超过大小上限 | 提示拆分文件或删除多余内容后重试 |
| 500 | 服务暂时异常 | 展示安全提示及 requestId；导入不假定整体回滚 |

常用错误码包括 `USERNAME_EXISTS`、`VALIDATION_ERROR`、`INVALID_REQUEST`、`UNAUTHENTICATED`、`FORBIDDEN`、`PASSWORD_CHANGE_REQUIRED`、`FILE_TOO_LARGE`，Excel 还会返回 `IMPORT_*`。单名 JSON 的字段校验失败返回 `VALIDATION_ERROR`，无法解析的参数返回 `INVALID_REQUEST`。前端不按中文消息文本判断业务分支。

管理员导入路径、四列学生模板和既有账号管理权限保持原契约；教师端新增能力不表示教师可以调用 `/api/admin/**`。
