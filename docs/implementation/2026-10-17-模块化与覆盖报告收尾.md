# 模块化规则、批注锚点与报告覆盖收尾

## 目标与验收

在保留现有论文规则结果的前提下，继续把图表/公式/封面规则从 `RuleEngine` 移入语义模块；真实支持报告中的规则覆盖及未检查区域清单；让批注器对可定位的正文、页眉页脚、文本框、修订、脚注尾注内容写入批注，并对 OOXML 新版批注元数据保持有效。每项变化均需通过真实规则/文档 XML 测试验证，不以空模块或仅存在部件文件视为完成。

## Source of Truth 与边界

- DOCX XML 解析模型是可检查范围的来源；批注报告必须与本次实际运行结果及批注写入记录一致。
- `RuleCatalog` 是学校规则清单的唯一登记源；未登记的动态规则必须显式显示为未登记，不能藏在默认模块里。
- `RuleEngine` 继续保留跨区域状态/顺序关系；单一文档对象和段落规则归对应领域模块；共享格式比较只归 `ParagraphFormatChecker`。
- `CommentWriter` 对每条注释接收显式父评论 ID（无父 ID 表示顶层评论）；不推断回复关系。老的单评论输入仍表示顶层评论。
- 不新增依赖，不修改历史论文或部署产物；无法从 XML 验证的最终分页/显示继续标记未确认。

## 执行次序

1. 先用测试锁定公式迁移不重复、封面模块无重复、图表检查输出与原行为一致。
2. 将图题格式/引用/居中/编号连续性迁至插图模块，并将表格旁边的图表专属助手移出主引擎；保留真正共享章节分类状态的助手时须明确理由。
3. 审查 `CommentWriter` 的锚点解析与新版批注元数据。新增显式父评论关系及往返 XML 测试；正文等现有行为不变。
4. 审计所有生成的规则 ID 与 `RuleCatalog`；报告显式展示未登记规则、规则执行状态和无法检查区域。
5. 先运行定向测试，再运行 `mvn test` 与 `git diff --check`；记录任何原有失败和真实边界。

## 不做

- 不宣称支持 Word/WPS 所有批注线程功能，除非 `comments.xml`、`commentsExtended.xml`、`commentsIds.xml`、`people.xml` 的关系经过 XML 回读验证。
- 不把批注锚点能定位等同于该区域内所有格式规则均已检查。
- 不用通用容错、全文正则或测试论文特判掩盖证据缺失。

## 规则口径复核（2026-10-17）

### 目标与验收

- 致谢标题严格使用“致    谢”，两个汉字之间为 4 个普通空格；尾随手动换行不算标题文字。
- Word 手动换行可以提供空行证据；一个换行只换行，连续两个换行才表示中间有一条空行。
- 正文至附录的页眉格式是硬规则；目录条目的字体、字号、行距、缩进和数字页码是硬规则。页码只核验数字字段，不推断最终页码是否与 Word 排版对应。
- 目录口径按用户确认的规范条款：一级条目首行缩进 2 字符，章号后空 1 个普通半角空格；二、三级编号后空 1 个普通半角空格，TOC2/3 原缩进值保持不变。样例 XML 的 TOC1 样式未声明缩进，按用户确认以条款文字为准。
- 插图规则只硬查规范写明的图题居中，不把图片对象本身居中作为硬要求。
- 对附录单独起页、最终分页关系等无法由静态 XML 证明的事项，输出待确认，不据此判错。

### Source of Truth 与范围

- 规则文字以用户提供的学校格式规范为准，DOCX 样例的 OOXML 用于确定格式属性、样式继承和文档结构。
- 规范文字与样例 XML 局部值冲突时，以明确规则文字和用户已确认口径为准，例如四边页边距均为 2.6 cm。
- 本轮范围覆盖章节、摘要、目录、致谢/参考文献、附录、页眉、图题和对应规则目录/报告登记；不修改论文文件或历史测试产物。

### 模块边界与数据流

- `Docx4jDocumentParser` 将 `w:br` / `w:cr` 转成段落文本中的换行符；共享空行语义由规则层的手动换行支持代码计算。
- 各语义规则模块分别消费同一段落证据；`RuleCatalog` 保持规则 ID 与中文报告文案的登记源。
- 页眉解析证据进入页眉规则模块；目录条目继续由目录模块检查；视觉分页无法证实时交给覆盖报告标为待确认。

### 验证

- 先运行目录、页眉、图题、章节/摘要/文末/附录空行的定向回归测试。
- 再运行 `rtk mvn -q -f backend/pom.xml test` 与 `rtk git diff --check`。
- 已确认的口径：英文关键词只要求 `Keywords` 标签加粗；页眉覆盖封面至附录；允许手动换行；“结论与展望”只有存在标题样式、标题级别或自动编号证据时才按一级标题处理；附录分标题只检查字母编号，不额外套用一级标题格式。表格内文字不作为正文引用证据，行内公式是否需要编号仍按可识别的独立公式对象和规范编号证据处理。

### 本轮回归修复

- 目录中缺页码且字体或字号错误的手工条目，不再被误当成正文标题；只有后文存在同名且带标题证据的正文段落时，才将其保留在目录区域并继续检查字体、字号、缩进和页码。
- 标题遍历模块与目录模块使用同一目录条目状态；异常目录条目不会再额外生成二级标题格式批注。
- 目录条目缺页码时，普通的“编号后一个空格”不再被误报为非数字页码；只有明确的省略号、制表符或额外分隔空白后接非数字内容时，才报告页码格式错误。
- 封面字段检查排除封面前表格中的段落，表格内日期不会被当作独立封面日期。
- 附录必需检查区分独立“附    录”总标题和“附录A”等字母分项；已有分项但缺少总标题时报告 `APPENDIX_TITLE_MISSING`，并给出补充总标题及空行的建议。
- 表格说明行识别支持“测试用例编号：… | 模块名称：…”等逐单元格标签行，不再把这类说明行当作表头；普通“模块名称”表头仍按表头处理。
- 页眉新增有效 DOCX 无显式分节和页眉引用的端到端回归；报告规则目录补齐英文目录标题和封面字段标签的中文名称与修改建议。
- 全量 `rtk mvn -q -f backend/pom.xml test` 通过（973 项，失败/错误/跳过均为 0）；目录、必需章节、页眉解析器、封面表格边界、表格说明行和报告映射均有定向回归覆盖。
