# 迭代 1.1 功能补全方案

## 目标与边界

补齐需求文档《王润东-迭代1.1》与 2026-11-16 审计确认的缺口：管理员概览图表、年级筛选、Excel 的学校/学院/专业列、完整的同院教师候选，以及教师统计的筛选、榜单、分布、趋势、热力图、学生明细和 Excel 导出。验收以真实账号、提交和审核结果为准，覆盖权限、历史数据、空数据、导入错误与窄屏。

用户后续决策优先：不恢复学生端论文规则页，不引入班级，不强制学生首次改密；本轮不部署生产。学校仍固定为山东石油化工学院，三个学院仍使用现有受控目录。

## Source of Truth 与数据流

- PostgreSQL 的 sys_user 是账号、学院、专业、导师归属和新增入学年级的权威来源。年级为可空的四位整数，老学生保持未知；新建学生与导入学生填写年级，不能从学号推断。仅 STUDENT 有年级，TEACHER 的专业可作可选资料，ADMIN 无专业/年级。
- 管理员 Excel 必须包含学校、学院、专业列；学生还包含年级和指导教师工号，教师的专业可空。教师自导学生模板也包含学校、学院、专业、年级，导师仍由当前登录教师决定。固定学校与学院作用域由服务端逐行核对，Excel 内容不能提升权限。校级管理员可导入多个学院，学院管理员/教师只能导入本院。
- PostgreSQL 的 submission 是提交、审核状态、问题总数的权威来源。审核引擎的 report.json 是规则明细来源；成功审核时把 FAIL 项按 ruleId 与中文说明聚合并写入 submission_rule_issue，同时记录该份成功审核是否已建立规则索引。历史成功审核用有界、可重试、幂等任务从 COS report.json 补录。统计读取数据库，不在请求链路逐份读取 COS。
- 未索引的历史审核不是零问题。统计响应返回符合条件的成功审核数与已索引数，页面明确提示覆盖率；无法取回报告的审核保留未覆盖状态。
- 浏览器经既有同源 API 取得汇总和分页明细；图表只读真实聚合，无 mock 或前端根据分页列表拼接全局统计。

## 模块与接口

1. 账号与导入：Flyway 增加 sys_user.grade；UserView、创建/编辑、管理员列表筛选、教师建号与 Excel 贯通。入学年份允许 2000–2100，历史空值可查。管理员列表仅学生角色接受 grade 过滤。导师候选改为服务端搜索加分页，前端支持翻页，不再静默截断 100 名。
2. 管理员概览：保留现有三项数字，再返回近 30 天每日提交量、审核状态分布及学院人数。校级管理员按全部授权学院统计，学院管理员仅本院；空数据展示零值与空图说明。
3. 教师统计：保留原十项汇总的默认口径，新增按年级与最近 30/90/365 天或全部时间筛选的洞察接口。问题数分布、规则榜单和热力图采用筛选范围内每名学生最近一次成功审核；提交趋势采用范围内全部提交。学生明细服务端分页，Excel 导出沿用相同筛选与权限。榜单只含 FAIL，规则以 ruleId 合并，显示报告里的中文规则说明。
4. 权限与响应：所有教师统计每次由当前教师 ID 和 sys_user.teacher_id 限定；所有管理员导入与图表均复用 AdminScope。保持现有 data/error/requestId、字符串 ID、UTC 存储和 Asia/Shanghai 日期展示。无效年级、范围、分页及越权仍返回现有中文错误语义。
5. 前端：复用现有 React、Ant Design、React Query、路由与下载工具；图表采用有标签的图形组件。筛选写入 queryKey，用户切换学院/角色时清缓存。榜单、分布、趋势、热力图、明细和导出均明确显示统计口径、空态与覆盖率。

并行实现的接口契约固定如下，代码可增加字段但不能把未知转换成零：

- UserView、学生创建/编辑请求和学生名单增加 grade:number|null；新建/导入的学生必须给出 2000–2100 的年份，既有学生可保持 null。管理员账号列表增加 grade 可选过滤，教师候选接口接受 page、size、q 并返回现有 PageResponse<UserView>。
- 管理员 dashboard 保留现有字段，追加 dailySubmissions:[{date,count}]、statusDistribution:[{status,count}]、studentsByCollege:[{collegeCode,collegeName,count}]。图表默认近 30 天，人数按当前启用账号统计，提交日期采用 Asia/Shanghai。
- 教师原 statistics 十项字段保持；增加可选 grade。新增 statistics/insights 接受 grade、range=30|90|365|ALL、page、size，返回 coverage:{eligibleReviews,indexedReviews}、topRules:[{ruleId,description,count}]、problemDistribution:[{label,students}]、dailySubmissions:[{date,count}]、heatmap:{rules:[{ruleId,description}],students:[{studentId,name,counts:{ruleId:number}}]}、students:PageResponse<{id,username,name,grade,major,lastSubmittedAt,latestProblemCount,latestReviewStatus}>。默认 range=30，问题分布和规则明细只按范围内每名学生最新 SUCCESS 计算，日期趋势按全部提交计算。
- 教师 statistics/export 使用同一 grade、range 过滤，下载 xlsx；导出明细包含学号、姓名、年级、专业、最近提交时间、最近成功审核问题数和当前审核状态。没有成功审核时问题数为空，不写成 0。

## 失败模式、迁移与回滚

- Flyway 只增可空年级和规则索引表/状态，不猜测旧账号年级，也不覆盖旧审核总问题数。新审核的规则索引与 SUCCESS 状态同一事务提交；任何解析/写入失败都不能把缺失明细记成零。
- 历史补录按固定批量读取 COS；临时网络或 COS 故障按有上限退避继续重试，只有确认报告永久不存在或内容无效才记为不可补录。单条失败不阻塞审核或统计请求，页面展示覆盖数。部署回滚应用版本时保留新增列与数据，不做破坏性回滚。
- 导入逐行校验学校、学院、专业、年级；预检不写库，执行重读文件和数据库。文件内跨院行、未知专业、非法年份单行报错，不改变其他有效行。教师模板不接受 Excel 伪造导师归属。
- 导出使用服务端有界分页或流式工作簿，权限与页面筛选一致；过大请求给可见错误，不能静默截断。响应失败时保留页面现有数据及重试入口。

## 验证

- 真实 PostgreSQL 集成测试覆盖 V5/V6 迁移、年级读写筛选、学院越权、两种 Excel 预检/执行、超过 100 名教师候选、SUCCESS 与规则索引原子性、历史缺失与零问题区别、教师隔离、筛选和 Excel 导出。
- 前端 typecheck、build、Playwright 覆盖管理员和教师主流程、空态、导入错误、筛选、图表数据、导出、375px 与桌面视口及键盘路径；前端假 API 仅用于边界测试，不冒充真实联调。
- 本地 Docker/PostgreSQL 不可用时如实记录集成测试未验证；不把历史成功测试当成本轮结果。完成后在本方案中记录实际命令、结果与残余限制。
