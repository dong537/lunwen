# 学院账号与师生端功能方案

## 目标、用户与范围

校级管理员管理全校账号及学院管理员；学院管理员仅管理自己学院的师生和专业。教师按本人指导名单新增/导入学生并查看真实统计。学生沿用论文上传、审核状态、批注稿和报告查看流程；按用户最新要求，不提供论文规则菜单或独立规则页面。保留现有 React、Ant Design、Spring Boot、PostgreSQL 和两套审核服务。当前不做班级/年级分组、截图中尚无数据源的趋势/热力图、部署或多学校规则配置。

成功标准：任何跨学院教师 ID 或账号 ID 都不能绕过服务端检查；历史论文不会因“删除”消失；教师导入和统计沿用已实现接口；新页面能从入口到结果完成真实数据流程。

## Source of Truth 与迁移

- 学校显示名固定为“山东石油化工学院”，从后端受控目录返回；学校字段在表单中只读。
- 学院使用受控代码与名称：信息科学与工程学院、教育与艺术学院、经济管理学院。`sys_user.college_code` 为学院归属；`ADMIN` 且归属为空是校级管理员，有归属是学院管理员。授权每次从数据库读取当前账号，不信任前端/会话里的学院值。
- Flyway 新迁移加入可空学院字段和有效代码约束。既有账号学院为空代表“待归属”，仅校级管理员可见和补录；不从旧专业或指导教师推断学院。新师生必须有学院，教师自行导入的学生继承教师学院；无学院的旧教师先由校级管理员补录。
- `major_catalog` 以 `(college_code, name)` 唯一，记录启用状态，管理员按学院新增/停用专业。现有用户的 `major` 文本保留为历史快照；新建或变更专业须匹配本学院启用目录，未修改的旧值不会被强行清空。
- `sys_user.teacher_id` 仍是教师指导名单的唯一归属来源；论文与审核记录仍在现有提交表/COS。教师统计只用真实数据库聚合，不读论文文件。
- `sys_user.must_change_password` 是强制改密的权威状态。新建/导入/管理员重置学生时写 `false`，V4 迁移将既有学生改为 `false`，不改密码哈希；教师和管理员沿用账号创建及重置后的强制改密，环境引导创建的校管沿用原行为。学生自愿改密仍可用。

## 后端接口与权限

- 账号响应增加 `collegeCode`、`collegeName`；校级管理员可用现有账号创建接口创建指定学院的学院管理员，不能从客户端创建新的校级管理员。学院管理员只能创建/维护本学院师生，无法查看或修改其他学院账号；校级管理员可查看“待归属”旧账号。
- `GET /api/admin/catalog` 返回学校和三学院；`GET /api/admin/majors?collegeCode=...` 返回指定学院专业；`POST /api/admin/majors` 新增，`PATCH /api/admin/majors/{id}/active` 停用/启用。学院管理员请求其他学院返回 403。专业名称创建后不改名，避免已有用户的文本快照漂移。
- 现有 `GET /api/admin/users`、`GET /api/admin/teachers`、创建/编辑账号、管理员 Excel 预检/执行与 `/api/admin/dashboard` 全部使用同一数据库学院范围。校级管理员可按学院筛选；学院管理员固定自己学院。教师下拉必须明确学生选定学院；后端只返回同学院启用教师。提交伪造的跨学院 `teacherId` 返回 400/403。
- `DELETE /api/admin/users/{id}` 对没有受保护入向引用的账号物理删除；教师仍被学生引用，或学生已有论文提交时，原子地停用并返回 `outcome=DEACTIVATED`。学生仅关联指导教师、但没有论文提交时可以删除，不影响教师。返回真实结果，界面不得把停用说成已删除。避免删除自己及校级管理员账号。事务锁定目标账号，保留外键约束作为最后防线；论文上传在创建提交记录的短事务内重新读取并锁定学生，防止停用或删除期间的旧请求继续创建记录，文件传输保持在事务外。
- 教师 `/api/teacher/students` 新增、模板、预检/执行与 `/api/teacher/statistics` 沿用先前已验证接口；教师新增/导入学生时从当前教师继承学院，专业按学院目录验证。统计返回既有十项汇总，最新问题数只取每名学生最近成功的审核记录。
- JSON 保持 `{data,error,requestId}` 包装、字符串 ID、UTC 时间、现有会话和 CSRF。401/403/409 含明确中文恢复说明，列表保留分页搜索。

## 前端任务路径

- 管理员账号页：列表先看角色/学院/状态与待归属；新建/编辑时先显示只读学校，再选学院，学生才选专业和同学院教师。学院变化清空专业和教师。校级管理员可管理学院管理员与专业目录；学院管理员只见本学院选项。删除前说明无关联会永久删除、有关联会停用，结果消息以服务端 `outcome` 为准。
- 教师“我的学生”：列表保留搜索、详情与提交历史；增加“新增学生”和“导入名单”。新建显示学校/学院只读、专业可选；导入复用现有模板下载、预检、执行及逐行错误展示。统计另设菜单页，展示人数、状态和最近成功问题汇总，不绘制无真实数据源的榜单/趋势/热力图。
- 学生端沿用“我的论文”和个人信息入口；撤销独立论文规则菜单、路由和规则文案模块。学生登录后不显示强制改密弹窗，仍保留自愿改密入口；审核引擎的学校规范和批注逻辑不因隐藏前端展示而改变。
- 所有页面使用既有 Ant Design 主题、菜单、`PageHeader`、`ApiAlert`、React Query 和中文反馈；操作入口与结果反馈同名。手机、键盘、长姓名/长专业、加载/空态/失败/重试/403、首次改密和账号切换均须可用。

## 失败、回滚与验收

- 迁移先建立允许空值的学院归属和专业目录，再上线新 API；现有账号需人工补录，不能凭空猜学院。V4 只清除学生强制改密标志，密码哈希不变；统一初始密码不强制修改将增加冒用风险，上线前应设计独立密码及安全发放。无学院教师新增/导入返回可操作的提示。停用或删除后服务端重新读取权限，旧会话不可继续操作。
- 后端以真实 PostgreSQL 测校级/学院级隔离、跨学院 ID、导入及并发、删除无关联/有关联、旧账号待归属、专业启停。前端运行 typecheck、format、build、Playwright；联调走登录→管理→新增/导入→统计→学生论文页，并验证规则入口消失、旧地址不可访问及错误恢复。
- 本次仅保留新分支；不改现有生产配置或部署。回滚应用版本不应删除已产生的历史账号和论文；数据库迁移通过前向修正。
