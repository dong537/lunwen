# 三级标题行距漏检修复

## 目标与范围

- 修复用户反馈的行距错误没有写入 Word 批注的问题，从原稿重测并回读批注。
- 权威证据：学校规范的 Heading3 样例为 1.5 倍行距；用户已要求补齐三级标题检查。段落实际值按 DOCX 直接格式、样式继承和默认属性解析。
- 只修三级标题行距规则、相应回归测试和说明。不变更其他区域要求，不修改原稿格式，不用容差或单篇文件名特判。

## 已复现根因

雷家琪原稿中 36 个三级标题继承自定义样式的 `288 / auto`（1.2 倍），覆盖基础 Heading3 的 `360 / auto`。旧解析器能够读取该值，但 HeadingRuleChecker 仅在 `level == 2` 时检查行距，三级标题未产生任何行距结果。旧测试和规则矩阵还明确排除了三级标题行距，造成测试全绿但真实漏检。

## 验证计划

1. 改正锁定旧错误行为的断言，增加真实 DOCX 样式继承 → 规则 → 批注写入 → XML 回读的回归测试，先验证失败。
2. 将三级标题接入共用的精确行距检查；正确的 1.5 倍必须通过，单倍、1.2 倍和同数值固定值不得通过。
3. 定向测试和全量 Maven 测试；从无旧批注原稿生成新目录并检查 36 个位置的实际 Word 批注。
4. 保留封面页眉豁免、目录一级章号后两格及旧批注锚点修复，核对正文、图片和分节未被改写。

## 同链路正文漏检

审计另复现了正文句以“图3-1所示……”或“表3-1列出……”开头时，被正文模块的题注前缀正则跳过。排除题注改为复用解析器的图/表题注位置（部件与段落路径），并保留明确 Caption/题注样式证据；不能仅凭句首有图表编号就免查正文行距。真实雷家琪原稿中的实际图表题均有解析器位置绑定。

批注链路对行距 FAIL 没有数量限制或特殊过滤；段落级行距错误只写段落批注，不给整段文字额外染色。通用的“同段另一个锚点非法可能导致整组拒绝”是额外风险，本次原稿未发现该触发，不以此解释本次漏检。
