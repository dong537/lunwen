# 迭代 1.1 功能补全实施计划

目标：完成需求文档中尚缺的账号年级、Excel 列、导师候选和真实数据统计可视化。架构与准确口径见同目录的《2026-11-16-迭代1.1功能补全方案》。技术栈沿用 Spring Boot、JPA、Flyway、PostgreSQL、React、Ant Design、React Query 和 Playwright。

## 任务 A：账号、导入和导师候选

负责 platform-backend 的 account、importing 包、V5 迁移及其集成测试；不得修改 teacher、submission 包或前端。先添加失败测试，再实现和复测。

1. V5 增加 sys_user.grade（可空、2000–2100 检查），把 grade 加到 UserView、学生创建/编辑、教师建号和管理员/教师学生列表。旧账号保留 null，新账号与新导入必须填写年级；教师可记录可选专业，管理员不可记录。
2. 管理员用户列表增加学生年级筛选；同院教师候选改服务端搜索分页，接口返回 PageResponse，并验证第 101 名可被找到。
3. 管理员和教师自导模板包含学校、学院、专业及学生年级。学校必须等于受控常量，学院必须存在且符合操作者权限；专业按该学院目录校验。预检零写入、执行逐行写入及错误顺序沿用既有逻辑。
4. 测试年级边界、未知历史值、越权 Excel 行、混合学院校管导入、教师候选分页、并发与已有导入回归。

## 任务 B：审核规则索引与统计接口

负责 platform-backend 的 teacher、submission、engine 接口适配、V6 迁移及对应测试；不得修改 account/importing 或前端。依赖任务 A 的 User.getGrade 与列表过滤，必要时先用稳定接口编译后联调。

1. 从审核 report.results 的 FAIL 项提取 ruleId 和中文说明，在 SUCCESS 事务中持久化规则计数与索引覆盖标记；保留零问题与未知明细的区别。V6 新建索引表/状态，增加有界、幂等的历史 COS report.json 补录，不在页面请求里逐份读取 COS。
2. 管理员 dashboard 增加每日提交、审核状态和学院人数聚合。教师统计增加年级筛选；新增 insights 的范围、榜单、问题分布、提交趋势、热力图和分页学生明细，并提供同筛选 Excel 导出。
3. 测试真实 PostgreSQL 的权限隔离、同日/同时刻排序、历史未索引、空/零、过滤口径、导出内容及错误传播。

## 任务 C：前端交付与浏览器验证

负责 frontend/src、frontend/e2e 和前端依赖；不得修改后端。接口以方案文档为准，与任务 A/B 的最终响应类型同步。

1. 账号列表加年级筛选，学生表单/教师新增加年级输入，教师下拉改服务端分页搜索；导入说明与模板列、错误显示保持一致。
2. 概览加真实趋势、状态、学院图表；教师统计加年级/时间范围筛选、规则榜单、问题分布、趋势、热力图、学生明细和导出。沿用用户提供的统计截图的信息层级，去掉班级，保留当前设计系统与角色路由。
3. 页面显示覆盖率与历史未索引说明，空态/权限错误/加载/导出失败均可见；运行 typecheck、format、build、Playwright，检查窄屏、键盘和控制台错误。
