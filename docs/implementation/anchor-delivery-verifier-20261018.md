脚本：`artifacts/verify_anchor_delivery_20261018.py`。由旧版独立交付校验脚本改编，未修改 `verify_16_delivery_20261018.py`。只读论文、原稿和服务存储中的转换稿，只在新输出目录增加 `锚点交付独立核验.json`。

## 调用

```powershell
python artifacts/verify_anchor_delivery_20261018.py 'C:/Users/Lenovo/Desktop/luwneshacha/16篇论文-批注定位修复重检-20261018-185119' --storage 'C:/Users/Lenovo/AppData/Local/Temp/thesis-line-18098-20261018'
```

第一个位置参数必须显式提供新目录。第二个位置参数可覆盖旧目录，默认 `16篇论文-行距修复全量重检-20261018-174614`。`--storage` 可覆盖新目录 `本次运行信息.json` 的 `storage`；有公式转换时必须提供可核对实际检测稿的存储位置，不能拿未经转换原稿冒充检测稿。

运行前要求新旧目录都已有完整 16 篇成功记录、每篇批注版和报告各一份以及 JSON 证据。文件不完整时提前失败，不生成部分通过的交付结论。禁止用 Python `-O` 绕过断言。

## 核对内容

- 原稿 SHA-256、准备副本 SHA-256、实际检测稿 SHA-256；核对新旧批次同篇原稿相同、16 个新请求 ID 唯一且不复用旧请求。
- 复用已有纯本地内容核验，重做全文、段落、文字直接格式、图片、嵌入对象、数学结构核对。不会调用 API。
- 在准备或转换后的检测稿与批注稿之间，逐段比较 `w:br`、`w:cr`、`w:tab`、`w:lastRenderedPageBreak` 的顺序、属性、文字位置与对象位置；比较完整段落属性、分节属性与文档设置。
- 全包批注 ID 唯一、起点/终点/引用逐一配对、同一部件且顺序正确；现代批注的 paraId、durableId、父线程链、作者人员表、关系及内容类型一致。
- 报告每条错误与批注记录覆盖一致，页首和原空白位置使用新的中文状态；按规则汇总数量与实际状态一致。
- 每个点批注的 `anchorSource` 必须解析到检测稿与批注稿中同一段落，文字及段落属性不变，并有唯一带定位说明的配对批注。
- 已核对的六处锚点采用明确预期：06 原位置 `[0,93]`，08 摘要 `[0,2]`，09 摘要 `[0,18]`，11 致谢 `[0,533]`，16 致谢 `[0,524]` 与独立空末节 `[0,533]`。
- 若页首段落原有同一 run 内的分页符或分页缓存，验证批注位于分页元素之后、首段文字之前；只看段落位置不算通过。
- 逐项追踪旧 64 项未写入问题，匹配键为篇号、ruleId、partName、elementPath，忽略公式更正的字符偏移但在核验文件保留前后偏移。预期 56 项数学问题写入、6 项空位置问题写入、08 篇图片封面 2 项页眉误报从结果中消失。数量或状态不同均详细列出并失败，不按总数凑平。
