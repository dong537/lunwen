# 批注范围与空位置修复

## 目标和边界

用户要求修复最新 16 篇结果中 64 条未写入的批注：数学论文 15 个公式的 56 条范围越界，以及页眉、页码和摘要空行的 8 条空位置。继续完成已经在做的目录不检查首行缩进修复。保留检测规则的真实结论，不通过删除问题、截断错误范围或插入可见占位文字伪造成功。

## 权威数据与模块

- 原始论文来源使用既有批量清单的 Source 和 SHA256；旧批注结果只作为复现证据。
- EquationParser 负责准确提供公式所在元素和文字坐标；CommentWriter 负责范围落点、段落合并、批注和高亮，不混淆数学内容与普通文字坐标。
- 空位置批注定位独立在 reporting 模块内处理。原始检测位置必须保留用于报告匹配，实际批注位置另外记录。
- 页首定位依据显式分页、已保存的分页标记、分节及页眉引用关系；不把全文第一段或任意相邻段落冒充当前页页首。不能确定页首时保留原位置的点批注，并明确说明定位方式。
- 前端与规则判定不变；不进行云端部署。

## 验证与交付

先建立失败回归，再修复生产路径。验证公式结构、段落、格式、图片与嵌入内容保持，批注起止和引用 ID 成对，重新读取能找到批注。统一运行定向及全量 Maven 测试，再用受影响原稿通过实际 API 复检；保存新 Word 和报告到新目录，不覆盖原稿或历史交付目录。原始失败项必须逐条核对写入结果，不能仅看总数变化。

并行分工：anchor_review 负责公式解析坐标；header_scope_audit 负责空位置的只读 XML 证据；主 Agent 负责目录收尾、空位置写入、集成与验证。

## 实现与回归结果

- EquationParser 改为使用原始可见文本坐标；不再用增加了阅读空格的公式摘要长度充当批注范围。37 个真实公式坐标核验无越界。
- HeaderRuleModule 保留页眉源证据，并通过 CheckResult.contextSource 提供封面豁免后的适用分节；空末节不借用上一节内容。
- PageStartAnchorResolver 根据分节、样式继承及分页证据选择点位；不能确定页首时保留真正的原空白位置。AnnotationItem.anchorSource 单独保存实际写入点，原 source 保持用于报告映射。
- 独立复审复现并修复了同段普通批注与页首批注冲突：先写普通文字批注，再从活动段落重新找到分页边界，避免缓存的旧运行导致重复文字、丢失高亮或把文字批注变成段尾点。点位也精确计入分页符之前的制表符与手动换行。
- 定向测试 677 项全部通过；全量 Maven package 1219 项全部通过，0 跳过。对应日志：logs/anchor-toc-targeted-green.log、logs/anchor-toc-full-package.log。
