## 08：两项封面页眉误报的直接证据

- 原稿：`论文2206181106_王雨诺_基于RAG技术的智能交互系统的设计与实现 - 副本.docx`。
- 第一节仅有 body 0 的图片段落和 body 1 的空分节段落；二者没有 w:t 文字。第一节独立引用 header1，第二节已改为 header2。
- body 2 是可识别的“摘    要”；首节和摘要之间没有其他文本区域。
- 从 body 0 的 drawing 关系提取原始图片，文件：`artifacts/20261018-audit-paper08-cover.jpeg`。图像已实际查看，含学校名称、本科生毕业设计（论文）、题目、姓名、学号、院系、专业、教师和日期，是完整封面。
- 因用户明确“封面不需要页眉”，header1 的 `HEADER-01-TEXT` 和 `HEADER-01-ALIGNMENT` 应不适用。把它们移到摘要批注会改变错误的所属页面，并制造新的误报。
- 现有 `CoverHeaderScope` 只凭文本识别封面，图片封面没有文字，因此被当作需要页眉的普通首节。这是识别边界遗漏，与批注是否可写入无关。

修复约束：仅识别位于文档起始、具有独立首节、只有单个无图题图片且无其他正文/表格/公式、紧接可识别摘要的结构。没有独立分节证据、后面是目录或正文、带图题、出现多个图片、位于文中或隔着另一分节的图页不享受此豁免。图片封面与摘要共用的页眉仍在摘要部分检查。不得按文件名、学号、图片内容哈希豁免，也不得调整页眉规则来追求零未写入。

## 精确分页与样式证据

### 06 连续空节

`[0,93,0,3]` 为该空段的 sectPr；含 `w:type w:val=continuous`、footer2 引用和 `w:pgNumType w:start=1`。段落样式 2 -> 1 均没有 pageBreakBefore。92、93、94 没有显式分页或 lastRenderedPageBreak；整篇也没有 lastRenderedPageBreak。`[0,94]` 文字为“第一章  绪论”，属下一正文节。footer1 没有 PAGE 域，footer2 有完整 begin/instrText(PAGE)/separate/缓存结果/end 域。

这些证据能够说明分节配置，不能唯一说明空连续节实际落在哪一页。尤其应重新审视 PAGE_NUMBER_IN_FRONT_MATTER 是否把紧贴正文开始的空连续节错误地划为前置部分；本次锚点迁移不应替规则模块下新的版面结论。

### 09 摘要新页

`[0,18]` 段落使用样式 2；样式 2 的 pPr 包含 `<w:pageBreakBefore/>`，且本段未直接关闭该属性。`[0,18,1,1]` 是文字“摘要”。上一段 `[0,17]` 是封面日期占位“年   月   日”。因此空 default 页眉的首个非封面批注候选可稳定落到摘要标题。

### 11 致谢

`[0,533,11,0]` 为 lastRenderedPageBreak；紧接 `[0,533,11,1]` 的“致”，后续两 run 为 4 个普通空格和“谢”。记录位于文字之前，不是标题文字中间或末尾。该记录是最近一次排版缓存，不能冒充本次 Word 重新排版的实时结果。

### 16 致谢与空末节

`[0,524,9,0]` 为 lastRenderedPageBreak，紧接 `[0,524,9,1]` 的“致”。532 的段落分节配置仍引用 header6；最终 534 的 sectPr 明确引用新的 header7。最后一节不能继承使用上一节致谢文字作为“当前页开头”。
