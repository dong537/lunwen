# 缺省行距漏检修复

## 目标与边界

- 对校园便利店论文的英文摘要、正文行距和首行缩进漏检查明共性根因，通过当前构建重新检测并交付新的批注文件。
- 学校规则仍为 1.5 倍段落行距、首行缩进 2 字符，不增加容差，不针对文件名修改规则。
- 原件和正在打开的 Word 文件只读；重测结果使用新目录。文档网格不等同于段落倍数行距；本次不增加最终页面版面判断。

## 数据与 Module 边界

- DOCX 原始 XML、段落样式继承链和文档默认属性是格式证据来源。
- `Docx4jDocumentParser` 负责将继承链中完全缺省的段落行距解析为 OOXML 单倍默认值 `240/auto`。显式非法值仍保留错误标记。
- `ParagraphFormatChecker` 继续精确比较 `360/auto`；不把真正未知的模型值强行当作错误或正确。
- `AbstractRuleChecker` 与正文模块一致，排除文本框段落，避免提示文字改变摘要边界和空行状态。
- 当前源码已经将缺少首行缩进判错；旧批次的 REVIEW 需通过新构建重新验证，不能以旧报告替代复测。

## 验证

1. 真实 DOCX XML 回归：无行距值、无继承行距且存在 312 twips 文档网格时，段落行距设置为默认单倍，不能 REVIEW 或 PASS。
2. 保留继承优先级：段落、当前样式、basedOn 和 docDefaults 的明确值优先于标准默认值。
3. 摘要回归：文本框提示和伪标题不进入摘要规则，真正正文仍产生行距/缩进判定。
4. 定向测试、全量 Maven 测试、真实文件 API 重测、批注 XML 回读、`git diff --check`。

## 研究证据与工具限制

- Word 只读打开目标文档后，英文摘要正文是单倍行距（LineSpacingRule=0，LineSpacing=12），中文摘要为 1.5 倍（1，18）。正文多个缺少 spacing 的段落也是单倍。
- 目标文档样式 Normal 无 spacing，docDefaults/pPrDefault 缺失；`docGrid type=lines,linePitch=312` 不能作为 1.5 倍证据。
- fast-context 调用失败：Windsurf API Key not found。已切换精确 rg 搜索和调用链阅读，本任务不重复调用失败路径。
- 定向测试 RED 的首次 fixture 误含 docx4j 自动生成的 276/auto 样式值；修正 fixture 为实际文档的无行距 Normal 样式后重新验证 RED。

## 结果

验证已完成（2026-10-18）：

- `rtk mvn -f backend/pom.xml -Dtest=ParagraphFormatCheckerTest test`：23 项通过。
- `rtk mvn -f backend/pom.xml test`：1115 项通过，0 失败。
- 以校园便利店论文原始 DOCX 在隔离端口 18102 实测：英文摘要 1 段、正文 31 段为 `240/auto` 单倍行距；均按规则标记为错误并成功写入批注。另有 1 段正文未设置首行缩进。
- 批注文档含 60 条批注，60 组起止锚点和引用均可从 OOXML 回读；正文文本与原件一致。
- 输出目录：`批注复测-行距首行缩进规则修复-20261018-1450`。
- 表格单元格和文本框段落仍不参与正文行距硬检查；本次依据明文规则没有把表格、形状文字直接套用正文行距要求。
