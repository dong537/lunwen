# 平台化前端审计与模块方案

日期：2026-10-18。范围：只读审计现有前端、现有 API 调用链，以及用户提供的《需求文档(1).md》v1.0、《数据库设计(1).md》v1.1；本次仅新增本文档，不修改前端、依赖或部署配置。

结论：现有 React、TypeScript、Vite 可以保留；需把一次检测工具改为有登录会话、权限边界、提交记录与后台处理状态的平台。不能在当前 `App` 中继续累加角色分支。推荐按业务能力拆成会话、提交、教师学生名单、用户管理、Excel 导入五个模块，学生与教师共用提交详情。

## 1. 已核实的现状

| 项目 | 现状与证据 | 对平台化的影响 |
| --- | --- | --- |
| 技术栈 | `frontend/package.json` 使用 React、React DOM、TypeScript、Vite、React 插件、lucide-react；已有原生 CSS | 保留，不迁移到 Vue，不另建一套前端 |
| 实际版本 | 锁文件版本3：React/React DOM 19.3.0、Vite 8.3.3、TypeScript 7.0.2、React 插件6.1.2、lucide-react 1.52.0 | `package.json` 多处写 `latest`，发布依靠锁文件；扩展时应固定经验证版本并保留 `npm ci` |
| 代码结构 | `src/main.tsx` 共157行，包含 DTO、规则中文名、错误文案、全部状态、上传请求、下载、完整页面；另有一个 `styles.css` | 文件虽不长，但多条职责挤在同一组件；不适合作三角色平台的承载点 |
| 路由 | 没有 React Router、路由表或页面模块 | 无法支持登录、列表、详情、刷新恢复和角色工作台 |
| 会话 | 没有登录、退出、当前用户、角色、首次改密状态 | 目前不存在账号级访问边界；隐藏按钮不能代替后端授权 |
| 上传 | `main.tsx:87` 只在浏览器校验扩展名和16 MiB上限；没有空文件检查；拖入多个文件时静默只取第一个 | 新需求为非空、单个 DOCX、50 MB；应显式拒绝多文件并统一客户端与后端限制 |
| 请求 | `main.tsx:103` 同步 POST `/api/inspections`，携带 `file`、`annotate=true`；等待完整报告 | 不支持立即返回排队中，也没有状态轮询或提交历史 |
| 结果 | 浏览器 `useState` 保存整个引擎报告，前端从 `results` 计算通过/错误数并展示逐条问题 | 刷新即丢；与新需求“不展示逐条问题清单”冲突；统计应改由提交 DTO 提供 |
| 下载 | `main.tsx:126` 使用报告中的路径跳转；现有服务提供批注 Word 与检查报告 Word，没有原始 Word 下载 | 新平台主流程需要原始与 `.marked` Word；下载必须每次后端鉴权 |
| 状态 | 一个 `busy` 布尔值，没有 PENDING/PROCESSING/SUCCESS/FAILED | 不能区别上传中、任务排队、引擎处理中与终态失败 |
| 代理 | Vite同源 `/api` 代理到18098；Nginx SPA回退已存在 | 可复用同源部署和刷新路径回退 |
| 体积限制 | `frontend/nginx.conf:4` 为 `16m`；服务配置也为16777216字节 | 只把前端提示改50 MB仍会被网关或服务拒绝；Multipart整包限制需给文件之外的开销留空间 |
| 构建与测试 | scripts仅 `dev`、`build`（`tsc -b && vite build`）、`preview`；未找到前端 `.test`/`.spec`、Vitest、Playwright配置；没有对应 GitHub Actions 工作流 | 当前只有编译/打包入口，不能证明登录、权限、导入或轮询正确 |
| 样式与文案 | 原生CSS，有暗色样式与局部焦点规则；界面存在英文副标题、XML/twips/SHA-256等实现词，页脚写“不保存账户信息” | 新平台需中文业务文案；保留样式实现路径，按页面职责整理，而不是直接重做整套主题 |

请求现状：浏览器选择文件 → 同步 `POST /api/inspections` → `InspectionService.inspect` 转换、审核、批注、报告 → 完整引擎数据返浏览器 → 从临时下载路径取文件。服务端当前使用内存索引和本地临时文件；原始文件在 `finally` 删除、结果有保留时限。新平台的永久历史与原始文件下载不能从前端补齐。

另有现存展示缺陷：`visibleResults` 包含 FAIL 与 REVIEW，但分组均标成“格式错误”，顶部只计 FAIL，会出现分组数量与总数口径不一致。平台化后不要复制这套统计；统一显示后端已定义的 `problemCount`。

## 2. 本次建议的权威数据与状态归属

| 数据/状态 | 权威来源 | 前端责任 |
| --- | --- | --- |
| 身份、启用状态、角色、必须改密 | 后端当前会话与 `sys_user` | 会话初始化、路由引导、功能入口显示；不在本地保存“已改密”标志 |
| 可查看学生与提交、可下载文件 | 后端按当前身份查询和授权 | 处理403/404，禁止将本地角色判断当安全边界 |
| 提交状态、提交次数、统计、失败原因 | `submission` 与后台任务更新，由 API 形成 DTO | 显示与定时刷新；不从当前页行号推算“第 N 次” |
| 提交问题总数及模块统计 | 引擎输出经后端适配后的 `problemCount`、`byScope` | 不再接收全文检查结果计算数量；模块统计缺失就不展示，不补0冒充 |
| 搜索、页码、筛选、管理页签 | URL查询参数 | 返回列表时恢复状态；搜索或筛选变化后回到第一页 |
| 登录/改密/编辑表单内容 | 当前表单状态 | 字段提示与提交控制；成功后以服务端响应刷新缓存 |
| 文件、拖入状态、确认对话框 | 当前页面临时状态 | 禁止写入localStorage；切换账号、退出和离开导入流程时清理 |
| 导入校验与结果 | 后端处理上传的XLSX | 显示预检、确认与结果；浏览器不能提交自行判定“合法”的数据冒充后端校验 |

建议采用同源 HttpOnly Cookie 会话；如果后端选择其他认证机制，应先统一登录、刷新、退出与下载契约再实现。不要把登录密码、导入初始密码或长期凭据放在 localStorage。Cookie方案需要与后端同时落实跨站请求防护；前端统一HTTP模块携带凭据和约定的防护头。

## 3. 路由与界面组织

| 路由 | 访问角色 | 主任务与页面内容 |
| --- | --- | --- |
| `/login` | 未登录 | 账号密码登录；不出现注册入口 |
| `/change-password` | 所有已登录用户 | 首次改密和主动改密共用表单；强制改密时只提供改密与退出 |
| `/student/submissions` | 学生 | 我的提交，倒序分页；唯一主操作为上传论文 |
| `/student/submissions/new` | 学生 | 单文件选择、校验和上传；得到提交ID后进入详情，不停留等待审核结束 |
| `/student/submissions/:submissionId` | 学生本人 | 共用提交详情，状态、次数、时间、文件名、问题统计、允许的下载 |
| `/teacher/students` | 教师 | 名下学生，学号升序、搜索、分页、成功提交次数、最近提交与最新问题数 |
| `/teacher/students/:studentId` | 名下教师 | 学生基本信息和该生提交列表 |
| `/teacher/submissions/:submissionId` | 名下教师 | 同一提交详情组件的只读入口；不显示上传或教师批阅操作 |
| `/admin` | 管理员 | 启用学生数、启用教师数、累计提交数，以及管理入口 |
| `/admin/users?role=STUDENT` | 管理员 | 学生/教师两个页签、搜索、启用筛选、分页；新建/编辑/启用/禁用/重置密码 |
| `/admin/imports` | 管理员 | 选择学生或教师模板 → 上传预检 → 确认 → 结果与当次错误报告下载 |
| `/profile` | 所有已登录用户 | 当前身份的只读信息及改密入口；学生展示专业和指导教师 |
| `/forbidden`、未匹配路由 | 相应状态 | 无权限或页面不存在，提供回到本角色首页的出口 |

学生/教师复用 `SubmissionList` 与 `SubmissionDetailPage`，通过后端返回的能力控制下载；不复制两份结果渲染。管理员路由树不包含论文列表、论文详情或论文下载入口，后端同样拒绝管理员读取这些资源。

用户新建/编辑只有少量字段，可以在用户列表上用规范的 `dialog`，保留列表筛选上下文；Excel导入是多步骤独立页面，不放进大弹窗。教师搜索选择器必须支持键盘和清空，不自制只支持点击的浮层。

会话守卫顺序：初始化当前会话 → 未登录进入登录页 → 已登录但 `mustChangePassword=true` 进入改密页 → 角色不匹配进入无权限页 → 渲染业务页面。未知会话期间显示加载状态，不能短暂显示其他角色页面。登录后的返回地址只接受站内且本角色可访问路径；改密或退出后刷新会话和业务缓存。

## 4. 模块划分

```text
frontend/src/
  main.tsx                     只创建根节点和应用Provider
  app/
    App.tsx                    应用布局组合
    router.tsx                 路由、会话/角色/改密守卫
    providers.tsx              服务端状态与路由Provider
  shared/
    api/http.ts                基础URL、请求ID、错误解析、凭据、取消请求
    api/contracts.ts           统一错误、分页、ID、时间类型
    ui/                        Button、FormField、Dialog、Pagination等实际复用控件
    styles/                    保留原生CSS，集中颜色/字体/间距变量
  features/
    auth/                      会话查询、登录/退出/改密、登录页、个人信息
    submissions/               DTO、查询键、上传、状态轮询、列表、详情、下载
    students/                  教师名下名单、搜索、学生详情
    users/                     管理员列表、字段表单、启禁用、重置密码
    imports/                   模板、上传预检、确认执行、结果与错误报告
  pages/                       各路由的薄组合页面；不再放业务规则
```

每个feature只在真实存在的查询、表单、组件、页面出现时建文件，不预建空框架。路由、详情与表单只消费模块的公开DTO和操作。无需加通用manager/facade、Redux或第二套API客户端。

建议增加成熟的小范围依赖：React Router处理导航和深链；TanStack Query处理会话、列表缓存、轮询、失效与取消。现有fetch封装为唯一HTTP入口即可，不必同时引入Axios。普通表单可先用受控组件和原生表单约束；不能为少量字段再造表单框架。保留原生CSS技术栈；不要在本次平台化中并行引入Tailwind/另一套组件主题迁移。

## 5. 前后端应先冻结的接口契约

以下是前端需要的资源能力和建议路径，具体命名由主架构与后端统一确认后冻结，不是现有已实现接口。

| 能力 | 建议接口 | 必须具备的响应/语义 |
| --- | --- | --- |
| 会话 | `POST /api/auth/login`、`GET /api/auth/me`、`POST /api/auth/logout` | 用户ID、账号、姓名、角色、启用状态、必须改密；登录失败中文错误与机器可识别错误码 |
| 改密 | `POST /api/auth/change-password` | 旧密码、新密码；成功后获取新的会话状态；旧凭据不可继续绕过重置/禁用限制 |
| 上传 | `POST /api/submissions` | Multipart DOCX，校验通过后立即返回提交ID和PENDING；校验失败不产生记录 |
| 提交列表 | `GET /api/submissions` | 后端按当前用户约束范围；分页、稳定倒序；教师按获准studentId查看 |
| 提交详情 | `GET /api/submissions/:id` | 身份信息、序次、状态、时间、文件名、统计、失败原因、可下载能力；不得暴露COS内部key或密码字段 |
| 文件下载 | `GET /api/submissions/:id/files/original`、`.../marked` | 每次后端鉴权；原始文件名与 `.marked.docx` 命名由服务端Content-Disposition负责 |
| 教师学生 | `GET /api/teacher/students`、`GET /api/teacher/students/:id` | 仅名下学生；学号排序；成功提交次数及已定义口径的最近统计 |
| 管理概览 | `GET /api/admin/overview` | 三个需求规定的全局计数，不能通过下载全部用户/提交后前端统计 |
| 用户管理 | `/api/admin/users`及单用户操作 | 学生/教师白名单角色；账号/角色不可编辑；教师禁用返回名下学生数用于提示 |
| 教师选择 | `GET /api/admin/teachers?query=...` | 启用教师搜索和分页；修改学生时仍能识别已有但已禁用教师，不静默改成空值 |
| Excel | 模板下载、`POST /api/admin/imports/preview`、`POST /api/admin/imports/execute` | 上传文件并返回逐行结果；执行重新校验；不创建导入历史资源 |

统一约定：

- `bigint` ID在JSON中作为字符串，避免JavaScript数字精度丢失。账号始终是字符串，保留前导零。
- 分页统一为 `items/page/pageSize/total`（页码约定固定为从1开始）；搜索、筛选和排序值必须有服务端白名单。
- 时间使用带偏移的ISO 8601字符串；数据库UTC，界面按浏览器本地时区显示，日期格式统一。
- 保留有用的 `requestId`。错误统一为 `code/message/fieldErrors/requestId`，`message` 面向用户用中文。不能原样显示解析异常、存储路径和技术栈异常信息。
- 所有JSON成功响应使用统一envelope或统一裸DTO方案，选定一种；下载响应保留原始字节，不套JSON。
- 401清空会话并回登录；必须改密是单独错误码并引导改密；403显示权限状态，404显示不存在；上传413和文档格式失败提供可操作的中文说明。
- 不用前端拼接COS路径。若后端鉴权后跳转短期签名地址，签名不写本地持久存储，失效后重新经过授权入口申请。

## 6. 关键用户流程

### 登录与首次改密

新建、导入、重置密码后必须由 `mustChangePassword` 控制，不通过“密码是否等于123456”在浏览器推断。改密页显示旧密码、新密码、确认新密码；新密码6–128字符，不能与旧密码相同，确认值只用于前端一致性提示。后端仍校验所有安全约束。提交中禁用重复提交；成功后重新取会话，不能仅在前端将标志改为false。

### 上传与异步审核

选择文件时检查一份、非空、扩展名、大小，向后端上传；浏览器校验仅用于及时反馈。拿到提交ID后进入持久详情。页面只对PENDING/PROCESSING轮询，终态停止；后台标签页停止或降低频率，重新聚焦后刷新。请求失败显示“状态刷新失败，可重试”，不能把网络错误直接改成任务FAILED。离开页面取消请求，不取消服务端已接收任务。

SUCCESS且 `problemCount=0` 才显示“全部通过”。PENDING/PROCESSING/FAILED即使数据库默认问题数为0，也不能显示通过、0个问题或空模块图表。FAILED仅保留基本信息与中文原因，不展示统计和下载；重试是重新上传产生新提交，原失败记录保留。

审核中允许下载原始Word；成功允许下载原始与标注Word。下载按钮的可用性来自服务端详情能力字段，避免页面自己根据状态猜测存储文件是否存在。上传请求状态未知时不能自动重复POST；如果后端支持幂等键，需要对同一次用户操作使用同一键，以免网络重试产生两条记录。

### 教师只读查看

搜索、分页由后端完成。列表“提交次数”只计SUCCESS；详情中的“第N次提交”包含失败，两个概念不可复用一个计数。教师端共享学生提交详情组件，不出现批阅、打回、评语或上传按钮。教师在页面停留期间学生被重新分配，下一次详情/下载必须按最新归属授权。

### 管理账号

学生和教师分两个页签，管理员自身不进入列表。账号与角色创建后只读；编辑只提交允许的字段。启禁用和重置密码用明确的对象名称与结果确认，操作成功后失效相关列表/详情查询。教师名下有学生仍允许禁用，成功响应或操作预览给出真实学生数并显示要求的提示；不能把前端当前已加载行数当名下总数。

### Excel导入

独立页面保留四步：类型/模板、文件、预检、确认结果。文件不超过5 MB、最多2000行；文件读取和行校验在后端。预检结果包含总数、可导入、已存在跳过、失败及逐行原因。前端保留同一 `File`，确认时重新提交该文件和预检hash；后端再次校验、检查账号唯一性和教师启用状态，不能信任先前预检。在预检后管理员换文件，必须清空旧预检结果。

不在浏览器将表格转JSON后作为权威输入，不保存导入历史。结果只在当次页面内存中；成功、跳过、失败数分开展示。错误报告由本次响应或短期结果返回，浏览器可立即下载并及时释放Object URL。模板把账号列定义为文本，避免学号/工号前导零丢失。合法行部分成功；重复执行由数据库唯一约束和后端查重产生跳过，不能靠禁用按钮保证唯一性。

## 7. 需要统一口径的少量事项

1. 教师列表“最近提交时间/最新问题数”：文档只明确提交次数统计成功，但“最近/最新”未明确失败是否参与。推荐后端返回最新成功提交的时间和问题数；没有成功记录均显示“—”。若产品要显示最新尝试，应另给最新尝试状态，不把失败的0当问题数。
2. “50 MB/5 MB”是否按十进制还是二进制：与后端共同选定字节值并统一界面与网关。推荐延续原系统MiB实现，界面标成“50 MB”时在产品契约记录精确字节值。
3. 成功问题总数的范围：需求说取引擎问题条数，而引擎当前含PASS/FAIL/REVIEW。由后端引擎适配层定义哪些是问题并直接返回统计；不能把全部检查条数或批注条数当问题数。
4. 新需求只要求原始/标注Word，新平台不默认保留当前“下载Word检查报告”入口，也不提供逐条结果/数据文件下载。若要继续提供检查报告，需要明确新增需求；引擎内部生成能力可与平台入口分开。
5. 需求“全量保留文件”有明确失败例外：失败提交保留记录、不保留文件。前端遵守失败无下载；不要用旧下载链接继续暴露已失败文件。

## 8. 验证与迁移顺序

按依赖顺序执行：先冻结DTO与错误契约 → 会话/守卫/改密 → 管理建号和教师分配 → 学生上传与异步详情 → 教师名单/共享详情 → 用户管理完整操作 → Excel预检/执行 → Docker和真实主流程检查。新前端只调用平台API，审核引擎原始API留给内部调用；不让浏览器在两套权限与下载路径之间切换。

建议新增前端验证入口：独立 `typecheck`、Vitest+Testing Library、Playwright。编译通过不等于业务成功。测试优先覆盖以下可观察行为：

- 首次改密守卫、普通登录、退出清缓存、被重置后再次强制改密；学生/教师/管理员互访页面均正确显示。
- 空文件、多文件、错误扩展名、超过限制即时提示；真实后端拒绝同样输入且不产生提交记录。
- PENDING→PROCESSING→SUCCESS、SUCCESS零问题、FAILED中文原因，终态停止轮询；HTTP失败不伪装任务失败。
- 同一真实学生能下载两份正确Word；其他学生、非名下教师和管理员用直接URL都被后端拒绝。
- 用户编辑不修改账号/角色；禁用教师仍保留学生，显示真实人数；启用与重置后的后端状态正确。
- 一份真实100行XLSX导入；重复导入全部跳过；混合合法/错误行部分成功；预检后教师被禁用、文件被替换时重新校验。
- 列表搜索/分页URL可恢复，长中文姓名、超长文件名、不存在专业/导师、0条记录、请求错误能正确显示；桌面1280/1440视口及200%缩放、键盘访问、dialog焦点恢复和Esc操作。

组件测试可以隔离网络，但最终业务验收必须使用真实后端、PostgreSQL、存储与审核引擎；不得用Mock返回成功代替异步审核与权限验证。已有DOCX规则回归套件继续保留，平台化不能改变检测规则口径。
