## 与当前生成器的差异

当前入口是 [`WordReportWriter.java`](../../../backend/src/main/java/cn/luwneshacha/thesis/report/WordReportWriter.java)。它创建一份新 DOCX，并把问题表、无法确认项、规则覆盖、规则目录、批注写入情况和未检查区域依次追加到同一文档。

| 版式方面 | 当前代码表现 | 对照 PDF 的差异/影响 |
|---|---|---|
| 页面尺寸与边距 | 通过 `WordprocessingMLPackage.createPackage()` 创建空白包，没有在报告生成器中显式设置页面尺寸或页边距。 | PDF 明确是 A4 且内容区紧凑。当前输出依赖 docx4j 初始模板默认值，不能从生成器代码保证页面框或内容宽度与参照一致。 |
| 字体字号 | `paragraph()` 给所有报告段落及单元格设置宋体/Times New Roman、字号 22 半磅即 11 pt；加粗仅由布尔参数控制。 | PDF 有明显的 18/16/12/10/8 pt 多层级。当前标题、说明、表格单元格基本同一字号，缺少独立的标题、正文、辅助信息层级。 |
| 标题 | 所有标题是同一段落工厂产生的加粗段落；没有设置居中、颜色、底纹或标题前后间距。段落行距统一按 `line=280, AUTO`。 | PDF 的居中封面标题、浅底章节标题带、不同层级间距和对齐没有映射到当前 DOCX。 |
| 表格 | 错误与复核表格固定 8 列；表格总宽 9000 DXA，固定布局；覆盖/目录表也以 9000 DXA 固定宽度。单元格设置宽度和内边距，但生成器没有设置边框、底色、字体等级或文字对齐。表头行有重复表头属性。 | PDF 的蓝灰标题带、灰色细分隔线、数值列靠右和首列浅底编号格都未在当前表格样式中定义。超长文本可能在固定窄列中导致多页或不均匀换行。 |
| 颜色/标识/水印 | 当前生成逻辑未添加颜色、品牌图标、图表、二维码或水印。 | 参照 PDF 的品牌化特征未实现。它们属于视觉参考，并非论文检测结果本身的必要数据。 |
| 页眉页脚/页码 | 生成器未设置页眉、页脚或页码字段。 | 无法复现 PDF 的连续居中页码和末页右下网址。 |
| 分页 | 生成器按内容顺序连续添加段落与表格，没有明确的分页控制。 | 可以自然续排，但不同的 DOCX 渲染器会产生不同分页；当前代码也没有处理表头重复之外的章节续页视觉。 |
| 报告内容组织 | 当前是面向审查的详细结果/规则覆盖报告；参考 PDF 是相似文本检测结果单，首屏摘要、章节相似结果、相似文献列表及末页说明的内容模型不同。 | 单靠调整颜色和字体不能实现结构等价；需要区分“借鉴视觉风格”与“复制 PDF 的业务内容结构”。 |

## 自动编号相关的旁证

当前报告错误列表的序号是把 `String.valueOf(index++)` 写入单元格文本。该文件中没有为错误列表创建 Word 自动编号定义；Word 文档编号能力与普通字符串编号是两种不同结构。若用户所说的“自动编号”指论文标题/参考文献中的 Word 自动编号是否被规则识别，此 PDF 样式核查不能验证该行为，应由对应规则解析链路和真实 DOCX 样本单独确认。

## 结论

当前生成器与参考 PDF 的主要差异是版面和样式没有显式定义：报告依赖默认页面设置，标题与正文共用 11 pt 字体方案，表格没有颜色/边框层级，且无页眉页脚和页码。PDF 可作为色彩、标题带、密度、表格线条和分页观感的参照；其检测系统品牌、统计图表、具体字段和相似文献内容不应直接复制到本项目报告。若后续按此参照改版，应先确认是只借鉴视觉风格，还是也要调整报告的信息结构。
