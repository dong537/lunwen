# 第四轮：兼容分支遍历与原文定位

日期：2026-10-04。范围：隔离研究试验，不是产品实现或 UI 设计。沿用第三轮的 docx4j 17.2.1、Java 23 运行环境与学校原件。

## 结论

Java + docx4j 仍是值得继续验证的基础，但必须搭配原始 XML 证据索引。不能仅遍历段落的直接子 run，也不能通过文本搜索定位错误：超链接、域、文本框、修订和兼容分支会造成遗漏或重复，相同文本也可能出现在多个位置。

本轮完整运行 22 项检查，0 失败、0 错误、0 跳过。其中包含确认已有库局限的特征测试，不表示完整格式检测已通过验收。

## 真实学校模板核对

对原始 `/word/document.xml`，显式选择不支持 wps/wpg 的兼容配置，读取 Fallback；预期计数来自此前独立 Python/lxml 核对。

| 核对对象 | 结果 |
| --- | ---: |
| 文本与域指令节点总数 | 611 |
| 普通 w:t 节点 | 536 |
| w:instrText 域指令节点 | 75 |
| 上述节点中位于文本框内的节点 | 131 |
| 地址唯一且逐项回查原文成功 | 611 |

这些是 XML 节点数，不是字符数、段落数或页数。正文部件内的表格和文本框包含在本次扫描中；页眉、页脚等其他部件不在这组计数中。

另行声明支持 wordprocessingShape/wordprocessingGroup 命名空间，选择现代 Choice 分支；本模板两种视图的文本值序列一致，而原始节点地址不同。这只证明该模板的文本一致，不能推导字体、图片、布局一致，更不能假设所有 DOCX 的两种分支都等价。

## 原始证据地址

试验索引保存：部件名、该部件原始 XML 的 SHA-256、从文档根开始的元素子节点下标路径、文本类型和文本框标记。路径保留 AlternateContent 中原始分支的位置，不对原件改写或重新编号。

回查先校验 XML 哈希和索引成员身份，再按路径定位并验证文本。重复文本使用不同地址；原文变化后旧地址被拒绝。这里没有使用段落文本子串匹配。

研究代码位于 `research-spikes/docx4j/src/test/java/research/thesis/SourceIndex.java`。它只实现本轮需要的 Choice/Fallback 选择，不是完整 MCE 实现。修订显式标记，域指令与普通文本区分，但没有解释域状态机或决定接受/拒绝修订后的最终显示内容。

## 表格预处理后的来源关联

真实调用 JAXB Binder 绑定一个合成表格，其中两个 run 的文本完全相同。随后把绑定对象放入 docx4j 工作模型，执行 ParagraphStylesInTableFix。

实测结果：两个 run 仍分别关联各自的原始 DOM 节点；预处理增加了工作模型段落样式，有效加粗生效；原始 DOM 没有新增 pStyle。试验不调用 binder.updateXML，以防将派生样式写回证据树。

这是受控表格样本的关联证据。尚未证明学校整个文档、全部兼容分支与所有预处理操作都能保留这种关联。不能把“原文地址扫描已验证”和“合成表格 Binder 已验证”拼接成“全篇有效格式均已精确回指”的结论。

## 对架构的约束

建议继续验证以下数据流，暂不冻结产品设计：

```text
不可变 DOCX 原件
  → 原始部件与证据地址索引
  → 按明确能力配置选择兼容内容
  → docx4j 工作模型及来源关联
  → 表格上下文与有效格式计算
  → 学校确定性规则
  → 错误位置、原值、期望值、规则来源、覆盖限制
```

原件是证据来源；工作模型是计算结果，不是原件替代品。最终报告必须能区分已检查合规、不合规、不适用与无法判断，不能把不支持的公式或布局算成合规。

效率上，正式实现应在每个部件解析一次后批量回查。当前 SourceIndex.resolve 为了独立验证每条地址，每次重新解析 XML，属于研究验证成本，不应照搬到生产路径。继续采用单文档顺序处理、跨文档有限并发的候选方案；没有数据支持逐段并发或微服务拆分。

本轮重复第三轮计时：加载中位数 6.693 ms、最大值 10.636 ms；表格预处理与已覆盖属性解析中位数 51.734 ms、最大值 131.865 ms。仍是同一文件、2 次预热、10 次测量，不包含本轮逐条地址回查、完整规则、渲染或并发负载。第三轮文档中的数值保留为历史记录，最新 timing.json 对应本轮。

## 验证与未完成边界

运行命令见 spike README 的完整研究检查；本轮结果保存在 `research-spikes/docx4j/evidence/round4/`，原件未修改。原有 WPS 私有设置丢失警告仍然存在，没有通过屏蔽日志伪装解决。

后续研究按依赖顺序推进：

1. 验证真实文档兼容内容投影与 JAXB 来源关联的端到端一致性，覆盖页眉页脚等部件。
2. 验证主题字体、字符字体选择、编号和表格条件样式组合；单位与缺省值不能混为一谈。
3. 检查 Equation.3/MTEF 的可用开源解析链，明确哪些内部格式可判定。当前学校模板有 2 个旧公式，尚未解析其内部格式。
4. 建立指定 Word/WPS 环境下的排版对照，评估渲染路径。当前未运行任何 Office 渲染器，不能承诺页码与视觉完全一致。
5. 用独立标注论文集评估误报、漏报和峰值资源，再冻结技术栈与产品设计。
