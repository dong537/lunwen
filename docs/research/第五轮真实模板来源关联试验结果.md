# 第五轮：真实模板的工作模型与原文关联

日期：2026-10-04。继续隔离研究，不增加生产接口或页面。使用同一学校原件和 docx4j 17.2.1；四边页边距保持按 2.6 cm 判断。

## 已验证结论

学校正文在明确选择旧版 Fallback 分支后，611 个文本及域指令节点的所属 run 均可通过 JAXB Binder 关联工作 DOM。执行 docx4j 表格样式预处理之后，这些 run 仍然：

- 对应原来绑定的 DOM 元素，使用对象身份验证，不使用文本模糊搜索；
- 可从工作文档遍历到，排除“关联仍存在但对象已被文档替换”的假通过；
- 能调用有效 run 属性解析并获得非空结果。

最后一项不等于字体值已经逐项正确：本轮未针对 611 个节点独立标注字体、字号、继承来源及期望值。它证明调用链和来源关联可运行，不证明规则准确率。

新增检查还验证了 7 个 header 部件和 footer1 共 16 个节点：15 个普通文本节点、1 个域指令节点。每个部件分别保存索引、回查原文并绑定所属 run。这组检查未把页眉页脚装配进工作包后执行样式计算，也没有核对各节实际引用哪一个页眉页脚。

## 先失败，再验证处理路径

初始试验直接将原始 document.xml 交给 Binder，未显式选择兼容分支。工作 DOM 文本与域指令数量断言失败：预期 611，实际 742。失败报告保存在 `research-spikes/docx4j/evidence/real-mapping-red.txt`。

这说明原始 DOM 保留了两个分支，不能直接作为已去重的活动内容视图。它不单独证明 docx4j 所有遍历 API 都会重复返回这些文本，不能把 DOM 计数扩展为所有库 API 的行为结论。

随后增加 test 范围内的 LegacyProjection：在独立工作 DOM 上选取显式 Fallback，移除兼容包装及未选择内容。选中元素沿用对象身份，因此在移动前记录的原始地址与元素关联仍可保留。Binder 在投影后建立关联，预处理只影响工作模型，学校 DOCX 原件字节保持不变。

原始地址必须在投影之前记录；不能在投影后按变更过的兄弟节点位置重新生成“原文地址”。当前测试按索引顺序保存选中元素并验证其内容，原始不可变 XML 的地址回查由上一轮测试共同覆盖。

## 重要限制

LegacyProjection 只是本次样本的研究工具，不是通用 MCE 处理器：

- 仅处理 Fallback 配置；遇到没有 Fallback 的兼容块明确抛错，不静默丢弃。
- 未完整处理 mc:Ignorable、ProcessContent、MustUnderstand 等规则。
- 未实现移动节点时继承命名空间声明和其他上下文属性的完整保留。独立检查本模板的 AlternateContent/Fallback 包装没有相对父节点新增的命名空间声明；这不能覆盖任意文件。
- 没有证明投影保留图片视觉效果、几何位置或排版。文本一致不代表布局一致。
- 没有为旧公式内部结构、主题字体、编号、字符字体选择或所有表格样式组合增加正确性证明。

原有 WPS 私有 settings 兼容块的丢弃警告仍存在。不能因为新检查通过而宣称该问题解决，也不应将整个包标记为无损解析。

## 对候选架构的影响

目前不需要改变 Java + docx4j 的候选方向，但解析边界必须有两个清晰产物：

1. **原始证据**：文件及部件哈希、原始节点地址、原始值，来源不可变。
2. **活动工作视图**：明确的兼容能力配置、对象到证据的关联、有效属性及未覆盖能力。

兼容能力配置属于结果可复现条件。不能固定选择 Fallback 后宣称它就是所有版本 Word/WPS 的显示结果，也不能把本轮投影器直接升级为生产解析模块。

按当前研究证据，继续采用模块化单体、单文档顺序解析、跨文档有限并发的方向；渲染作为独立进程的可选验证阶段。正式批量回查必须复用一次解析所得的索引，避免逐节点重新读取 XML。

## 运行证据与下一步

完整命令在 `research-spikes/docx4j` 下运行：

```powershell
mvn.cmd -B -ntp -s settings.xml '-Dprobe.tableAware=true' '-Dprobe.measure=true' '-Dschool.docx=<学校规范绝对路径>' test
```

本轮 24 项测试，0 失败、0 错误、0 跳过；报告及计时保存在 `evidence/round5/`。本轮测量仍是第三轮的有限解析循环，不覆盖新的完整关联路径：加载中位数 7.047 ms，预处理与已覆盖属性计算中位数 52.231 ms。历史计时分别保留，不作吞吐量承诺。

下一项有价值的研究是**有效字体与字号的独立期望值验证**，随后处理 Equation.3/MTEF 开源解析能力和指定编辑器的布局对照。只有这些准确性边界清楚后，再冻结产品架构及界面设计；当前成果仍是可复现研究，不是完整论文筛查系统。
