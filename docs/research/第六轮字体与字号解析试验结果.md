# 第六轮：字体选择与字号继承

日期：2026-10-04。研究组件仍为 docx4j 17.2.1；不新增生产代码、产品页面或未经验证的学校规则。

## 结论

PropertyResolver 计算出的 rFonts 槽位不能直接当成最终字体。必须进一步结合主题、语言、字符及复杂文字设置选择文档字体。本轮复用 docx4j 已有 RunFontSelector.documentFontFor，没有另写字符范围表或主题解析器。

完整测试 30 项通过，0 失败、0 错误、0 跳过。本轮新增 6 项测试，其中 3 个真实模板样本在同一项测试中核对。通过范围是这些明确样本，不代表任意 DOCX 字体与排版均准确。

## 可复现证据

测试位置：`research-spikes/docx4j/src/test/java/research/thesis/FontResolutionTest.java`。合成 fixture 使用学校 theme1.xml 的真实主题，并明确设置 en-US/zh-CN 的主题语言；每次保存成 DOCX 后重新加载。不是 mock 对象测试。

先使用有效 rFonts 的直接 getter，4 项检查中 2 项通过、2 项失败：

- 主题字体期望 Calibri，直接读取 ascii 得到 null。
- eastAsia 为 Times New Roman、ascii/hAnsi 同为 Arial 时，中文期望 Arial，简单按字符选 eastAsia 得到 Times New Roman。

失败报告保存在 `evidence/font-resolution-red.txt`。最初 fixture 曾因 settings 的 JAXBElement 未解包发生类型转换错误，修正 fixture 后才取得上述有效失败基线；类型转换错误不计作能力缺陷。

将取值路径改为 `documentFontFor(pPr, effectiveRPr, codePoint, true)` 后，上述断言不变并通过，随后补充复杂文字标记及学校真实样本检查。`true` 表示已计算有效属性，避免逐字符重复计算同一 run 的继承链。

| 检查 | 结果及适用范围 |
| --- | --- |
| 同层主题引用与字面字体共存 | 主题生效：本 fixture 的 A 为 Calibri，中为宋体 |
| 直接字面字体覆盖继承主题 | 本 fixture 的 A 为 Times New Roman，中为黑体 |
| 字符样式字号覆盖段落字号 | 12pt 的段落字号被字符样式的 14pt 覆盖 |
| 直接字号覆盖字符样式 | sz=21 保留为 10.5pt；szCs=40 保留为 20pt |
| 东亚字体的特殊选择规则 | eastAsia=Times New Roman 且 ascii/hAnsi 同为 Arial 时，本 fixture 中文选择 Arial |
| 复杂文字标记 | 同一拉丁字符 A，w:cs 开启时选 cs 槽位 Courier New；显式关闭时选 Arial |

sz 与 szCs 单位均是半磅；二者独立保存，不能统一读取 sz 后假定适用于所有字符。本轮验证了属性继承及数值保留，没有实现完整的逐字符最终字号选择或字形尺寸测量。

## 学校模板独立抽样

通过 Python/lxml 直接读取原始 XML 中显式格式，确定下列预期，再通过 docx4j 属性解析与字体选择核对。位置为从零开始的 body 直接段落及段落直接 run 下标，仅用于固定 SHA 原件的试验，不作为产品定位协议。

| 段落 / run | 文字 | 预期字体 | 原始 sz / pt |
| --- | --- | --- | --- |
| 3 / 1 | 本科生毕业设计（论文） | 方正小标宋简体 | 72 / 36pt |
| 8 / 0 | 题    目： | 仿宋 | 32 / 16pt |
| 8 / 2 | 线性表的设计和实现 | 黑体 | 36 / 18pt |

每个样本断言完整文本、有效字号及第一个中文字符的文档字体。没有把这 3 处扩展成全篇逐字符检查，也没有把封面样本格式直接变成正文规则。

学校原始主题的 minor Latin 为 Calibri，Hans 为宋体；major Latin 为 Calibri Light，Hans 为宋体；settings 中主题语言为 en-US/zh-CN，docDefaults 使用 minor 主题引用。它们证明主题解析确实与本项目有关，不只是人为构造的边界。

## 新发现的风险

### 库的默认字体不等于论文的显式证据

审查固定版本 RunFontSelector 源码发现：没有主题部件时，会根据 `docx4j.fonts.defaultTheme` 选择版本相关的默认主题；缺少可选择槽位时也可能返回文档默认字体。`documentFontFor` 承诺返回非空值，因此“拿到了名字”不等于“原件提供了充分证据”。

正式适配器需要预先记录主题、语言、字体声明是否存在，以及结果依赖的默认环境；对未确定的编辑器环境标为无法确定或需复核。不能直接把库兜底得到的名字当成合规依据。本轮只审查了该源码分支，未新增缺主题的运行对照实验。

### 文档字体与物理字体必须分开

选择器构造过程会访问物理字体映射。运行日志出现本机字体解析警告、缺少物理字体映射，以及合成文件缺少 FontTable 时库创建默认部件的警告。没有屏蔽这些告警。

测试返回的是文档字体名，不是对该字体已安装、每个字形可用或实际采用该字体渲染的证明。构造时传入 XSL_FO 模式只用于实例化已有选择器，本轮没有执行 FO/PDF 渲染。

候选实现应每个文档复用选择器、每个 run 只计算一次有效属性，并单独度量首次字体扫描成本。这里的研究 helper 为简化断言反复构造选择器，不应照搬到生产路径。字体缓存不得跨不同字体环境而不带版本标识。
