# 规则回归基线

本文档记录本轮对话中已经修复、必须长期保留的共性规则。修改规则时，先更新对应测试，再运行定向测试和完整测试。

## 已固定的规则

### 英文关键词数量

- 规则编号：`EN-03-FORMAT`
- 原因码：`ENGLISH_KEYWORD_COUNT_MISMATCH`
- `Keywords:` 后的英文关键词必须为 3 至 5 个。
- 关键词使用英文或全角分号分隔；分隔符格式和数量分别检查。
- 检查报告、Word 批注必须使用中文说明，不能只显示内部原因码。

回归测试：`RuleEngineTest`、`RuleDescriptionsTest`、`CommentWriterTest`。

### 封面字段排版空白

- `学号`、`院系` 字段名内部允许用于封面对齐的 Unicode 空白，例如 `学    号`、`院    系`。
- 字段名称、冒号和字段值仍然单独检查；不因为放宽字段内部空白而接受错误字段名。
- 候选字段诊断仍保留，用于报告真实的字段名或分隔符错误。

回归测试：`RuleEngineTest.acceptsCoverLabelsWithAlignmentWhitespaceInsideChineseFieldNames`。

### Word 分割续表

Word 可能把一个视觉上的续表保存成多个 XML 表：完整原表、单行重复表头、续表数据。续表检查必须：

1. 在同编号候选中优先选择行数更多的完整原表；
2. 识别与原表表头完全相同的单行重复表头；
3. 只有 XML 证据确认表头不同，才产生 `TABLE_CONTINUATION_HEADER_MISMATCH`；
4. 真实缺少原表时仍产生 `TABLE_CONTINUATION_ORIGINAL_MISSING`。

回归测试：`TableRuleCheckerTest.acceptsContinuationWhenWordStoresRepeatedHeaderAsSeparateOneRowTable`，以及原有的真实不一致和缺失原表测试。

另一个已覆盖的 XML 形态是“原表数据 + 无表题单行分割数据 + 续表标题 + 真正续表”。无表题单行表只有在后续续表编号与前置原表编号一致且列数一致时才按分割片段跳过独立表题和边框检查；续表标题仍归属于标题后的真实表格。

## 变更边界

- 这些修复只改变候选识别和错误归因，不放宽字体、字号、边距、行距、编号等最终格式比较。
- 规则仍以 DOCX XML 的实际属性和节点顺序为准，不按单篇论文名称添加特例。
- 旧批注文档中的历史批注不会自动更新，必须用新规则重新检测原始论文。

## 验证命令

```powershell
mvn -s settings.xml -q '-Dtest=RuleEngineTest,TableRuleCheckerTest,RuleDescriptionsTest,CommentWriterTest' test
mvn -s settings.xml -q verify
```

2026-10-13 规则整理后的 16 篇原始论文重测结果位于项目根目录：`规则整理后重测-20261013-075441`。每篇目录包含 `response.json`、`批注版.docx` 和 `检查报告.docx`；结果由原始 DOCX 重新生成，没有把旧批注版作为输入。

Docker 发布前还要重新执行 `mvn -DskipTests package`、`docker compose build backend` 和 `docker compose up -d --force-recreate backend`。
