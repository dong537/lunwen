# 公式检查误判修正记录

## 本次目标

修正公式规则中会把有效文档写法误报为格式错误的共性问题。判定依据仍以学校规范明文为准：可检查编号、编号格式与字号字体、正文引用、编号连续性、公式和编号对齐，以及变量说明；学校没有明确规定的公式主体字体、字号和变量斜体不作为错误。

## 根因与处理

- **OMML 节点白名单不完整**：Word/WPS 可输出标准公式结构及扩展节点；节点名未列在本地集合中，不代表论文格式错误。已删除基于手写白名单的 EQ-08 错误判定及其报告文案。公式内部无法读取的 OLE/图片对象仍由现有 EQ-06 路径处理。
- **同段公式编号对齐被过度推断**：段落整体居中、编号前出现制表符，都不能证明编号落在右侧。保留失败判定，直到解析到制表位及其位置证据；不以空格数量、制表符存在与否或段落居中推断右对齐。
- **数学文本被扁平化后丢失符号边界**：简单连接全部 `<m:t>` 会把独立的 `x`、`y` 合并成 `xy`；在每个文本节点间插空格又可能拆开同一运行中的长标识符。现在按 `<m:r>` 数学运行提取：同一运行内的文本片段合并，运行之间保留边界。变量说明规则读取提取出的符号集合，不再重拆整条公式文本。
- **函数名和上下标缺少结构区分**：结构化 `<m:fName>` 子树不作为变量；上下标中的字母仍进入待说明集合，避免只检查基变量而漏掉索引符号。

## 验证

- `EquationParserTest`、`RuleEngineTest` 通过。
- 回归覆盖：同一运行拆分的文本片段合并为标识符；相邻运行中的独立变量保持分开；结构化函数名不作为变量；上下标符号进入说明检查；未解释的下标符号会报缺项。

## 尚未解决

- 变量识别已改为按数学运行和函数节点提取，并检查上下标字母；但相邻运行可能是被样式拆开的一个名称，也可能是隐含乘积。单位符号与同名变量、未结构化标记的函数名也无法只凭文本始终区分；需要继续用真实 DOCX 样本校验，不能宣称完全准确。
- LibreOffice 转换保护已改为安全解析 `word/document.xml`，按命名空间和公式对象结构计数，并要求转换后的公式节点含有数学文本；验证包含源文件已有 OMML 与 OLE 混合时不得丢失原有公式。它仍不能证明公式表达式、编号、顺序或版式完全不变，转换产物不得被描述为无损。
- 同段公式右对齐要支持严格结论，仍需解析段落有效制表位（包括样式继承）及其相对版心位置；缺少证据时保留失败而不放宽。

## OMML 内公式号回归（2026-10-14）

- 真实数学论文把显示公式和编号放在 `<m:oMathPara>/<m:oMath>/<m:eqArr>` 中；公式号位于 OMML `<m:r>/<m:t>`，而不是普通 `<w:t>`。此前只从段落普通文本找编号，造成 16 条“缺少公式号”误报。
- 现在仅在 OMML 数学数组中，检测到独立 `#` 分隔运行后紧跟完整的半角或全角括号编号时，才记录 `EquationNumberEvidence`。编号文字、括号、字体、字号和 XML 位置单独保存，不伪造成普通段落字符范围。
- EQ-01 使用该证据判断括号；EQ-02 直接检查编号所在数学运行的字体字号；批注锚点仍落在所在公式段落。EQ-03 不把段落整体居中推断为编号右对齐，必须有独立位置证据。
- 在 `数学论文初稿(测试版).docx` 上复测：37 个公式对象中有 16 个 OMML 数组编号；16 个均被识别，缺号误报从 16 降为 0。其编号运行明确使用 Cambria Math，且 XML 未提供五号字号；16 个格式问题被如实检出。XML 也未提供编号右对齐的证据，因此不能判为符合右对齐要求。
- 另有 21 个公式对象处于正文叙述行内；它们没有被计入独立公式缺号判断。

## 公式号有效格式继承（2026-10-14）

- 公式号的有效字体字号不一定写在 OMML 编号运行本身；Word 可从字符样式、段落样式的 `w:rPr` 和 `w:docDefaults/w:rPrDefault` 继承。只看编号运行会把继承后合规的格式误报。
- `EquationParser` 现在接收 `word/styles.xml`，按“编号运行直接属性 → 字符样式及其 basedOn 链 → 段落样式及其 basedOn 链 → 文档默认运行属性”解析字体与字号；同一属性上直接设置的值优先，非法值不回退到继承值。
- 样式 XML 作为解析调用上下文传递，不保存在解析器实例中，避免并发解析时串用文档样式。
- 字体声明为 `asciiTheme`/`hAnsiTheme` 时，通过 DOCX 主题字体映射解析为实际字体；优先级仍遵循 OOXML 的直接字体属性覆盖主题字体属性。
- 回归覆盖字符样式 basedOn 链、段落样式、文档默认运行属性、主题字体槽，以及编号运行直接属性覆盖样式。全量 Maven 测试 648 项通过。
- 真实数学论文使用编号运行直接指定的 Cambria Math；这仍精确报告 16 个字体不符合，缺少五号字号声明也不会被误判为合规。真实 API 批注验证中，136 条待注释结果全部为 WRITTEN，生成 81 个 Word 批注；其中 16 条 EQ-02 和 16 条 EQ-03 均已写入。
- 主题继承改动后再次用真实论文复测：37 个公式、16 个编号、缺号 0、编号格式错误 16、编号右对齐错误 16。

## OMML 编号结构与跨规则回归（2026-10-14）

- 不能仅凭整条公式中最后两个 `<m:r>` 识别编号：分数分子/分母也可能恰好以 `#` 和括号数字结尾。编号现在要求位于 `<m:eqArr>` 最后一行 `<m:e>` 的直接运行末尾，且末两条直接运行分别是独立 `#` 和完整编号；嵌套分数等子结构不参与这条匹配。
- 数学编号由 ASCII 数字、字母和括号组成，字体检查只取 ASCII 字体。直接运行只设置 `hAnsi` 时，不得拿它覆盖从样式继承的 `ascii` 字体；主题属性与字体名并存时，按项目已有 Word 字体解析规则优先解析 `asciiTheme`。
- OMML 编号改用独立运行地址后，公式排版表格分类也同步消费这个地址，防止 1x2 无边框公式布局表被当成普通数据表检查。
- 新增回归：嵌套分数伪编号、主题与显式字体并存、直接 hAnsi 对继承 ascii 的影响、OMML 编号公式表排除。全量 Maven 测试 652 项通过。
- 最新真实 API 批注复测：37 个公式对象、16 个编号、缺号 0；16 个编号格式错误如实检出；136 个待注释结果全部写入，Word 文件含 81 条批注。
