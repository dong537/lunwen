	<h2 id="remarks">Remarks</h2>
	<p>[ISO/IEC 29500-1 1st Edition]</p>
<p><strong>rPr (Run Properties)</strong></p>
<p>This element specifies a set of run properties which shall be applied to the contents of the parent run after all style formatting has been applied to the text. These properties are defined as <em>direct formatting</em>, since they are directly applied to the run and supersede any formatting from styles.</p>
<p>This formatting is applied at the following location in the <em>style hierarchy</em>:</p>
<ul>
<li><p>Document defaults</p>
</li>
<li><p>Table styles</p>
</li>
<li><p>Numbering styles</p>
</li>
<li><p>Paragraph styles</p>
</li>
<li><p>Character styles</p>
</li>
<li><p>Direct formatting (this element)</p>
</li>
</ul>
<p>[<em>Example</em>: Consider a run which should have a set of run formatting properties. This set of properties is specified in the run properties as follows:</p>
<pre><code class="lang-xml">&lt;w:r&gt;  
  &lt;w:rPr&gt;  
    &lt;w:b /&gt;  
    &lt;w:imprint /&gt;  
    &lt;w:lang w:val="en-ca" /&gt;   
  &lt;/w:rPr&gt;  
&lt;/w:r&gt;  
</code></pre>
<p>The rPr element specifies the properties which are applied to the current run - in this case, bold formatting on the run contents using the b element (§17.3.2.1), an imprinted (engraved) text effect using the imprint element (§17.3.2.18), and that this text should be interpreted as English (Canada) when spell or grammar checking the run text using the lang element (§17.3.2.20). <em>end example</em>]</p>

<p>[ISO/IEC 29500-1 1st Edition]</p>
<p><strong>rPr (Run Properties For Structured Document Tag Contents)</strong></p>
<p>This element specifies the set of run properties which shall be applied to the text entered into the parent structured document tag in replacement of placeholder text. When placeholder text is present in a structured document tag, its formatting is often different than the desired underlying formatting, and this element specifies the formatting which shall be used for non-placeholder text contents when they are initially added to the control.</p>
<p>If this element is not present, the inserted is unformatted, as with any other run of text - it shall not inherit the properties of the placeholder text.</p>
<p>[<em>Example</em>: Consider the following structured document tag:</p>
<pre><code class="lang-xml">&lt;w:sdt&gt;  
  &lt;w:sdtPr&gt;  
    &lt;w:placeholder&gt;  
      &lt;w:docPart w:val="TestPlaceholderDocPart"/&gt;  
    &lt;/w:placeholder&gt;  
    &lt;w:showingPlcHdr/&gt;  
    &lt;w:rPr&gt;  
      &lt;w:rStyle w:val="UserName"/&gt;  
    &lt;/w:rPr&gt;  
    …  &lt;/w:sdtPr&gt;  
  &lt;w:sdtContent&gt;  
    &lt;w:r&gt;  
      &lt;w:rPr&gt;  
        &lt;w:rStyle w:val="PlaceholderText"/&gt;  
      &lt;/w:rPr&gt;  
      &lt;w:t&gt;[Type Your Name Here]&lt;/w:t&gt;  
    &lt;/w:r&gt;  
  &lt;/w:sdtContent&gt;  
&lt;/w:sdt&gt;  
</code></pre>
<p>This structured document tag specifies that its current contents are placeholder text via the showingPlcHdr element (§17.5.2.39), and that text has the <em>PlaceholderText</em> character style applied to it.</p>
<p>Now, assume that that style created grey shaded text (typical for placeholder text). This formatting would clearly not be desirable for any text entered into the structured document tag. Therefore, when this text is added, the rPr element in the sdtPr is used to store the formatting on the resulting text.</p>
<p>In this example, the text which initially populates the control shall be formatted with the <em>UserName</em> character style. <em>end example</em>]</p>

<p><strong>rPr (Structured Document Tag End Character Run Properties)</strong></p>
<p>This element specifies the set of run properties which shall be applied to the character present to delimit the end of the structured document tag's contents. When these properties are applied, they shall be applied in addition to the run properties specified for the entire structured document tag via the rPr element (§17.5.2.27) stored in the tag's main property container.</p>
<p>If this element is not present, the inserted closing tag shall be formatting identically to the start tag.</p>
<p>[<em>Example</em>: Consider the following structured document tag:</p>
<pre><code class="lang-xml">&lt;w:sdt&gt;  
  &lt;w:sdtPr&gt;  
    &lt;w:placeholder&gt;  
      &lt;w:docPart w:val="TestPlaceholderDocPart"/&gt;  
    &lt;/w:placeholder&gt;  
    &lt;w:showingPlcHdr/&gt;  
    &lt;w:rPr&gt;  
      &lt;w:rStyle w:val="UserName"/&gt;  
    &lt;/w:rPr&gt;  
    …  &lt;/w:sdtPr&gt;  
  &lt;w:sdtEndPr&gt;  
    &lt;w:rPr&gt;  
      &lt;w:b/&gt;  
      &lt;w:i/&gt;  
    &lt;/w:rPr&gt;  
  &lt;/w:sdtEndPr&gt;  
  &lt;w:sdtContent&gt;  
    …  &lt;/w:sdtContent&gt;  
&lt;/w:sdt&gt;  
</code></pre>
<p>The rPr elements under the tag's properties specify that this structured document tag specifies that its start character must have formatting in the character style <em>UserName</em>, and that the end character must have the formatting in the character style <em>UserName</em> as well as bold and italic direct formatting. <em>end example</em>]</p>

<p><strong>rPr (Run Properties)</strong></p>
<p>This element specifies the set of run properties which comprise the default run properties for the current WordprocessingML document. [<em>Rationale</em>: The reason that an rPr element is present within the rPrDefault element is to allow for easy repurposing of any set of run properties within a WordprocessingML document - since the run properties are always child elements of a single rPr element, that element can simply be relocated in its entirety to the desired new location without additional modifications. <em>end rationale</em>]</p>
<p>If this element is omitted, then the default run properties for the current document are non-existent (i.e. there are no default run properties, and the defaults are therefore application-defined).</p>
<p>[<em>Example</em>: Consider the following definition for the document defaults for a WordprocessingML document:</p>
<pre><code class="lang-xml">&lt;w:docDefaults&gt;  
  …  &lt;w:rPrDefault&gt;  
    &lt;w:rPr&gt;  
      &lt;w:b/&gt;  
    &lt;/w:rPr&gt;  
  &lt;/w:rPrDefault&gt;  
&lt;/w:docDefaults&gt;  
</code></pre>
<p>The rPr element as a child of the rPrDefault element contains the set of default run properties for this document - in this case, bold text. <em>end example</em>]</p>

<p><strong>rPr (Table Style Conditional Formatting Run Properties)</strong></p>
<p>This element specifies the set of run properties which shall be applied to all runs within a table which match the conditional formatting type specified on the parent tblStylePr element. These properties are applied in the order specified via the style hierarchy.</p>
<p>[<em>Example</em>: Consider a table style which contains conditional formatting for its <em>firstRow</em>, defined as follows:</p>
<pre><code class="lang-xml">&lt;w:style w:type="table" w:styleId="exampleTableStyle"&gt;  
  …  &lt;w:tblStylePr w:type="firstRow"&gt;  
    &lt;w:rPr&gt;  
      &lt;w:i/&gt;  
    &lt;/w:rPr&gt;  
    …  &lt;/w:tblStylePr&gt;  
&lt;/w:style&gt;  
</code></pre>
<p>The rPr element specified within the tblStylePr element specifies the set of run properties which must be applied to all parts of the table which meet the criteria specified by the type value of <em>firstRow</em> - all of the header rows of the table. In this example, the single run property applied is italics via the i element (§17.3.2.16). <em>end example</em>]</p>

<p><strong>rPr (Numbering Symbol Run Properties)</strong></p>
<p>This element specifies the run properties which shall be applied to the numbering level's text specified in the lvlText element (§17.9.12) when it is applied to paragraphs in this document.</p>
<p>These run properties are applied to all numbering level text used by a given abstract numbering definition and numbering level. It should be noted that run properties specified on a numbered paragraph itself, or on text runs within a numbered paragraph, are separate from the run properties specified by rPr elements within a numbering level, as the latter affects only the numbering text itself, not the remainder of runs in the numbered paragraph.</p>
<p>[<em>Example</em>: Consider the WordprocessingML below which uses the rPr element to specify that the numbering symbol used within a given numbering level should be bold and of a 16 point font size:</p>
<pre><code class="lang-xml">&lt;w:lvl w:ilvl="1"&gt;   
  …  
  &lt;w:rPr&gt;  
&nbsp;   &lt;w:b /&gt;   
&nbsp;   &lt;w:sz w:val="32" /&gt;   
&nbsp; &lt;/w:rPr&gt;  
&lt;/w:lvl&gt;  
</code></pre>
<p>The resulting paragraph uses its regular paragraph formatting, but the numbering level text itself must be specifically formatted as bold in 16 point font. <em>end example</em>]</p>
