# 标题结构精确判定复核

## 本轮发现

`RuleEngineTest.recognizesChapterHeadingWhoseTitleStartsWithACommonVerbWhenHeadingFormattingConfirmsIt` 用例创建了一个“第X章……”标题，但测试数据没有设置 `outlineLevel=0`。生产判定路径在标题文字无法证明章标题时，要求段落具备一级大纲级别，并且非空文本运行同时符合一级标题字号及中英文对应字体。测试夹具缺少大纲级别，所以不会进入正文检查；失败来自测试没有构造完整的 XML 证据，不是正文遍历状态错误。

已将夹具补齐一级大纲级别。这个用例现验证：当章标题文本包含容易触发叙述句排除条件的词语时，可靠的结构证据仍能识别章标题，后续正文会执行 `BODY-INDENT` 检查。普通叙述句不会仅因为提到“第X章……”就被当作标题；既有反例仍由 `RuleEngineTest` 覆盖。

## 判定原则

- 标题结构证据来自 OOXML 段落大纲级别、编号属性和实际运行格式，不以单一关键词作为最终结论。
- 标题字号和字体按模型中可读取的属性精确比较，不使用数值容差。
- 若大纲级别、编号或有效运行格式缺失，XML 证据不足以证明它是标题，不能用“看起来像标题”绕过判定。
- 文本正规化仅用于候选结构识别；标题编号空格等格式规则仍需检查原始文本或相应 XML 属性，不能用正规化后的文本替代格式结论。

## 验证

- `rtk mvn -q -f backend/pom.xml -Dtest=RuleEngineTest test`：通过。
- `rtk git diff --check`：通过。

这只验证规则引擎单测覆盖的标题识别行为，不代表全量 `mvn verify` 已通过，也不表示所有规则均已完成精确匹配审计。

## 规则精确性续审

附录编号大小写边界已新增回归用例验证：附录标题识别使用不区分大小写的候选匹配，但保留原始字母；`附录a` 得到实际值 `a`，与要求的大写 `A` 精确比较后报序号错误。附录图题 `图a1` 也无法匹配要求的大写对象编号。这里的宽松只用于发现候选标题，不代表格式放行，因此保留当前实现。

### 已逐项核对的数值匹配

- 页边距比较整数 twips `1474`，并独立检查装订线；任一边缺值不会作为通过证据。
- 正文缩进只接受 `firstLineChars=200` 或 `firstLine=480 twips`；两种属性同时存在时两项都必须精确相等。`420`、`421` 等近似值不通过。
- 正文字体按字符实际使用的 OOXML 字体槽与 `Times New Roman`、`宋体` 精确字符串比较；字号按半磅整数精确比较。
- 行距按 `line=360` 且有效 `lineRule=auto` 精确比较；不使用数值容差。
- 标题编号空格数量、图表/公式编号字符串连续性、参考文献编号顺序均使用明确的字符串或整数条件，不使用近似数值比较。

XML 属性的缺省值按 OOXML 语义解析，不等同容差。例如 `lineRule` 缺省时其规范默认值为 `auto`；检查的是有效语义值。候选段落识别阶段移除空白或用 `find()` 搜索文内引用，也不直接构成格式通过：对应的格式规则仍需基于原始文本、来源区间或有效属性给出判断。

### 本轮发现与修复：文本前导空白

正文/摘要的缩进规则此前只比较段落属性 `firstLineChars` 与 `firstLine`。反例显示，XML 同时有正确的 `firstLine=480` 且文本以两个空格开头时，`BODY-INDENT` 仍判通过；实际首行位置会叠加文本空格与段落缩进。现已将段落文本开头的 Unicode 空白数量纳入缩进判定，必须为零；空白与属性缩进同时存在时报告 `INDENT_MISMATCH`，实际值中附带空白数量。新增回归测试先复现 PASS，再修复后通过。该检查只作用于正文/摘要缩进，不改变标题规则。

### 本轮发现与修复：参考文献类别标点

参考文献类别解析之前把 `[M]` 行尾、`[J] .` 和 `[EB/OL]。` 都作为有效类别，尽管学校规范中的示例均为类别标识后紧接 ASCII 句点（如 `[M].`、`[EB/OL].`）。新增回归用例复现这些格式错误被解析成有效类别；现有效类别匹配要求类别标识后立即出现 `.`。宽松的类别候选扫描仍只用于识别无编号文献条目，避免错误条目从数量统计中消失；编号条目保留在结果中并因类别无法识别触发 `REF-02`。

验证：`ReferenceParserTest`、`ReferenceElectronicRuleTest`、`RuleEngineTest` 通过；`git diff --check` 通过。

### 仍需逐项审计

本轮没有发现仍使用浮点 epsilon、绝对差或数值区间的格式规则，也没有为此改动生产规则。后续审计继续检查非数值匹配的边界：引用与编号的完整 token 边界、章节/附录/摘要区域终止条件、DOCX 样式继承解析缺失时是否静默通过、表格单位及续表结构的候选识别与最终判定是否一致。当前不能宣称规则已全部精确或完成。
