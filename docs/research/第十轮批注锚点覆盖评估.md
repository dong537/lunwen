# 第十轮：批注锚点覆盖评估

日期：2026-10-07。范围：固定学校规范原件的故事部件与段落覆盖统计；不修改原件。

## 结果

选择 Fallback 分支后，`word/document.xml` 中共有 263 个段落：

| 位置 | 段落数 | 当前批注样本是否支持 |
| --- | ---: | --- |
| 正文 body 直接子段落 | 140 | 支持固定序号的整段锚点 |
| 表格内段落 | 51 | 已用结构路径验证第一个真实表格段落；批量能力仍需扩展 |
| 文本框内段落 | 72 | 投影后路径与原始路径不一致，当前安全拒绝 |
| 其他嵌套段落 | 包含在总数中 | 需按原始结构地址处理 |

页眉 7 个部件各有 1 个段落；footer1 有 2 个段落，其中 1 个含文字。第十三轮关系试验表明当前不向这些 story 写入批注。

这说明“程序能读取 XML”与“每个问题都能安全写入 Word 批注”是两个能力。当前样本的批注 API 只接受正文直接段落序号；如果调用方把表格或文本框的顺序误当成正文序号，就可能把意见写到错误位置。因此正式接口必须接收原始部件名和元素路径，禁止只传一个全局段落编号。

## 处理策略

首版批注输出按能力分层：正文直接文字和已验证的表格文字在有稳定原始路径时允许写入；文本框、页眉页脚、超链接、域、修订或复杂范围先保留在 HTML 报告；无可靠范围、重叠批注或来源哈希变化时拒绝写入并报告原因。

第一个真实表格段落已通过结构路径写入并经 docx4j 回读；这只证明单元格内整段锚点的 OPC 结构可读。仍需验证跨 run、合并单元格、跨页表格和编辑器显示。文本框测试显示：原始文档中 57 个 Fallback 文本框被兼容投影后，节点路径会改变；当前写入器拒绝投影路径，不能直接把批注写入 Fallback 并假定 Word 会显示。

## 证据与限制

统计证据：`research-spikes/comments/evidence/anchor-inventory.json`。本机没有发现 Word、WPS 或 LibreOffice 可执行文件；docx4j 回读只证明当前 OPC 关系可读。

正式 `AnchorResolver` 应使用前轮 SourceIndex 的部件哈希与原始元素路径，并在写入前重新验证路径和文本。报告中每条结果保存 `annotationStatus=WRITTEN|UNSUPPORTED_ANCHOR|REJECTED`；未写入批注的问题必须仍可查看和下载 HTML 报告。
