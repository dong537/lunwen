# 第十三轮：页眉页脚批注关系试验

日期：2026-10-07。范围：在批注样本副本上把同一个 commentRange 写入 header1.xml，观察 docx4j 关系处理；不修改学校原件。

## 试验结果

构造了两种副本：

1. 页眉包含 `commentRangeStart/End` 和 `commentReference`，但只保留主文档到 `word/comments.xml` 的关系。docx4j 能加载主文档批注，但没有把页眉范围当作可解析的主文档批注。
2. 另外为 `header1.xml` 建立到同一 comments.xml 的关系。关系目标使用 `comments.xml` 后，docx4j 的测试进程虽然以 `BUILD SUCCESS` 结束，但日志明确出现 `RelationshipsPart - Couldn't process id: rIdComments`；这条 warning 表示页眉关系没有被正常解析，不能把测试通过误读为批注支持。使用错误的 `../comments.xml` 目标则直接触发关系加载异常。

这不是 Word/WPS 实机结论，但足以说明不能从正文 comments.xml 关系推导页眉页脚批注支持。docx4j 的 `CommentsPart` 固定名称为 `/word/comments.xml`，现有研究没有发现 header/footer 专用批注适配器。

## 决策

页眉、页脚批注暂不写入 Word 副本。相关问题保留在 HTML 报告，并标记 `UNSUPPORTED_ANCHOR`；只有完成标准关系验证、Word/WPS 实机打开和保存回读后，才允许启用。正文和表格批注不受本轮限制影响。

证据日志原始文件位于 `research-spikes/docx4j/header-main.log`、`header-rel.log` 和 `header-rel2.log`，并复制为可审阅文本保存于 `research-spikes/comments/evidence/header-main.txt`、`header-rel.txt` 和 `header-rel2.txt`；样本输出不纳入 Git。原件 SHA 没有改变。当前机器没有 Word、WPS 或 LibreOffice，无法做编辑器级验证。
