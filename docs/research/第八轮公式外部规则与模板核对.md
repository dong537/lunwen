# 第八轮：公式外部规则与模板核对

日期：2026-10-04。只读规范、研究试验；未实现通用规则引擎或 UI。

## 规范原文及来源

原件 SHA-256：`3c9c3dc012b779b4ebd20ea35cb86142d73fb911c7733e3b0d1789ce2d6ac2b2`。

正文公式要求出现在 `/word/document.xml` 的 `/w:document/w:body/w:p[72]` 下的文本框内容中。以下是原文，不是根据示例字体推断：

> 正文中公式。所有的公式要有公式号，公式序号按一级标题编排，如一级标题是第三章，公式为该级标题的第1个公式，则为“3-1”，依次类推。公式号和公式一起要居中对齐，编号需加圆括号并居右放置（5号，Times New Roman）。在文中出现的公式一定要有引用，公式中出现的变量一定要有说明。

原始 XML 的 Choice/Fallback 各有一份该文本。按上一轮的兼容配置选择分支后，该条款只出现一次；不能对原始 XML 全文直接拼接后当成两条要求。

另在 `/w:document/w:body/w:p[139]` 有附录特例：

> 论文的附录用大写字母A，B，C等连续编号，如附录A。附录中的图、表、公式等用阿拉伯数字另行编序号，但在数码前冠以附录序码，如图A1；表B2；式(B3)等。

所以正文编号与附录编号必须区分，不能用一个只允许“数字-数字”的正则扫描全篇。

## 条款拆解与判定边界

| 条款 | 明确期望 | 所需证据及边界 |
| --- | --- | --- |
| 正文公式编号 | 按一级标题章节编排，章号-顺序号 | 先确定章节边界、公式主体及编号归属；不能把正文引用当作编号 |
| 圆括号 | 编号加圆括号 | 原文没有明确全角/半角等价政策；不可只因宽度不同直接判错 |
| 编号字体字号 | Times New Roman、五号即 10.5pt | 检查编号全部字符的有效属性，w:sz=21；不能把公式本体字号套用到编号，反之亦然 |
| 编号居右 | 原文明确 | 段落对齐、制表位、表格单元格或浮动位置可能实现；最终位置必要时依赖排版 |
| 公式居中 | 原文称“公式号和公式一起要居中对齐” | 与“编号居右”存在措辞歧义；主体居中、编号居右只是候选解释，不能标为已确认硬规则 |
| 正文引用 | 公式在文中要有引用 | 排除公式标签自身、目录及规范说明；支持文本与域引用，不能只统计编号出现次数 |
| 变量说明 | 变量要有说明 | 变量集合需要可靠公式解析；出现“式中”不等于说明完整，缺少关键词也不等于没有说明 |
| 附录公式编号 | 冠附录序码，如式(B3) | 单独适用范围；不能强套正文章号规则 |

以上是研究规则清单，不是已部署的规则配置。规范没有给出公式本体字体、字号，仍不添加这些硬性要求。

## 模板实测

### 第一个对象

位置 `/w:document/w:body/w:p[76]`，对象 `rId13 → embeddings/oleObject1.bin`；预览 `rId14 → media/image2.wmf`。段落明确设为 center。

公式后是 7 个普通空格和 `(3-1)`。编号分为 `(`、`3-1`、`)` 三个 run。所有编号字符的文档字体均解析为 Times New Roman，有效 sz=21，即 10.5pt。

该段落标记自身另有 sz=24，但不能作为文字 run 的字号；本轮编号样本证明直接读段落标记会得出错误的 12pt。复杂文字字号 szCs 也不能不加区分地用于这些拉丁数字和标点。

前一段 `/w:document/w:body/w:p[75]` 的直接文字为“由式(3-1)给出：”，提供一个真实引用候选。这里确认存在引用，不证明整篇所有公式的引用完整。

整个段落 center 加空格不等于编号已对齐版心右边界，也不等于公式主体本身正好居中。不能仅靠 jc=center 把全部对齐要求判合格。

### 第二个对象

位置 `/w:document/w:body/w:p[77]`，对象 `rId15 → embeddings/oleObject2.bin`；预览 `rId16 → media/image3.wmf`。

本段无直接文字编号、没有直接指定 jc，继承默认 Normal 的 both（两端对齐）。这是模板结构事实，不是无条件的违规结论：需要确认该对象是独立公式、前一公式的续行，还是示例的一部分，再决定是否必须单独编号。

不能简单执行“一个 OLE 对象必须对应一个独立编号”；多行公式、组合公式、行内公式和附录需要先归类。

### 图片归属

两个 WMF 均由各自 w:object 内的 v:imagedata 引用，是公式预览。不能仅凭扩展名或图片关系类型，把它们计为两张需要图题的普通插图。图片检查的入口需要对象归属信息，而不是独立遍历全部媒体文件。

## 技术影响

规则执行前应先构造具有证据关联的公式候选对象，至少包含：主体位置、存储类型、OLE/预览关系、编号各字符来源、正文/附录作用域、引用候选和解析覆盖限制。

这些领域信息应集中在文档结构识别边界，不能分别散在编号正则、图片扫描器、字体检查器中。没有确定归属时保留歧义，并输出需复核；不要以最近一个数字字符串自动配对。

XML 可证明格式声明与结构关系；实际居中、居右、同页和不换行属于布局结果。后续渲染必须注明编辑器及版本、字体环境和原件哈希，不能把一个未经对照的 PDF 当作 Word 的权威结果。
