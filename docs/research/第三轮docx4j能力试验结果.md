## 3. 新发现：有测试通过仍必须检查警告

加载包存在延迟解析：只调用 load 并访问正文不能证明 settings 等部件成功读取。执行表格预处理/属性计算时才触发 settings 解析，日志出现 JAXB 未知元素和兼容块丢弃警告。

原始节点为 settings.xml 中的 mc:AlternateContent，只有 Requires=wpsCustomData 的 Choice，内容为 wpsCustomData:typoFeatureVersion val=1，没有 Fallback。当前库不识别该 WPS 扩展并删除这一兼容块。

这不直接证明正文内容丢失，也不证明学校要求的字体错误；它证明派生模型不是完整证据来源。缺少受支持的 Choice 且无 Fallback 时跳过内容可能符合兼容处理规则，但是否影响 WPS 布局仍未确定，不能假装支持该扩展。

处理原则：

1. 原始 ZIP/XML 永久作为本任务证据，保持只读。
2. 进入派生模型前扫描不支持的部件/命名空间，记录覆盖限制；不以吞掉警告作为成功。
3. 表格预处理只操作工作模型；结论回指原始节点，不能把合成样式名称展示为学生原始样式。
4. 对受未知布局设置影响的页面级规则标为未验证/需复核，字体等确定性规则按自身证据运行。

## 4. 初步时间测量

同一 JVM，原件字节预先读入内存，2 次预热 + 10 次测量，单线程，原件 310456 bytes。

| 阶段 | 中位数 | 样本最大值 |
| --- | ---: | ---: |
| docx4j 包加载 | 6.358 ms | 9.016 ms |
| 表格预处理 + 遍历 + 所覆盖属性计算 | 51.928 ms | 123.426 ms |

本次遍历返回 263 个段落对象，检查 806 个直接子 run。此数字是 API 遍历口径，不是已证明去重完整的所有文字数；超链接/域等容器中的 run 不包含在这次简单计时循环的全部覆盖承诺内。

计时不包括磁盘上传、杀毒、数据库、任务排队、完整字符级字体选择、学校规则、MTEF 解码、页码映射、Word/LibreOffice 渲染或报告生成。没有测 RSS 或并发，不能推算每秒论文数或学校高峰吞吐。JAXB 部件延迟读取可能计入第二阶段，故第一阶段数字不能当作完整解析时间。

## 5. 对候选架构的影响

继续优先验证模块化单体代码库、持久化任务和隔离渲染。新增明确约束：

- adapter 输出必须同时携带有效格式、原始来源和覆盖限制。
- 原始模型/工作模型需逻辑隔离；无需两份完整 DOM 长驻，但原始字节和稳定定位不能丢。
- 正式 adapter 不能仅调用 PropertyResolver，必须包含经验证的表格上下文。
- 提前定义要检查的部件并触发读取，避免任务看似解析成功、后续才暴露未支持设置。
- 库内预处理告警应转成结构化诊断；不能依靠全局日志级别或字符串吞错维持“成功”。

当前数据不支持优化为微服务或逐段并行；先避免重复解析，单文档顺序处理，在真实语料上测得瓶颈后再调整。
