# 2026-10-12 精确规则审计补充

## 范围

本轮核对当前后端规则中学校规范明确给出数值或格式值的检查，并搜索 `Math.abs`、epsilon、区间比较和近似比较等容差实现。目标是确保规则按 DOCX XML 的有效属性精确判定，不以视觉接近替代属性一致。

## 审计结果

- 页边距按四边 `1474 twips` 比较，并单独检查 `w:gutter`；不做厘米换算容差。
- 正文首行缩进按有效 `firstLineChars=200` 或 `firstLine=480 twips` 精确比较；两种表示同时出现时按 OOXML 的字符单位优先级选择有效值，不把被覆盖的另一表示误当成容差或独立硬条件。字号按半磅整数比较，行距按 `w:line=360` 且 `lineRule=auto` 比较。
- 字体按字符所用的 `ascii`、`hAnsi`、`eastAsia` 字体槽位与解析后的主题字体名比较；错误信息包含槽位和值，避免只报笼统字体错误。
- 检查源码未发现数值容差、epsilon 或近似相等判定。章节、摘要等标题的空白归一化只用于识别候选段落；具体空格格式检查仍读取原始文本。
- 引用格式原先会容忍方括号内的零宽字符，且引用号无法解析时可能仍让 `CITE-01` 通过。本轮改为将零宽空格、词连接符、BOM 与普通空白一样判为格式错误，并让无法解析的引用组同时触发 `CITE-01` 失败；引用编号仍参与关联诊断。
- 公式编号的括号校验已拒绝括号内空格，但 `EQ-02` 仍可能把同一编号格式判为通过。本轮将字号/字体匹配限定为成对括号且编号紧贴括号；ASCII 与全角成对圆括号仍被视为规范允许形式。
- `EQ-02` 曾在整段文字里搜索任意同号、格式正确的编号，可能用另一个重复编号掩盖实际编号错误。本轮改为按 `EquationModel.numberSource` 的段落路径和字符区间校验，并修正规则测试夹具，使来源区间符合 DOCX 段落/Run 文本坐标。
- 目录一级条目缩进曾在 `left` 与 `leftChars` 同时存在时只比较 twips，物理值正确会掩盖字符值错误。现按 OOXML 字符单位优先级对有效的 `leftChars` 精确比较；字符单位缺失时才精确比较 `left` twips，不使用浮点容差或范围匹配。
- 表格使用 `tblStyle` 时，`TAB-02` 目前会跳过三线表边框判断。原因是条件样式（如 `firstRow`、`lastRow`）和单元格直接边框会参与最终效果，简单把 `styles.xml` 中所有边框合并会把不适用的条件边框误判为实际边框。此处是明确的覆盖缺口，需按 OOXML 样式优先级和表格条件逐格解析后再取消跳过。

## 未完成边界

复杂脚本主题字体 `cstheme`、EastAsia 主题字体的语言选择，以及表格条件样式和逐单元格样式合成仍需专项 DOCX 样本与回归测试。表格边线已解析 `w:tr/w:tblPrEx/w:tblBorders` 行级例外属性，并支持表级、行级、单元格级直接边框覆盖；表格样式目前只解析 `basedOn` 链及 `wholeTable` 边框。遇到 `firstRow`、`lastRow`、首末列、带状条件或其他带边框条件样式时，将边框证据标记为未解析并跳过 `TAB-02`，不视为通过。样式表中没有被条件化的普通样式边框、默认表格样式的适用范围及直接/条件边框的完整 OOXML 渲染优先级仍需继续验证。表格规范允许必要辅助线，因此仅检测到竖线不能直接推出格式错误；当前仅在必需横线缺失时判错，并在实际说明中附带竖线解析事实。单位量纲识别也只覆盖代码中明确列出的常见字段，仍需按规范扩展并以真实表格校验。公式编号若通过同段落制表位实现，当前模型尚未提取有效制表位的位置，因此无法证明这类布局正确；当前按无右对齐证据直接判失败。标题/章节候选识别和单位表头语义识别仍有基于文本形态的分类逻辑，需要逐项验证它们不会直接产生格式 PASS。源码对规范中明确的数值属性使用整数精确比较，本轮搜索未发现数值容差、epsilon 或近似相等实现；这不等于所有语义识别和样式级联均已完整。本文记录不据此宣称 XML 格式审计全部完成。真实分页、同页关系等排版结果也不属于仅靠规则属性精确比较可完整证明的范围。

## 生成目录字段识别修复记录

- 目标：只跳过 OOXML 中确认为生成目录字段的段落；正文即使含有普通单词 `TOC`、`PAGEREF` 或 `HYPERLINK`，仍应参与规则检查。
- Source of Truth：DOCX `word/document.xml` 中明确以 `TOC` 为指令的字段，以及 `TOC1` 等目录段落样式；`PAGEREF`/`HYPERLINK` 可用于其他交叉引用或普通超链接，不能单独证明该段是生成目录；可见文本不是字段指令的权威来源。
- 模块边界：`Docx4jDocumentParser` 从 XML 识别字段，`ParagraphModel` 携带布尔事实 `generatedTocField`，`RuleEngine` 仅消费该事实，不再从显示文本猜测。
- 契约/数据流：XML 段落 -> parser 的结构化字段识别 -> `ParagraphModel.generatedTocField` -> 只用于阻止目录字段退出目录区或误入标题/正文分类；目录显示条目照常经过目录间距和缩进检查。无法确认字段时值为 `false`，显示结果仍按精确目录条目结构检查。
- 成功标准：真实 `TOC` 字段 XML 被标记；普通文本 `HYPERLINK` 不被标记且不跳过格式检查；原有目录条目格式检查继续通过。仅改解析器、段落模型和规则过滤，不扩展字段识别到其他 Word 功能。

## 页码字段拆分结果 run 续审

- 页码解析原先只读取字段缓存结果中的第一个文本 run，若数字被 Word 拆成多个 run，后续数字字体或字号错误会漏检。
- 复杂 PAGE 字段现在按 `begin`、`instrText`、`separate`、结果文本和 `end` 的 OOXML 顺序收集全部结果 run；逐 run 解析有效字体与字号，任一 run 不符就由 `PAGE-05` 报错，每项错误按页码段落聚合为一个发现，避免拆分数字重复批注。
- `fldSimple` 字段同样读取所有文本结果 run。无缓存结果文本时保留既有的页脚段落样式读取行为。对于无 `separate` 标记的非标准复杂字段，兼容路径沿用“指令后第一个文本 run 为缓存结果”的既有解释；这类 XML 没有明确结果区间，不能据此推断多个 run 的缓存结果边界。

## 分节页码起始值精确判定

- 原规则只拒绝正文后续分节显式 `w:pgNumType/@w:start="1"`，因此后续分节从 2、5 等其他数字重新编号时会漏检。

- 最新验证：`rtk mvn -q -s settings.xml -DskipTests package` 构建通过；规则相关定向测试套件通过；`rtk git diff --check` 通过。

## 数值容差复核结论

- 对页边距、首行缩进、字号、行距、页码字号和编号序列的源码比较进行了复核，均使用精确整数/字符串相等判断，没有 epsilon、四舍五入或允许误差区间。
- 发现的宽松逻辑均属于候选识别或 OOXML 合法语义：样式继承、缺省属性默认值、字符单位与 twips 的不同表示、标题/题注候选筛选。候选被识别后仍按规范原始值精确比较，未知值进入 `*_UNKNOWN` 失败路径，不作为合规处理。
- `REVIEW` 结果仅用于 XML 无法证明最终视觉版面的场景，不是数值容差；这部分仍需单独决定是否改成保守失败结论，当前不把它计为已完成的自动判定。
- 新增页边距一单位边界反例 `rejectsMarginThatDiffersByOneTwip`：`1473` 对规范值 `1474` 必须失败，验证比较没有隐含的 ±1 twip 容差。该用例通过。
- 新增行距一单位边界反例 `rejectsLineSpacingThatDiffersByOneTwip`：`359 twips` 对 1.5 倍行距要求的 `360 twips` 必须失败，且 `lineRule=auto` 不能掩盖数值不符。该用例通过。

## 空行与二值判定补充

- 主规则引擎原先用 `String.isBlank()` 统计标题后的空段落；Java 不把 U+3000 全角空格视为空白，Word 中只含全角空格的视觉空行因此会被漏计。现统一按 Unicode `isWhitespace` 或 `isSpaceChar` 判定，零宽字符仍不自动视为空行。
- 新增摘要标题后全角空格空行回归测试，避免把合法空行误报为缺失。
- 用户要求直接给出正确/错误，原先 `review()` 产生的表题位置、图题位置、图引用结构、OLE/MathType 公式四类结果现统一按保守 `FAIL` 输出；原因码和修改建议保留，XML 无法证明规范属性时不再返回人工复核状态。
- 图片题注、表题、公式排版表的结构扫描原先分别使用 `trim().isEmpty()` 或 `String.isBlank()` 判断中间空段落，U+3000 全角空格会阻断关联。新增 `XmlPartSupport.isBlankText` 作为统一 XML 空白判定，并替换三处结构解析；新增“图片后全角空格段落仍能关联题注”回归测试。
- 封面起始标题和“专业年级”识别原先使用 `replaceAll("\\s+", "")`，全角空格可能使封面规则整段跳过。现改用规则引擎的 Unicode 空白归一化；新增全角空格封面标题回归测试，定位归一化不影响后续原始文本格式精确检查。
- 再次检索 `Math.abs`、`Math.round`、epsilon、浮点区间等近似数值实现，规则和解析代码未发现数值容差。`BigDecimal.setScale` 只用于报告把 twips 转成厘米的展示，不参与规则判定。页面格式、段落行距等缺省属性需按 OOXML 定义的默认值解释，不能把合法省略属性误判为未知；其余未能解析的硬性属性进入失败路径。
- 复核引文字号后确认学校规范要求正文引文小四号，OOXML `w:sz=24` 是精确值；页码五号 `w:sz=21` 不适用于引文。未改变现有引文字号规则。
- 该审计仍在进行：当前检查覆盖精确数值、常见前缀编号、空白段落及主要规则入口；尚未证明每一种属性组合（特别是非法重复 XML 属性、条件表格样式覆盖及复杂列表/编号继承）均已穷尽，不宣称百分百无遗漏。

## 自动编号关闭值续审

- 标题编号间距检查已区分“存在 `w:numPr`”和“自动编号实际启用”。OOXML 的 `w:numId w:val="0"` 表示关闭编号；若仍按编号定义取证据，会把用户手动输入的标题编号和空格当成无效列表，错误报格式问题。
- 新增 DOCX 回归用例：`numId=0` 且文本编号后有两个 ASCII 空格应通过；只有一个空格应失败。修复前合法用例为 FAIL，修复后两种边界均符合预期。
- `numId` 缺失或非零但对应定义链无法解析时，仍视为自动编号证据未知并失败；不会退回文本空格而放行。编号有效时，间距继续由 `w:suff` 与 `w:lvlText` 精确计算，非法/未知间隔不会被估算为空格。
- 验证：单项回归用例通过；前序 `Docx4jDocumentParserTest` 与 `RuleEngineTest` 共 345 项通过。需要在本次后续完整重跑后补记最终结果；自动编号 `lvlOverride` 的更多异常组合仍待持续覆盖。

## 行距枚举与附录编号溢出续审

- docx4j 对 `w:spacing/@w:lineRule` 的非法枚举会丢弃原值并暴露为 `null`；旧规则把 `null` 统一当作 OOXML 默认 `auto`，因此显式 `lineRule="invalid"` 且 `line="360"` 可能错误通过。
- 解析器现在从原始 `document.xml` 和 `styles.xml` 读取有效来源：属性缺失才按 OOXML 默认 `auto` 处理；属性显式存在但不属于允许枚举时保留其原始字符串并按 `360 / invalid` 精确失败。直接段落覆盖样式、样式继承和缺失属性的优先级均有回归测试。
- 附录图、表、公式序号检查改用 `BigInteger`，不再用 `Integer.parseInt`。超出 32 位范围的编号不会跳过检查，而是与期望序号比较并产生 `APPENDIX_OBJECT_SEQUENCE_MISMATCH`。
- 图片尺寸解析允许 `Long.MAX_VALUE`，拒绝更大、负数、零和非数字值；这些字段仅作为 XML 无效证据保留，学校规范没有图片宽高要求，当前不会单独产生图片尺寸格式错误。
- 定向验证：`ImageParserTest` 16 项、`Docx4jDocumentParserTest` 75 项、`RuleEngineTest` 289 项全部通过；`git diff --check` 通过。全量测试仍包含既有批注写入和文本框解析失败，不能据此宣称整个项目无失败。
