# 学校规范 XML 与规则实现冲突复核

复核依据：用户提供的《学校论文规范（有格式要求标签版）》中已提取的 DOCX XML 规则内容，以及当前 `school-v1` 规则、Word 批注和检查报告实现。

说明：上一轮读取规范原件时文件被其他进程锁定，本轮未重复尝试打开；本轮依据已提取的 XML 规则矩阵及用户在会话中提供的规范文本复核。

## 本轮修正

- 封面学校名称在论文类型标题之前，原逻辑从论文类型行才开始检查，遗漏了学校名称。现在对封面中识别到的“山东石油化工学院”行应用方正小标宋简体、小初、居中检查。
- 前置封面或目录版式表格原先会被当作正文表格，产生缺少表题、三线表等误报。现在根据正文一级标题在 XML 中的位置排除正文之前的表格，并忽略表格单元格内部的章节文字。
- 中文关键词的规范要求两端对齐，原先未检查。现在检查段落有效对齐属性，并在批注和报告中给出中文修改建议。
- 有“注：”表注时，规范要求表注放在表格下方左侧。解析器已经提供对应段落地址；现在对能从 XML 定位且读取到对齐属性的表注检查左对齐。
- 对明确标为“续表编号”且能匹配前文原表的拆分表，现在逐格比较两张表的首行表头。编号和表头缺失或无法匹配时不推断续表关系。
- 正文篇幅按封面专业区分：外语专业检查正文不少于 16000 个字符，其他专业检查不少于 8000 个汉字。原先额外要求“非汉字字母数多于汉字数”没有规范依据，现已删除；仅凭 XML 字符类别不能断定论文实际使用的语种。
- 页码格式检查原先遍历所有分节，可能把摘要或目录的罗马数字页码误套为正文规则。现在将页脚中的 PAGE 域关联到实际生效的节，并依据第一章位置限定检查范围；前置部分存在页码域、正文节不是阿拉伯数字、正文开始后分节显式重置为 1，分别给出确定错误和中文修改建议。页码域的节索引仅作内部解析数据，不出现在 API JSON；页码格式问题的批注锚到对应正文节的正文段落，避免定位到写入器不支持的 footer part。
- `REF-06` 原先强制作者、年份、来源等字段齐全，但给出的学校规范没有列出统一必填字段，且字段随文献类型不同。现已移除该确定性错误，只保留规范明确要求的文献类别标识、引用/编号、篇数和字体行距检查。
- 前端检测范围文案原先声称真实分页、图片和公式均可直接判错，现改为只报告 DOCX XML 可直接判定的格式项。图题未居中的提示也不再误称图片本身必须居中。
- 已保留之前复核的规则：公式编号章节号须与公式实际章节一致；目录制表符不能丢失；Unicode 希腊字母按变量处理；图题居中时不要求图片段落居中。
- 根据用户确认的规范文本补齐目录一级章标题“前空 2 格”检查；检查原始 run 的前导空格，也接受 XML 段落左缩进设置为 2 字符的表示，不再只检查编号后的空格。
- 公式号位于公式表格相邻单元格时，原解析器只扫描公式所在段落，导致公式号漏读并把排版表格误判为缺少表题。现在对单行双格、无题注、公式单元格仅含一个公式且另一格仅含公式号的结构提取编号来源；据此检查编号格式和公式/编号的分别对齐。只有无表格样式及可见边框的该类表格才从普通表格规则中排除；带样式或边框的表格仍按普通表格检查。

## 证据与验证

每项新增或变更行为均补充了规则级回归测试；关键误报和漏检先通过失败测试复现，再修正实现。新增表注、续表题头和中文关键词问题的批注测试，确认意见能生成中文 Word 批注。

本轮完整验证通过：`rtk mvn -q -f backend/pom.xml verify`、`rtk npm run build`、`rtk git diff --check`。定向测试还覆盖目录一级章标题前空两格、`w:leftChars` 缩进读取、公式号跨单元格解析与对齐、公式布局表排除和普通/带样式数据表继续检查。

## XML 判定边界

DOCX XML 能说明段落属性、字符属性、表格单元格顺序、显式分页符和字段结构；页脚域现在还保留其有效节关联。分节起始号明确重置为 1 时可确定违反连续编号；其余连续性需要实际页数，不能只从 XML 推导。Word 最终分页、浮动图片的实际版面归属、公式变量的语义定义、表顶线右侧的单位归属等仍不作为确定性错误或批注。

外语专业识别依赖封面专业字段中的常见语种名称；未识别出的专业名称不会套用 16000 字符规则。系统不以汉字和外文字符比例替代语种识别，也不将字符类别比例作为学校硬规则。

## 2026-10-11 公式编号与报告复核

- 公式编号解析接受 ASCII 和全角圆括号，也保留裸编号、左右括号不配对的编号候选；规则引擎对缺括号或括号不配对明确报 `EQ-01` 错误，正确的全角括号不报错。
- Word 批注和 Word 报告对该错误均使用中文说明与具体修改建议，不将内部 reason code 暴露给论文作者。
- 检查报告统计只将 `PASS` 和 `FAIL` 计入确定检查项。`InspectionService` 在生成报告前剔除 `REVIEW`，报告不会把证据不足的检查计为通过。
- 纠正旧记录：DOCX `w:sz` 以半磅为单位，五号 10.5 磅对应 21 half-points；当前公式编号规则、报告显示和回归测试均使用该值。
- 本轮依据仓库已提取的 `artifacts/spec-word_document.xml` 与规则矩阵复核。规范原件当前仍被其他进程占用，本轮无法重新读取原始 DOCX，未据此声称重新验证原件与提取件的字节一致性。
- 验证结果：定向测试 `EquationParserTest`、`RuleEngineTest`、`RuleDescriptionsTest`、`CommentWriterTest` 共 197 项通过；完整后端 `verify` 共 284 项通过，前端 `npm run build` 通过，`git diff --check` 通过。
- `artifacts/batch-test-20261010-F-final` 中的旧 JSON 仍包含 `REF-06`、摘要字数等历史结果；这些规则已在当前实现中移除或降为非确定性范围，不能作为当前版本报告依据。重新批量检测后应以当前 API 生成的 `report.docx` 和 JSON 为准。

## 2026-10-11 正文行距与单位一致性复核

- 正文段落现在检查 1.5 倍行距（`BODY-LINE`），不符合时返回 `LINE_SPACING_MISMATCH`，批注建议为“正文行距不是 1.5 倍”。
- 正文计量单位现在检查全称与缩写是否混用（例如“厘米”和“cm”），发现冲突时返回 `BODY-UNIT/UNIT_STYLE_INCONSISTENT`，并定位到后出现的段落。
- 单位识别使用明确边界，避免把普通英文单词中的 `m`、`s` 等字母误判为单位；表格顶线右侧单位的最终归属仍无法仅凭 DOCX XML 完整证明。
- 验证：`mvn verify`、定向规则测试、`npm run build`、`git diff --check` 均通过；真实 DOCX 上传成功并生成批注文件。

## 2026-10-12 精确匹配审计

- 页边距的四个 `w:pgMar` 值按 twips 整数精确比较，不做厘米换算容差；另外读取 `w:gutter`，缺省按 OOXML 默认值 0，非零时报告装订线错误。否则四边都等于 1474 twips 仍可能叠加额外装订线。
- 首行缩进按 XML 中可读取的有效表示精确比较：`firstLineChars` 与 `firstLine` 同时出现时遵循 OOXML 字符单位优先级；只有字符单位缺失时才以 `firstLine` twips 判断。420、421 twips 单独作为有效物理缩进值时不通过。被优先级覆盖的属性不作为额外格式门槛。
- 行距精确比较 `w:line=360` 与 `lineRule=auto`；`lineRule` 缺失按 OOXML 默认 `auto` 解释。字号以半磅整数精确比较。
- 字体模型分别保存 `ascii`、`hAnsi`、`eastAsia`，按字符代码使用对应槽位；不会用 hAnsi 值冒充 ASCII 字体。`asciiTheme`、`hAnsiTheme`、`eastAsiaTheme` 通过 DOCX 主题部件解析，页码字体也解析 ASCII 主题字体。
- 新增回归覆盖非零装订线、仅提供 hAnsi 的 run、主题字体三个槽位及页码主题字体。定向解析/规则/报告测试通过 250 项，之后补充的页码主题测试单独通过。
- 当前未完成的解析覆盖审计：复杂脚本 `cs/cstheme`、按 run/样式语言确定主题 EastAsia 字体、表格条件样式与所有样式属性合成，仍需独立样本和回归测试。这里不能把未知属性推断为通过。
