# 学校规则矩阵与核心验收清单

日期：2026-10-04。状态：研究收敛稿，非生产规则集；不表示下列能力均已实现。依据八轮研究及本轮重新读取原件形成。

## 来源与读法

唯一学校文件为《论文规范.docx》，SHA-256：`3c9c3dc012b779b4ebd20ea35cb86142d73fb911c7733e3b0d1789ce2d6ac2b2`。用户另明确四边页边距严格按 2.6 cm 执行。

表中 Pn 指 `/word/document.xml` 的 `/w:document/w:body/w:p[n]`，从 1 开始；有些要求位于该段落所锚定的文本框中，Pn 不是页码，也不代表批注必然适用于该段落。读取时选择一条 AlternateContent 分支去重，不能把 Choice/Fallback 的相同文字计为两条要求。

“明确”表示文字要求明确，不表示通用检测器已通过验收；“待确认”表示语义或适用范围不确定；“建议”保留原文弱约束；“人工/排版”表示需要人工或渲染证据，不能用缺省值代替。

字号换算：小初 36pt、小二 18pt、三号 16pt、四号 14pt、小四 12pt、五号 10.5pt。OOXML 的 sz 采用半磅；字符缩进独立使用百分之一字符，不能直接当作 twips。

## 明确不增加的学校硬规则

- 图片 DPI、固定宽高、必须使用某种图片编码，原文没有规定。
- 公式本体必须宋体/Times New Roman、固定字号，原文未规定。
- 所有表格必须恰好三条边框线，原文允许辅助线。
- 全文必须使用模板当前的每一个样式或 styleId；格式语义相同不要求 XML 相同。
- 模板示例的人名、日期、标题、图号、参考文献内容必须相同。
- 未确认的纸张规格、正文全局行距、完整目录/页眉格式，不因模板出现就升级为硬规则。

### 结果契约的关键区分

规则的权威性、实现覆盖和本次判定是三个独立维度。例如“编号必须 10.5pt”是明确规则，但遇到不可解码对象仍可能无法判定；“建议近十年文献”即使可计算，也不能变成硬性失败。

建议报告分别保存：规则来源及强度、适用范围、执行状态、判定结果、原始/有效属性证据、未知原因。任务完成不等于论文通过；只有全部适用硬规则完成判定且没有失败/未知，才有条件作相应范围内的合规表述。没有启用或实现的能力必须显示覆盖说明。

## 当前决策与下一阶段

已有研究足以支持下一步设计核心系统，无需继续把所有 Word 特性研究完才开始；但不能承诺任意文档 100% 准确。

推荐 Java + docx4j 作为主解析路线，保留不可变 XML 证据；统一入口，不区分教师端学生端。确定性规则先进入核心验收，旧公式内部属性、歧义条款和实际版面作为有明确状态的复核项。是否需要首版自动完成版面规则，必须在设计阶段明确，因为它决定是否引入并部署渲染器。

推荐模块化单体代码库、持久化后台任务、单文档一次解析并复用索引、跨文档受限并发；不要先引入多语言微服务和分布式中间件。字体/主题和渲染环境要作为结果复现条件，不能只缓存文件哈希。

本轮只整理规则与验收，不冻结页面视觉、不建立生产接口，不将仍失败的 MTEF 精度实验包装为已支持。进入正式设计时，以此矩阵替代早期草案中的泛化检测范围；先解决影响核心范围的少量歧义，其余记录为复核项。
