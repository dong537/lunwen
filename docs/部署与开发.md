# 部署与开发说明

## 数据流与模块边界

浏览器上传 DOCX → 后端接口校验文件 → 解析 XML 与有效格式 → 按文档区域执行规则 → 生成批注副本及 Word 报告 → 保存到结果目录 → 前端下载结果。

api 管理请求和结果文件，document 提取文档结构与格式事实，rules 负责判断，reporting 负责将问题定位到 Word 批注，report 负责中文说明和报告排版。检测副本与原文件分开保存。

目录整段的左侧缩进与正文首行缩进使用不同检查语义。目录缺少页码时也不应退化为正文缩进检查。公式文字位置与普通文本位置分别解析，批注写入后需能回读定位。

## 配置

| 配置 | 默认值或 Compose 值 | 作用 |
| --- | --- | --- |
| SERVER_PORT | 18098 | 后端监听端口 |
| THESIS_STORAGE_ROOT | 本地为 Java 临时目录下 thesis-inspection；容器为 /data/thesis-inspection | 检测结果目录 |
| THESIS_MAX_UPLOAD_BYTES | 16777216 | 业务上传大小上限 |
| THESIS_ANNOTATION_RETENTION | PT1H | 结果文件默认保留一小时 |
| THESIS_ANNOTATION_CLEANUP_INTERVAL | PT5M | 清理任务间隔 |
| VITE_API_URL | 空值，即同源 | 前端构建时的 API 前缀 |
| JVM 参数 thesis.soffice | Docker 中为 /usr/bin/soffice | LibreOffice 可执行文件位置 |

Spring multipart 和 Nginx 也有 16 MB 请求限制；调整文件上限时需一起核对。配置可通过部署环境提供，凭据不得写入仓库。

## 本地公式转换

安装 LibreOffice 后，构建后端并指定实际路径，例如 Linux：

~~~bash
mvn -B -f backend/pom.xml verify
java -Dthesis.soffice=/usr/bin/soffice -jar backend/target/app.jar
~~~

Windows 可将 thesis.soffice 指向本机 LibreOffice 的 program/soffice.com。转换是有边界的检查步骤，不保证所有 MathType、OLE 或图片公式都能还原内部结构。

## Docker 操作

~~~bash
mvn -B -f backend/pom.xml verify
docker compose up -d --build --wait
docker compose ps
docker compose logs --tail=100 backend
~~~

当前前端 Dockerfile 会在镜像构建过程中执行 npm ci 和 npm run build；后端 Dockerfile 复制事先生成的 target/app.jar，并安装 LibreOffice。

宿主机 8080 端口提供前端和同源 /api 代理。生产环境如已有 HTTPS 反向代理，应使用其正式入口，并将请求转发到 8080；同时保留与容器 Nginx 一致的上传大小和超时设置。

thesis-data 是命名持久卷。更新服务使用 docker compose up -d --build；需要停止服务时使用 docker compose down。删除数据卷会丢失已保存结果，不应将删除卷作为普通更新步骤。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/inspections/health | 健康状态 |
| POST | /api/inspections | multipart 上传 file，annotate=true 生成批注 |
| GET | /api/inspections/{requestId}/annotated | 下载批注 Word |
| GET | /api/inspections/{requestId}/report | 下载 Word 检查报告 |

下载地址以上传接口返回的 downloadPath 为准。结果文件有保留时间，过期后需重新检测。

## 验证与提交范围

后端运行 mvn -B -f backend/pom.xml verify，前端运行 npm ci 和 npm run build。真实论文验收应核对原文、批注位置、格式保持和报告，不仅检查接口是否返回成功。

GitHub 发布使用已核验源码和明确文件清单，不提交 node_modules、target、dist、论文原件、论文解包 XML、检查报告、临时结果、机器路径清单或私钥。研究草稿和真实样本证据在本地保留，不随应用代码上传。
