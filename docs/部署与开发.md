# 部署与开发说明

## 数据流与边界

浏览器通过同源 Cookie 会话访问业务服务。业务服务负责账号、权限、提交状态、统计和 COS，内部审核引擎仅负责 DOCX 检查与批注。浏览器不能直接调用旧 `/api/inspections` 接口。

平台与 COS 之间默认走公网；配置 `COS_ENDPOINT` 为同地域内网后缀后，服务器到 COS 的流量走内网。

`TRANSFER_MODE=direct` 时，学生上传和用户下载使用短期预签名 URL，浏览器直接与 COS 传输文件，平台只负责鉴权、预签名和 COS `HEAD` 校验。`TRANSFER_MODE=proxy` 时保留旧的服务器中转上传/下载。两种模式下审核 worker 都仍由平台服务器从 COS 取原件并回写结果。浏览器直传/直下必须使用 `COS_PUBLIC_ENDPOINT`（公网域名），不能使用 `COS_ENDPOINT` 的内网域名。

上传校验 → PostgreSQL 预留记录 → COS 原始文件 → 释放排队 → 后台领取 → 下载原件 → 引擎检查 → COS 保存标注文件/JSON → 更新成功状态。教师统计只来自 SUCCESS；非成功提交的 API 问题数为 `null`。失败记录保留，文件清理失败会记录日志并补偿。

成功文件属于 COS 长期存储，与引擎的临时结果目录分开。引擎清理临时目录不会删除成功提交的 COS 文件。

## Compose 环境配置

复制根目录 `.env.example` 为 `.env` 后填写下表。空白必填项会阻止 Compose 启动。不要把密钥写进镜像、Git 或聊天记录。

| 名称 | 用途 |
| --- | --- |
| `POSTGRES_PASSWORD` | 数据库密码，必填 |
| `PLATFORM_ADMIN_USERNAME` | 首次管理员账号，默认 admin |
| `PLATFORM_ADMIN_PASSWORD` | 首次管理员密码，必填；仅数据库没有管理员时使用 |
| `COS_BUCKET` | 私有桶完整名称，含 APPID 后缀 |
| `COS_REGION` | 桶地域，例如 ap-shanghai；以真实桶配置为准 |
| `COS_ENDPOINT` | 可选。留空走公网 `cos.<region>.myqcloud.com`；服务器与桶同地域时填 `cos-internal.<region>.myqcloud.com` 走内网。只填域名后缀，不含协议、桶名和路径 |
| `COS_PUBLIC_ENDPOINT` | 可选。浏览器直传/直下使用的公网域名后缀，例如 `cos.ap-beijing.myqcloud.com`；留空使用 SDK 默认公网 endpoint。不能填内网域名、协议、桶名或路径 |
| `PRESIGN_EXPIRE_SECONDS` | 预签名 URL 有效期，默认 600 秒；必须小于上传预留并留有余量 |
| `TRANSFER_MODE` | `proxy` 为旧的服务器中转，`direct` 为浏览器直传 COS 和从 COS 下载；默认 `proxy`，配置 CORS 并验证后改为 `direct` |
| `COS_SECRET_ID`、`COS_SECRET_KEY` | 具备对象上传、读取、列表、删除权限的凭据 |
| `PLATFORM_HTTP_PORT` | 对外前端端口，默认 8080 |
| `SESSION_COOKIE_SECURE` | HTTPS 环境为 true；仅本地 HTTP 验证使用 false |

COS 桶应为私有读写，不公开对象链接。成功论文不设置自动过期生命周期。推荐仅授予该桶的 `submissions/` 前缀所需权限。

`COS_ENDPOINT` 只改变平台访问 COS 的域名，不改变桶权限。内网 endpoint 要求服务器与桶同地域且网络可达；跨地域、本地开发或不确定时留空。填写非法值会在平台启动时失败。

`COS_PUBLIC_ENDPOINT` 只用于生成浏览器预签名 URL。它必须与 `COS_ENDPOINT` 分开配置；如果服务器侧使用 `cos-internal`，浏览器侧仍必须是公网域名。`TRANSFER_MODE=direct` 前必须在 COS 桶配置 CORS，至少允许实际前端源的 `PUT` 和 `Content-Type`；下载使用浏览器导航，不强制需要 CORS。

CORS 预检示例：

```bash
curl -i -X OPTIONS \
  'https://<bucket>.cos.<region>.myqcloud.com/submissions/test/original.docx' \
  -H 'Origin: https://<实际前端源>' \
  -H 'Access-Control-Request-Method: PUT' \
  -H 'Access-Control-Request-Headers: content-type'
```

期望返回 `Access-Control-Allow-Origin`、`Access-Control-Allow-Methods: PUT` 和 `Access-Control-Allow-Headers: Content-Type`。宿主 Nginx 或前端如配置 CSP，还需在 `connect-src` 中加入 COS 公网域名。

```bash
docker compose config --quiet
docker compose up -d --build --wait
docker compose ps
docker compose logs --tail=100 platform
```

`platform-db` 保存数据库，`thesis-data` 保存引擎临时产物。更新用 `docker compose up -d --build`，停止用 `docker compose down`，不要加 `-v` 删除持久卷。更新数据库前做好备份；Flyway 在启动时执行受版本控制的 schema 迁移，Hibernate 只验证结构，不自动改表。

四个服务均使用独立职责，平台和引擎镜像多阶段构建、非 root 运行。默认只发布前端 8080，PostgreSQL、平台 18099、引擎 18098 仅容器网络可达。已有服务时，使用单独 Compose 项目名和不同端口验证，避免覆盖运行中的版本。

反向代理必须支持至少 52 MiB 请求体，以容纳 50 MiB 文件和 multipart 数据。HTTPS 入口必须搭配 Secure Cookie。`/api/health` 只返回非敏感存活状态；发布验收仍需实际登录和上传/下载流程。

## 本地开发

引擎：

```bash
mvn -f backend/pom.xml spring-boot:run
```

平台通过下列环境变量连接真实 PostgreSQL 和 COS：

- `DATABASE_URL`：JDBC PostgreSQL 地址；也可使用 Spring 标准 `SPRING_DATASOURCE_URL`。
- `DATABASE_USERNAME`、`DATABASE_PASSWORD`：或对应 `SPRING_DATASOURCE_*`。
- `INITIAL_ADMIN_USERNAME`、`INITIAL_ADMIN_PASSWORD`：本地首次管理员配置。
- `PLATFORM_COS_BUCKET`、`PLATFORM_COS_REGION`、`PLATFORM_COS_SECRET_ID`、`PLATFORM_COS_SECRET_KEY`。
- `PLATFORM_COS_ENDPOINT`：可选；留空走公网，同地域内网填 `cos-internal.<region>.myqcloud.com`。
- `PLATFORM_COS_PUBLIC_ENDPOINT`：可选；浏览器预签名使用的公网域名后缀。
- `PLATFORM_TRANSFER_MODE`：`proxy` 或 `direct`；本地未配置 CORS 时保持 `proxy`。
- `PLATFORM_TRANSFER_PRESIGN_EXPIRE_SECONDS`：预签名有效期，默认 600 秒。
- `PLATFORM_ENGINE_BASE_URL`：本地引擎地址 `http://127.0.0.1:18098`。
- `SESSION_COOKIE_SECURE=false`：仅本地 HTTP 开发。

```bash
mvn -f platform-backend/pom.xml spring-boot:run
cd frontend
npm ci
npm run dev
```

平台默认监听 18099，Vite `/api` 代理到 18099。配置不完整会启动失败，不提供生产本地文件存储替代 COS。

旧公式转换依赖 LibreOffice。默认通过 PATH 查找 `soffice`；可通过 JVM `-Dthesis.soffice=/实际路径/soffice` 指定。每次转换使用独立配置目录，两阶段各有 120 秒超时，日志保存在任务暂存目录。`-Dthesis.conversion-timeout-seconds` 可调每阶段超时；调整时应同步核对平台引擎请求超时和任务租约。

## 会话、重试与数据恢复

会话为 HttpOnly、SameSite Cookie。每个请求从数据库重查用户状态和密码指纹；禁用、重置或改密会让旧会话失效。服务重启后用户重新登录，提交历史仍在 PostgreSQL/COS。

创建账号与导入账号的初始密码为 `123456`。首次登录必须改密，管理员重置后再次强制改密。新密码 6–128 字符，不得与旧密码相同；密码统一预哈希后 BCrypt，避免中文长密码受到 BCrypt 72 字节截断影响。

任务使用数据库状态和执行次数领取，旧执行不能覆盖新执行的结果。每次执行使用独立对象目录；损坏文档直接失败，服务异常最多执行 3 次。启动恢复和文件清理错误要通过平台日志排查，不能将 FAILED 人工改成 SUCCESS。

成功文件和数据库需分别备份，恢复时保持对应目录一致。不要只恢复数据库却遗失 COS 文件。

`TRANSFER_MODE=proxy` 时下载使用8个工作线程和16个排队位置；排队结束后再次确认账号和导师权限，才打开COS文件。请求过多返回503及中文重试提示。MVC异步超时330秒，Nginx读写超时360秒，COS完整传输预算5分钟；调整其中一项时需一起核对。已经传出的文件字节无法收回，权限撤销保证阻止后续新请求和尚未开始读取的请求。

`TRANSFER_MODE=direct` 时平台只签发短期下载 URL，不再占用下载线程池；URL 在有效期内可被持有者使用，注销或权限变化不会立即撤回，因此下载 URL 的有效期应保持较短。

审核成功前会独立检查返回的Word结构、正文内容、批注与批注关系，防止把空白文档或没有实际批注的文件当作成功。批注合并仍按原有规则处理，不强制一条错误对应一个独立批注。

## 验证

```bash
mvn -B -f backend/pom.xml verify
mvn -B -f platform-backend/pom.xml verify
cd frontend
npm test
npm run build
```

平台测试需 Docker 运行，使用真实 PostgreSQL 容器；不得用 H2 或内存数据冒充 PostgreSQL 验收。外部适配器隔离测试不等于 COS 真实联调。
