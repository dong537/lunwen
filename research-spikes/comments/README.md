# 原件副本添加 Word 批注试验

范围：只在固定 SHA 的学校规范副本中增加一条真实页边距修改意见，不是通用批注导出器。使用 Python + lxml 6.0.4 做独立的原始 OPC/XML 写入试验，再由 Java/docx4j 17.2.1 独立读取；这不改变正式后端 Java 技术方向。

## 已完成

- 给正文第 115 个直接段落（第 7 节标题）添加标准 classic comment。第 7 节位于第 114 个段落的分节结束之后，到第 120 个段落结束；批注明确指向本节右边距，未指责标题内容。
- 原件右边距 1418 twips，学校要求 1474 twips（2.6cm）。副本仅给出建议，不修改边距。
- 新增 comments.xml；维护正文范围、reference、document.xml.rels 与 Content Types。
- Python 4 项测试通过：原始其他部件字节不变、正文去掉批注后 C14N 一致、已有批注保留/ID 唯一、错误哈希与空文字锚点拒绝。
- Java 独立读取 1 项测试通过，识别 CommentsPart、作者、批注数量及关系目标。
- 重复文字定位测试通过：即使其他段落出现相同文字，批注仍只落在指定结构段落。

本机未发现 Word、WPS 或 LibreOffice 可执行文件，因此本轮没有实际编辑器打开、无修复提示或版式对照证据；docx4j 能打开不等于这些检查已通过。完整 XSD 校验也未配置，当前使用关系、ID、范围和内容保护断言。锚点覆盖统计见[第十轮报告](../../docs/research/第十轮批注锚点覆盖评估.md)和[第十三轮页眉页脚关系报告](../../docs/research/第十三轮页眉页脚批注关系试验.md)：正文直接段落和一个真实表格段落已验证；文本框投影路径不匹配时会安全拒绝，页眉页脚关系试验失败，暂不写批注。

## 复现

当前环境已有 lxml 6.0.4；依赖记录在 requirements.txt。以下从本目录执行：

```powershell
$env:SCHOOL_DOCX='<学校规范绝对路径>'
python -m unittest -v test_comments
python annotate.py '<学校规范绝对路径>' '../../artifacts/论文规范-格式筛查批注试验.docx'
```

输出文件使用独占创建，已存在会报错，不覆盖已有结果或原件。重新试验应更换输出文件名。

在 `../docx4j` 执行独立读取检查：

```powershell
mvn.cmd -B -ntp -s settings.xml '-Dtest=AnnotatedCopyTest' '-Dprobe.annotatedDocx=<批注副本绝对路径>' test
```

AnnotatedCopyTest 只有指定 probe.annotatedDocx 才启用；普通研究命令中该项跳过，不能算通过。研究通过证据在本目录 evidence/。

## 边界

- 地址为固定原件的正文直接段落序号 + 整文件哈希，只支持直接文字 run 范围。本次不是按相同文本搜索定位。
- 不支持任意字符范围拆 run、超链接、域、修订、文本框或页眉页脚批注；当前只验证整段直接文字范围。
- 保留不同段落已有标准批注；目标段落已有批注则明确拒绝，尚未实现交叠锚点。现有批注使用标准 comments.xml 关系；其他位置的批注部件需要另验。
- 检测到数字签名或已识别的现代批注扩展部件时拒绝，不声称兼容所有现代线程批注格式。
- 生成一个新 ZIP 包；无关部件的解压后字节一致，不承诺 ZIP 容器压缩字节整体不变。
- 不运行表格样式预处理，不把分析模型保存回原件。尚不是生产上传入口，没有完整的 ZIP 炸弹、超时和内存控制。
- 带批注论文保留原论文内容，不进入 Git；evidence 只保存结构/哈希/测试结果。

正式实现应将检查结果的稳定原始位置传入独立的批注写入边界，并在输出前核验原件版本；无法可靠锚定的问题留在报告中且说明批注未写入原因，不能改挂到任意邻近段落。
